# Changelog

All notable changes to RLMesh are documented here. This changelog tracks the `rlmesh` Python package on PyPI. The Rust crates are internal implementation detail and currently carry no separate user stability promise.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/2.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- The Rust crate authors and serves envs as Python does. `rlmesh::Env` and `rlmesh::VectorEnv` are sync Gymnasium-shaped traits: `observation_space()` / `action_space()` return a `Space`, `reset(seed, options)` returns `(observation, info)`, `step(action)` returns `(observation, reward, terminated, truncated, info)` with `Value` and `InfoDict`, and `render`, `close`, `render_mode`, `metadata` and `id` have Python's defaults (`id` `None` serves `"UnknownEnv-v1"`; a render frame is any numeric image `Value`, PNG-encoded by Python's lenient rule). A vector env takes a `VectorSeed` and sees Python's batched layout. `rlmesh::EnvServer` is one server built with `new`, `lanes` or `vector` and `EnvServerOptions` (`address`, `host`, `port`, `path`, `transport`, `options`, `tags`, `close_env_on_shutdown`, and the Rust-only `ext` with `token`, `peer_info_extra` and `publish_describe`): it binds at construction (`address()`, `env_contract()`), then `serve()` keeps lane 0 on the calling thread (SIGINT drains, closes and returns the cancellation class; SIGTERM stops it; both dispositions are restored on return), `start()` / `wait(timeout)` / `shutdown()` follow Python's state machine, and `serve_async` / `wait_async` / `shutdown_async` are the async twins; dropping a server shuts it down. It runs Python's construction checks (a one-lane vector env served as a scalar lane, tags, `RLMESH_EXPECTED_ENV_BRANCH`, `autoreset_mode`, lane agreement, address, workflow edition, endpoint token) and keeps served value validation. `ServeOptions` has Python's fields (`allow_remote_shutdown`, `idle_timeout`, `drain_timeout`, `close_timeout`, `workflow_edition`, `compress_responses`; an env server caps a `None` drain or close at 5 s, and a zero timeout is a `ValueError`-class error); its `token`, `predict_concurrency` and `peer_info_extra` moved to `ext::EnvServerOptions` and `ServeModelOptions`. `EnvFactory` (associated `tags`, `tag_params` of `TagParam { name, default_, choices }`, `reset_options`, `workflow_edition`, `tags_for`, `enumerate_variants`; `prepare`, `make`, `close`) with `EnvFactoryExt::make_env` (binds discriminant defaults and stamps tags, branch and reset options), `serve` / `serve_async` (`EnvFactoryServeOptions` with `num_envs`, `workflow_edition`, `make_kwargs` and an `ext::CancelToken`), `MadeEnv`, `Variant` / `VariantOptions`, `rlmesh::trial_index`, `rlmesh::specs::EnvContract` (read-only, with `to_dict`, `env` and `spec`) and `Transport` are new. An authored env failure reaches the client as `[INTERNAL] {op} failed: {message}`. The async request/result traits, `VectorEnvServer`, `BoundEnvServer`, the request and result types, `EndpointPhases` and `TRIAL_INDEX_OPTION` left the crate root for the hidden `rlmesh::binding`.

- The Rust crate authors and serves models as Python does. `rlmesh::Policy` is the native `Model` subclass: it writes any of the four corners (`predict`, `predict_batch`, `predict_chunk`, `predict_chunk_batch`, each with a `<corner>_with_context` twin) and lists them in `const CORNERS` and, for the ones that read the context, `const CONTEXT` (`rlmesh::Corners`); `load(&Kwargs)` (the default accepts only an empty config, and `const LOAD_KEYS` of `LoadKey::required` / `LoadKey::optional` is checked first with Python's texts), `on_episode_end`, `close`, `spec()`, `workflow_edition()`, `allow_fusion` and `NATIVE_CHUNK` / `native_chunk()` are its other members. A closure is a policy, and `rlmesh::with_context` wraps one that reads the context. `rlmesh::Model::new(policy, ModelOptions)` and `Model::from_config::<P>(config)` load eagerly and refuse invalid declarations first (`TypeError` class); missing corners derive as Python's raw-`Value` model does (`predict` from `predict_batch`, `predict_chunk` from `predict_chunk_batch`). `Model` is a shared handle whose corner and hook calls run one at a time on a library thread, refuse re-entry from their own corner, and keep each episode's `rlmesh::types::PredictContext` (`episode_id`, `episode_seed`, `predict_index`, `predict_seed`, `state: EpisodeState`) for the corners that read it, refusing a new episode past 65,536 (`RLMESH_EPISODE_CAPACITY`) instead of evicting. `close()` / `close_async()` stop any serve, wait for queued calls and fire the hook once; later calls fail with the `RuntimeError` class, and dropping the last handle closes it. `Model::serve(address, ModelServeOptions)` / `serve_async` serve with Python's rules (5 s drain and close caps, the call's edition first, SIGINT and a `cancel` token drain, close and return the cancellation class, SIGTERM returns `Ok`) and close the model when they stop; the model-only `token` and `predict_concurrency` moved to `ext::ModelServeOptions` (`Some(0)` is a `ValueError`). `NO_ADAPTER`, `rlmesh::types::{SpecArg, LoadKey, BatchPredictContext}` and `rlmesh::adapters::ModelSpec` (built with `ext::model_spec_from_json` until the adapters surface lands) are new. `ModelHandler`, `ModelWorker`, `PredictFn`, `RunLocalOptions`, `ServeModelOptions`, `BoundModelServer`, the route and observation types, `SpaceValue`, `SpaceSpec`, `EnvRuntimeError` and `async_trait` left the crate root and the prelude for the hidden `rlmesh::binding`.

- The Rust crate has Python's `describe` and `describe_json`: `rlmesh::describe(obj, DescribeOptions { kind, generated_at })` returns the envelope as `Metadata`, and `rlmesh::describe_json(obj, DescribeJsonOptions { kind, generated_at, served_env, workflow_edition })` its canonical string. `obj` is a `Describable`: `Describable::model::<P>()` reads a policy type's declarations without constructing it (a static `native_chunk` construction refuses is refused, `TypeError` or `ValueError` class), `Describable::env_factory::<F>()` default-constructs one factory per build, and `&Model` / `&mut factory` describe an instance. `Model::describe::<P>()` and `EnvFactoryExt::describe()` are the classmethods. A factory envelope carries the default branch's `env_spec` (or a badge whose `error_type` is the R-21 class), `env_tags`, `params` from `tag_params`, `variants.catalog`, and, for a branched factory, `env_contracts` with every branch's tags and spaces; a model envelope carries `model_spec`, `corners`, `native_chunk` and `params` from `LOAD_KEYS`; `target.qualname` is `rust:<type>`, `runtime` is the Rust host plus the edition offer, `DescribeKind` cross-checks the kind, and `rlmesh::ServedEnv` (`env`, `vector`, `lanes`, `From<&MadeEnv>`) replaces the default build. `EnvFactoryExt::serve` now publishes this full envelope on its handshake (with `params`, `env_contracts` and the catalog), read off the env it serves.

- The Rust crate runs models as Python does. `rlmesh::run(model, env, RunOptions)` and `Model::run(env, RunOptions)` (with `run_async` twins) take Python's keywords as `RunOptions` (`episodes`, `seeds`, `max_episode_steps`, `max_episode` as a `Duration`, `hooks`, `close_env`, `trust_entrypoints`, `execution_horizon`, `prefetch_lead`, `workflow_edition`, `trial_index_base` and an `ext::CancelToken`), check them before anything dials (`ValueError` class), resolve the run's workflow edition from the call, `RLMESH_WORKFLOW_EDITION` and the model's type, and return a `RunResult` of `EpisodeResult`s (0-based `index`, `reward`, `duration_s` in seconds, `success`, `trial`, per-episode `predict_ms` / `step_ms`) and `TelemetryRow`s with Python's `num_episodes`, `total_steps`, `mean_reward`, `success_rate`, `format_telemetry` and `repr` text. The env is an `EnvTarget`: an address, a served `&EnvServer`, a borrowed `&mut` env, `EnvTarget::vector(&mut venv)` or `EnvTarget::factory(&mut factory)` (built only when an episode needs it and closed after); the model is a borrowed `&Model` or `RANDOM_SAMPLE`, which runs on the session loop. A run borrows both: it never closes the model, closes the env only on `close_env`, and a model runs one run at a time (`RuntimeError` class). `RunHooks` (`on_run_start` with an `Arc<dyn RunContext>`, `on_episode_start`, `on_step` with a `StepEvent` carrying the observation and action, `on_episode_end`, `on_run_end`, which fires once also on an error) run on the thread that called a sync run, so a hook may make sync rlmesh calls; under an `_async` twin they run inside its future. `rlmesh::session` / `Model::session` return a `Session<'a>` that borrows the model and the env: `reset(seed, trial_index)`, `predict`, `step`, `run(SessionRunOptions)`, `done`, `contract`, `num_envs`, `selected_workflow_edition`, `run_context`, `cancel_handle` and `close`, each I/O call with an `_async` twin; dropping it ends the open episode and releases what it made. A sync call made from async code fails with the `RuntimeError` class naming its twin. The runtime driver's `RuntimeHooks`, its event types, `HookError`, `NoopRuntimeHooks`, `RuntimeReport`, `PeerCeiling`, `telemetry` and the `CancellationToken` re-export left the crate root for the hidden `rlmesh::binding`.

- A C callback can fail with any of Python's exception classes, as a Python author raises `ValueError` or `TypeError` from a hook: `rlmesh_callback_set_error_class(RLMESH_ERROR_CLASS_TYPE_ERROR, "bad observation")` makes an in-process call (a model's `rlmesh_model_run_local`, a warning handler's caller) fail with that class, its status and that text; across the wire the peer still sees an environment or model failure. The C++ wrapper's callbacks use it, so a predict that throws `rlmesh::TypeError` fails the run with `rlmesh::TypeError` instead of a `ModelException`.

- Python's `build_info()` in every language. Rust: `rlmesh::build_info()` returns `rlmesh::BuildInfo` (`version`, `protocol_generation`, `workflow_edition`, `workflow_edition_base`, `supported_workflow_editions`, `build_cohort`, `build_source` as the `BuildSource` enum, and `git` as an `Option`), whose `Display` is Python's `repr`; `rlmesh::VERSION`, `DESCRIBE_METADATA_KEY` and `DESCRIBE_SCHEMA_VERSION` (an `i64`) join `ENV_RESET_OPTIONS_KEY` at the root. The experimental C API has `rlmesh_build_info(&info)` filling an `RLMeshBuildInfo` (`RLMESH_BUILD_INFO_INIT`, `_MIN_SIZE`; static strings, nothing to free), `rlmesh_build_info_repr`, `RLMeshBuildSource` with `rlmesh_build_source_str`, `rlmesh_current_workflow_edition()`, and the `RLMESH_VERSION`, `RLMESH_DESCRIBE_METADATA_KEY`, `RLMESH_DESCRIBE_SCHEMA_VERSION` and `RLMESH_ENV_RESET_OPTIONS_KEY` macros; `RLMESH_ABI_VERSION_MAJOR/MINOR/PATCH` are deprecated in favour of `RLMESH_VERSION`. Its warnings go through `rlmesh_set_warning_handler(fn, user_data, free_user_data)` with `RLMeshWarningCategory`, `rlmesh_warning_category_name` and `rlmesh_warning_category_is_subclass`. The C++ wrapper wraps them as `rlmesh::build_info()`, `BuildInfo` (printable with `<<` and `to_string`), `BuildSource`, `VERSION`, `current_workflow_edition()`, the three constants, and `Warning`, `WarningCategory` and `set_warning_handler(std::function)`. The additions are additive: the ABI version is unchanged.

- The Rust crate resolves workflow editions with Python's rules: `rlmesh::current_workflow_edition()` is the bare `YYYY.MM` base to declare, and the resolver behind every native serve takes the call's own value, then `RLMESH_WORKFLOW_EDITION`, then the served peer's option, then the type's declaration (natives read no `pyproject.toml`); a blank value declares nothing, a set-but-blank variable floats deliberately, and an edition this build cannot run is a `ValueError`-class error. `RemoteEnv::selected_workflow_edition()` reports the edition the handshake selected. Native warnings have Python's categories: `rlmesh::WarningCategory` (`UserWarning`, `RuntimeWarning`, `WorkflowEditionWarning`, with `name` and `is_subclass_of`), `rlmesh::Warning`, and `rlmesh::set_warning_handler`, whose failing handler fails the call that warned; by default each distinct warning prints once to stderr as `rlmesh: <Category>: <message>`. `CURRENT_WORKFLOW_EDITION`, `parse_declared_edition`, `PROTOCOL_GENERATION`, `supported_workflow_editions` and the `PeerInfo` override moved from the crate root to the hidden `rlmesh::binding`.

- The experimental C API has Python's spaces as a stateful handle: `RLMeshSpace` (with `RLMeshBox`, `RLMeshDiscrete` and `RLMeshDict` as typedefs of it) built with `rlmesh_box_new(low, high, shape, ndim, options, &out)`, `rlmesh_discrete_new(n, options, &out)` and `rlmesh_dict_new(keys, specs, n, &out)`, or from a spec with `rlmesh_space_new`, `rlmesh_*_from_spec` and `rlmesh_spaces_space_from_spec`; `rlmesh_space_seed` (a `uint64_t`, `NULL` draws one), `rlmesh_space_sample`, `rlmesh_space_contains`, `rlmesh_space_equals`, `rlmesh_space_repr`, `rlmesh_space_clone` (shares the sampler) and `rlmesh_space_free`. Bounds are typed `RLMeshBound`s (`rlmesh_bound_int`, `_uint`, `_float`, `_bool`) read back exactly with `rlmesh_box_low`/`_high`/`_bounds_kind`; `rlmesh_ext_box_elementwise_new` builds a per-element Box. Dict keys are length-bearing `RLMeshStr` (`rlmesh_str()`), read with `rlmesh_dict_key_at`/`_value_at`/`_get`/`_len`/`_contains_key`. `RLMeshDType` is now the dtype enum (`RLMESH_DTYPE_FLOAT32`, ..., `rlmesh_dtype_str`, `rlmesh_ext_dtype_size`) taken by `RLMeshBoxOptions` and `RLMeshDiscreteOptions` (`_INIT`, `_MIN_SIZE`); the spec readers `rlmesh_space_spec_kind`/`_shape`/`_dtype`/`_repr`/`_clone`/`_free` return `RLMeshSpaceKind` and the enum.

- The experimental C++ wrapper has the same spaces in `rlmesh::spaces`: `Space` (copies share the sampler; `seed`, `sample`, `contains`, `==`, `to_string`, `as_box`/`as_discrete`/`as_dict`), `Box`, `Discrete` and `Dict` with `create(...)`/`from_spec(...)` factories returning `Result` and, with exceptions, constructors that throw (`Box(-1.0, 1.0, {3})`, `Discrete(4, {.start = 1})`, `Dict({{"pos", box}, ...})`), `SpaceSpec`, implicit `Bound` with `as_int`/`as_uint`/`as_float`/`as_bool`, `BoxBound`, `SpaceKind`, `BoundsKind`, `rlmesh::DType`, and `rlmesh::ext::box_elementwise`.

- The Rust crate has Python's spaces: `rlmesh::spaces::{Space, Box, Discrete, Dict, SpaceSpec, space_from_spec}` with `seed` (a `u64`, returned), `sample`, `contains`, `kind`/`shape`/`dtype`, Box `low`/`high`/`bounds_kind` as exact typed `Bound`s, Discrete `n`/`start`, and Dict's read-only mapping in declaration order (`keys`, `values`, `items`, `get`, `len`, `contains_key`, `d["key"]`). Clones of a space share its sampler; `as_box()`/`TryFrom` downcast and `From` upcasts to `Space`. `rlmesh::Tensor` is Python's `Tensor` (`new`, `shape`, `dtype`, `ndim`, `size`, `nbytes`, byte `strides`, `device`, `buffer`, `is_contiguous`, `reshape`, `copy`, `tobytes`), `rlmesh::DType` the twelve dtypes with Python's spellings, and `rlmesh::ext` holds the Rust-only extras (`TensorExt`, `SpaceExt::contains_detail`, `Storage`, `dtype_size`).

- The Rust crate has Python's `rlmesh.types.Value` and `Metadata`: `rlmesh::Value` (also `rlmesh::types::Value`) with exactly Python's kinds (`None`, `Bool`, `Int`, `Float`, `Text`, `Bytes`, `Tensor`, `List`, `Tuple`, `Dict`), strict reads (`as_int` refuses a `Bool`, `as_float` an `Int`, with `Error::Type`), `kind()` and kind-strict equality; `rlmesh::Metadata` (with the `InfoDict` and `Kwargs` aliases) is an insertion-ordered map with Python `dict` semantics (`insert` keeps an existing key's place, `remove` keeps the rest in order, collecting repeated keys keeps the first position and the last value) whose equality ignores order. `Space::sample` returns a `Value` (a Box a `Tensor`, a Discrete an `Int`, a Dict a dict in its declaration order, MultiBinary and MultiDiscrete a `Tensor`) and `Space::contains` takes one, accepting what Python's `contains` accepts: for a Box a `Tensor` of its dtype or numbers and nested lists of its exact shape (integer dtypes refuse floats), for a Discrete an `Int`, `Bool`, integral `Float` or one-element `Tensor`.

- The experimental C++ wrapper defines the Python package's exception classes with Python's inheritance when exceptions are enabled: `rlmesh::RLMeshException` (a `rlmesh::RuntimeError`), `ProtocolException`, `EnvironmentException`, `RecoverableEnvironmentException` and `ModelException` under it, and `ValueError` (`AdapterResolutionError`), `TypeError`, `RuntimeError`, `OSError` (`ConnectionError`, `TimeoutError`) outside it; `rlmesh::ext::CancelledError` derives from no `std::` exception. `rlmesh::throw_error(error)` and `Result::value_or_throw()` throw the class an `Error` reports, and `Error::error_class()` / `detail_code()` expose it. A predict may throw `rlmesh::ModelException(msg, true)` and an env callback `rlmesh::RecoverableEnvironmentException(msg)` to fail one request as recoverable; any other exception stays a permanent failure. `Result<T>` and `-fno-exceptions` builds are unchanged.

- The experimental C API reports the Python exception class of every error: `rlmesh_last_error_class()` returns an `RLMeshErrorClass` (`RLMESH_ERROR_CLASS_RECOVERABLE_ENVIRONMENT_EXCEPTION`, `RLMESH_ERROR_CLASS_CONNECTION_ERROR`, ...), with `rlmesh_error_class_name` and `rlmesh_error_class_is_subclass` following Python's inheritance. `rlmesh_last_error_code` and `rlmesh_last_error_code_str` read an environment or model error's code (`RLMeshErrorCode`, `RLMeshModelErrorCode`; `rlmesh_error_code_str`, `rlmesh_model_error_code_str`). New statuses `RLMESH_ERR_PROTOCOL` (9), `RLMESH_ERR_TYPE` (10), `RLMESH_ERR_RUNTIME` (11) and `RLMESH_ERR_OS` (12) join the existing ones, whose values are unchanged. The additions are additive: the ABI version is unchanged.

- `rlmesh.ModelException` (a `RLMeshException`, so `except RuntimeError` still catches it) is raised when a model fails a request. It carries `code` (the model error code, `"INTERNAL"` for an authored failure) and `is_recoverable`, and its text is `[CODE] message`. A model raises `ModelException(message, is_recoverable=True)` to fail one request as recoverable: a served model sends that flag to the client, instead of every raised exception being a permanent internal failure.

- Native environment describe envelopes report the host's language, language standard, and compiler through the optional `RLMeshEnvConfig.host_runtime_json`. The C++ wrapper detects them automatically; C callers use `rlmesh_env_config_init()`. Compilers appear under `runtime.toolchain` as `{"name":"gcc","version":"16.2"}` (`clang`, `gcc`, or `msvc`, with `major.minor` versions); `framework_versions` is populated only by explicit framework declarations, and an explicit declaration can override detection. Older configs and unset declarations keep the legacy `"c"` runtime with no version/compiler. The appended field is guarded by `struct_size`; ABI generation 4 is unchanged.

- `rlmesh registry publish TARGET` with no sources builds and publishes the variants declared in `rlmesh.toml`, so compute variants need no hand-written JSON label. The file is the `dev.rlmesh.package` label in TOML under its own key names, plus `dockerfile`, `target` (the Dockerfile stage), `context` and `build_args`; each `[variant.KEY]` table is one build, in priority order, with its requirements as `accel.*` keys, and `[profile.KEY]` tables are shared by every build. Every problem in the file is reported at once, by the same rules as `check-image`. Each variant is built for `linux/amd64` with its label rendered in and pushed as `TARGET-TAG-KEY`, then the builds are published as one version with the file's version-level keys as the index annotation. A version tag already in use, or a `TARGET-TAG-KEY` tag holding an image other than an earlier build of that variant (its label differs), is refused before anything is built, unless `--force`. A publish that stopped after pushing TARGET is finished by running it again: when TARGET already holds the index of the builds at the `TARGET-TAG-KEY` tags, each labelled as the file renders it, nothing is rebuilt and only the remaining tags are pointed at it (`--force` rebuilds instead). `--dry-run` builds nothing, prints the builds, and fails on a tag the real run would refuse; `--dry-run --json` only renders, printing each label and the index annotation; `--config FILE` names another manifest (`-` reads stdin).
- `rlmesh registry publish TARGET SOURCE...` publishes a version with several compute variants: it assembles already-pushed per-variant images (a PyTorch CUDA build, a ROCm build, a JAX build) into one OCI image index and pushes it under the target tag, plus `--tag` and `--channel` tags. Each child must be one linux image whose `dev.rlmesh.package` label declares a valid `variant` block. Variant and row keys must be unique, all children must serve the same kind, and at least one must be `linux/amd64`. Every carried attestation must describe a child, and an index source's declared platform must match its image config. Every check that can run before pushing runs first (the sources, their labels, the assembled index, where each tag points), and every problem it finds is reported at once, before anything is pushed. `--index-package FILE` sets version-level data as the index's `dev.rlmesh.package` annotation; it is refused when every manifest the sources carry (images and attestations) is a Docker schema2 manifest, which would turn the index into a Docker manifest list without it, the assembled index is checked to carry it before the push and as stored after it, and a lone index source's own annotation is checked by the same rules. The target and `--tag` tags do not move to a different index without `--force`, and are pushed only over a tag the registry said was absent when checked (the check and the push are separate calls, so this is not a lock): one that cannot be read (authorization, transport, registry errors) is refused without `--force`. A tag already holding the same index, compared field by field as stored, is not pushed again, except that another tag holding it at a digest other than the target's is re-pointed at the target's. The index is pushed to the target tag alone and checked as the registry stores it (the index assembled and, with `--index-package`, an OCI image index carrying the annotation); only then are the `--tag` and `--channel` tags pointed at the target's digest, which is also what they point at when the target already holds the index, so every tag is the same manifest. If that check fails, only the target tag has moved: the error says what it pointed at before and how to recover (put the previous digest back with `docker buildx imagetools create`, or publish again with `--force` once the cause is fixed). If pointing those tags fails, the error gives the `imagetools create` command that points them, and running the same publish again finishes it. What a tag holds is read by the digest it resolved to, so a tag moving mid-read is not mistaken for this index. The `--channel` tag moves and reports the digest it moved from, unless it is also the target or a `--tag`. `--dry-run` prints the per-variant table, the index JSON, and each tag's state. See [Publishing compute variants](docs/compute-variants.md).
- `rlmesh check-image` checks an image's compute variant by the managed platform's rules:
  - fails what the platform fails: keys (`^[a-z0-9][a-z0-9-]{0,31}$`), the `framework`/`accel`/`render` facets, `requires` constraints (comma-joined `>=`, `>`, `<=`, `<`, `==`, `=` clauses, a bare version meaning a minimum; `accel.vram`, the minimum VRAM per GPU, as a positive whole-byte quantity string within the signed 64-bit range: `"24Gi"`, with `Ki`, `Mi`, `Gi`, `Ti` powers of 1024, `K`, `M`, `G`, `T` powers of 1000, and no suffix meaning bytes) and their vendor rules, `priority` as an integer in `[-1000, 1000]`, `gpu.count` up to 8, at most one default profile, and derived row keys
  - warns where `requires` disagree with the image's `CUDA_VERSION`, `NVIDIA_REQUIRE_CUDA`, `ROCM_VERSION`, or describe `framework_versions`, including an `accel.cuda` constraint without a lower bound (`<13`), which admits drivers older than the image's CUDA runtime
  - reports the requires the platform infers for an image without a variant block, and the row keys the image gets

- The experimental C ABI hosts environments as well as models: a C or C++ program implements reset, step, render, and close (`RLMeshEnvVtable`, or `rlmesh::Environment` in `rlmesh.hpp`), declares its spaces with the `rlmesh_space_*` builders and its adapter tags as JSON (validated against the spaces at creation), and serves them with `rlmesh_env_new`/`bind`/`serve`. `rlmesh_env_new_lanes` serves N instances as the lanes of one `num_envs = N` endpoint, each on its own thread; `RLMeshEnvConfig.foreground` runs every callback on the thread that calls serve instead. `RLMeshEnvConfig.variants_catalog_json` lists the named scenarios an image serves, which the describe envelope carries as `variants.catalog`. A callback can fail one request as recoverable without ending the session. Each endpoint publishes its describe envelope on its handshake, and `rlmesh_env_describe_json` prints it for an image label. When `rlmesh_env_serve` or `rlmesh_env_free` returns, no callback is running or will run again; `close_timeout_ms` does not apply to a C env. A failed `rlmesh_env_bind` (an address in use, a bad endpoint token) leaves the env as it was, so the bind can be retried, and each lane's `close` runs exactly once: in serve, or in `rlmesh_env_free` for an env that never served. The library takes any value a callback leaves in its out-parameters, even when the callback fails. The additions are additive: the ABI version is unchanged.

- Each GitHub Release carries the experimental C/C++ package for Linux x86_64 (glibc 2.34 or newer): `rlmesh-X.Y.Z-x86_64-unknown-linux-gnu.tar.gz` with both headers, the shared and static libraries, and CMake and pkg-config metadata, plus its `.sha256`. A CMake project uses it through `FetchContent_Declare(rlmesh URL … URL_HASH SHA256=…)` and `FetchContent_MakeAvailable(rlmesh)`, or `find_package(rlmesh)` on the unpacked tree, then links `rlmesh::rlmesh`; no Rust toolchain is needed.

- `examples/chrono` serves Project Chrono's six-axis industrial robot from native C++ as a reach task, with a CPU ray-traced camera or an opt-in offscreen Vulkan one (GPU or lavapipe), driven by either a Python model with a `ModelSpec` or a C++ model, plus a Dockerfile.

- Env errors can be recoverable: the request fails but the client's session stays usable. After a fatal env error the client's next reset opens a new session instead of every later call failing; Python raises `RecoverableEnvironmentException` for a recoverable one, and env exceptions carry `code` and `is_recoverable`. In a multi-lane batch a fatal lane error wins over a recoverable one, and a batch where some lanes failed recoverably while others advanced ends the session, since replaying it would step the advanced lanes twice.

- `View(hold=...)` keeps the live viewer up after the session ends, showing the final frame and HUD (marked `[held]`, with every source still selectable): `hold=True` until you quit it, or a number of seconds. The default still closes the viewer with the session. The hold follows only a session that ended normally: one closing on an error or Ctrl-C (`KeyboardInterrupt`) skips it, releases the env and model, and raises at once. An unbounded hold with no interactive terminal (stdin not a tty, as in CI, on any backend) is skipped with a warning, so a non-interactive run never blocks on it; a number of seconds still holds.

- `View(step_hz=...)` paces a viewed session's env steps to at most that rate, so a fast simulator plays back at a watchable speed (the env's control rate for real time). `View.fps` still only thins the drawing. The pacing sleep is left out of the run's step and round timings.

- The HTTP viewer has a quit button (and a `/quit` route) that does what `q` does in the terminal: stop the run, or close a held viewer.

- `Session.run()` fills `RunResult.telemetry`, so `format_telemetry()` works on the Python loop a served model or a viewed run drives. It reports the client-observed `rpc.total` of `model.predict`, `env.reset`, `env.step`, and `runner.round`, under the names the native `Model.run` loop uses.

- `ServeOptions(compress_responses=True)` has an env server compress its responses (zstd, else gzip) for clients that accept it; every RLMesh client now accepts compressed responses. Compression is responses-only: RLMesh clients never compress requests, and servers refuse a compressed request (`UNIMPLEMENTED`) before reading it, so a peer without the endpoint token cannot make a server decompress one. It is off by default: on loopback a ~200 KB rendered-image observation shrinks to ~1.4 KB on the wire but the step takes as long, so it only pays on a slow link with compressible observations.

### Fixed

- `EnvServer.shutdown()` called from inside one of the server's own env callbacks under `start()` triggers the drain and returns, as it already did under `serve()`; the owner's `wait()` or `shutdown()` reports the stop. Before, it waited on its own callback and failed with `serve failed: close timed out` after both 5 s caps.

- A vector env served with `start()` runs every call on one dedicated thread for the server's life, as each lane already did, so a thread-bound vector env (a GL context) works there; before, its calls could hop threads on the blocking pool.

- A foreground `EnvServer.serve()` restores the process's SIGTERM disposition when it returns; before, its SIGTERM handler was never removed, so a later SIGTERM no longer ended the process.

- `Model.serve(address, options=ServeOptions(workflow_edition=X))` declares `X` even when `RLMESH_WORKFLOW_EDITION` is set, as `EnvServer` and the method's own docstring already did: the options' edition is the serve call's own value. Before, the environment variable won.

- A `Model(policy)` wrapping a policy object reads its workflow edition from the policy's class (`type(policy).workflow_edition`) for `run`, `session` and `serve`, and, when that class declares none, warns once with `WorkflowEditionWarning` as a `Model` subclass does. Before, it read the `rlmesh.Model` wrapper's `None` and never warned. A `Model` wrapping a bare predict callable still floats quietly.

- `describe(rlmesh.Model(policy))` describes what `describe(policy)` does: the target qualname, the edition declaration, the `load` params, the variants, the predict corners and a class-level `native_chunk` come from the wrapped policy (only `model_spec` is the model's own). Before, they came from the `rlmesh.Model` wrapper class (`rlmesh._native:Model`, no corners).

- `describe` reads `native_chunk` from the class, never from an instance, so describing a `Model` subclass instance no longer reports a K that `load()` set from a checkpoint.

- `describe_json(..., served_env=[])` raises `ValueError` instead of `IndexError`.

- An `rlmesh.Tensor` in an env's `info`, reset `options` or any other metadata is sent as the nested list of its elements, as a NumPy array is, and `sanitize_metadata` turns it into that list too; before, the codec raised `TypeError` and `sanitize_metadata` stringified it.

- A served model's failure reads `[INTERNAL] message` at the client in every language, instead of `[INTERNAL] [INTERNAL] message`.

- An integer `Box` samples in its dtype's exact integer domain instead of through `float`: a `uint64` Box with bounds above 2^63 no longer saturates at 2^63 - 1, and `int64`/`uint64` bounds beyond 2^53 no longer round. Samples of integer Boxes whose bounds are exact as floats, and of bool Boxes, are unchanged.

- Model and env servers disable Nagle's algorithm on accepted TCP connections, which removed a ~40 ms stall on some env steps.

- Served model endpoints enforce `RLMESH_MODEL_ENDPOINT_TOKEN` when set, taking precedence over token options. Empty or invalid environment values fail startup instead of disabling authentication, as does a token no client could send in an HTTP header (leading or trailing whitespace such as a secret file's trailing newline, or control or non-ASCII characters): the error names the variable and the problem, and the value is never trimmed.

- Served environment endpoints enforce `RLMESH_ENV_ENDPOINT_TOKEN` the same way, from both Rust `EnvServer`/`VectorEnvServer` and Python `EnvServer`.

- An endpoint token that cannot be sent in an HTTP header no longer locks every client out silently: a model or env server given one through its token option fails startup naming the problem, and a model or env client given one fails with an error naming the problem instead of `invalid address: invalid token`.

- Model and environment servers accept the endpoint token as `authorization: Bearer <token>` as well as the raw token.

- `Model.run()` presents `RLMESH_ENV_ENDPOINT_TOKEN` to the loopback env server it starts, so setting the variable does not lock the run out of its own env.

- `rlmesh check`, `rlmesh check-image`, and `python -m rlmesh._describe --check` join an env's tags against its spaces, per contract branch, the way `rlmesh.serve` does at startup, so tags whose widths or space classes do not fit now fail the check instead of passing it and crashing the server. A contract branch without tags, or whose tags fail to load, fails, as the platform probe does.

- `spaces.Text` accepts `min_length=0` (and `max_length=0`), as Gymnasium does, so a Gymnasium `Text(min_length=0)` converts instead of failing; only negative lengths are rejected.

- `rlmesh.run()` and `Session` read an episode's success the way the runtime does. Of `is_success`, `success`, and `task_success` in the final step's `info`, the first holding a bool, integer, or float decides; a string such as `"False"`, `None`, or a list is skipped instead of counting as success or ending the search. NumPy scalars and 0-d arrays count as their values.

- `rlmesh.trial_index(options)` reads a NumPy integer, and reads the per-lane list a multi-lane reset sends through the new `lane=` argument. Without `lane=` the list raises a `ValueError` saying to pass it, instead of returning `None`.

- `RemoteEnv.step` reports `completed_episodes` in its `info` on every step (`0` mid-episode), as `RemoteVectorEnv.step` does; it used to appear only on the step that ended an episode.

- Importing `rlmesh` in an embedded interpreter that installed no signal handlers ignores SIGPIPE, as CPython itself does, so a peer that hangs up mid-write fails that write instead of killing the host process. A handler the host installed is left alone.

- A C or C++ `rlmesh_model_run_local` / `Model::run_local` (and the Rust `ModelWorker::run_local`) runs the same number of episodes as Python's `Model.run`: one by default, or one per seed when `episode_seeds` is given, instead of running until the env ends. A `max_episodes` that disagrees with the seed count fails with `RLMESH_ERR_INVALID_ARGUMENT`. In Rust, `for_episodes(0)` runs nothing; C and C++ cannot ask for zero episodes yet, since `max_episodes = 0` means unset.

- A native run borrows the model, as Python's `Model.run` does: `rlmesh_model_run_local`, `Model::run_local`, and Rust's `ModelWorker::run_local` no longer fire the model's `on_close` when the run ends, so one model can run several times. A C or C++ model's `on_close` fires once per handle, when a serve stops or at `rlmesh_model_free` (the C++ destructor). In Rust, `RunLocalOptions::close_model(true)` still closes the model at the end of the run.

- A C or C++ model tracks up to 65,536 live episodes, as a Python model does, and refuses a new episode past that instead of evicting the least recently predicted one through `on_episode_end`: the predict fails with `RLMESH_ERR_RUNTIME` (Python's `RuntimeError`) before the callback runs, and every live episode keeps its count.

### Changed

- A Python `Model`'s `close()` is terminal and runs once: it stops a `serve` still running on the model (requests it already received finish, and that `serve` returns), waits for in-flight corner calls, then fires the close hook once; a subclass's authored `close()` no longer re-runs on every call. Afterwards `run`, `session` and `serve` on the model, and `predict`, `step` and `run` on a session opened before, raise `RuntimeError("the model is closed")`, and a session closed afterwards fires no `on_episode_end`. Before, a closed model kept working and the next serve rebuilt it.

- All corner and hook calls on one Python `Model` run one at a time, across its sessions, runs and serves, so two threaded sessions on one model no longer overlap inside it. A corner or hook that calls back into its own model (a predict, `run`, `session`, `serve` or `close()` on it, or a predict through a session on it) raises `RuntimeError` instead of deadlocking.

- `Model(on_close=...)` replaces a subclass's authored `close()` body, as the constructor's docstring says: with `on_close` set, `close()` runs the hook once instead of the authored body. A subclass passing both loses its authored body.

- A served model drops an env's per-episode context entries when that env's route is torn down (an evict-all `ResetAdapter` or a `ReleaseAdapter`), without firing `on_episode_end`, so episodes ended by teardown no longer leak until the 65,536-episode capacity refuses new ones.

- `native_chunk` is read once, after `load()`, and a value below 1 is refused there with `ValueError("native_chunk must be >= 1 ...")`. A `native_chunk` set in `load()` on a model with no chunk corner is refused by the constructor or `from_config` with `TypeError`, as a class-level one is; before, `Model.run` and `serve` refused it only at route resolve with `RuntimeError("model error: ...")`, and a local session never did.

- A `Model` subclass's declarations (a derivable `predict`, a class-level `native_chunk` with a chunk corner) are checked before `load()` runs, so a bad declaration no longer costs a full weight load.

- A wrapping `Model(policy)` reads its declarations from the policy: `allow_fusion` is the policy's (a wrapped policy that sets `allow_fusion = False` is no longer fused), and the wrapper's `allow_fusion`, `native_chunk` and `workflow_edition` attributes report the policy's. A wrapped bare callable keeps the defaults.

- A model returning a tuple as an action chunk now replays (and de-chunks) it as one frame, as the native engine already did when the model was served; return a list of frames instead. Only a list, an array or tensor (along its leading axis) and a mapping (per field) split into frames.

- `Model.run` raises `ValueError` for a chunk that is not exactly the declared `native_chunk` frames and for an empty chunk at a horizon above 1, as a local session already does, instead of `RuntimeError("model error: ...")`.

- `Model.run` and `serve` warn `RuntimeWarning` (once per episode, with the session's text) when a model with no `native_chunk` returns a chunk shorter than the execution horizon, as a local session does; before they only logged it. Native warnings in a Python process now go through Python's `warnings` machinery.

- A lane endpoint served from Rust, C or C++ reports each range warning (`rlmesh.conformance.warning`) once per lane for the server's life, as a Python server does, instead of once for all lanes; a vector env still reports once for all its lanes.

- A C or C++ env's failed callback reaches the client as `[INTERNAL] {op} failed: {message}`, as from Python and Rust, with `callback failed with status <n>` when the callback set no message (it read the raw message, or `environment {op} failed`). An env with no id serves `"UnknownEnv-v1"`, as Python's does (it was `"env"`). A render frame follows Python's lenient rule: any numeric image is cast to uint8, `[3, H, W]` and `[4, H, W]` encode too, and any other shape or kind is no frame instead of a failed render.

- The remote text of a Python env failure is `{op} failed: {message}` with no type name: an env that raises `ValueError("x")` in `step` reaches the client as `[INTERNAL] step failed: x` (it read `[INTERNAL] step failed: ValueError: x`), and an authored `EnvironmentException("bad")` as `[INTERNAL] step failed: bad`, as from a Rust, C or C++ env; a model failure reaches the client as `[INTERNAL] x`. Servers send the message without the code and the client adds it once.

- `EnvServer` raises `RLMeshException` (a `RuntimeError`) for a failed serve or close, from `serve()`, `wait()` and `shutdown()` alike, with the one text `serve failed: <message>` (`serve failed: close failed: boom`, `serve failed: close timed out after 5000ms`); a foreground `serve()` failure gains the `serve failed: ` prefix it lacked. Misuse (`wait()` before `start()`, a second `serve()`) stays `RuntimeError`.

- `EnvServer(path=..., transport="tcp")` raises `ValueError` instead of silently binding `unix://<path>`.

- An env without its observation or action space (or `single_*` spaces for a vector env) raises `TypeError` (`env must have 'observation_space'`) from `EnvServer(...)`, checked first: before, it leaked `AttributeError`, or `AdapterResolutionError` when tags were given.

- A one-lane vector env's `metadata["autoreset_mode"]` is checked as any env's is before the scalar view strips it: a present `None`, a non-string, an unknown string or `"SameStep"` raises `ValueError` (before, only a `SAME_STEP` enum was refused).

- `rlmesh.trial_index(options)` returns `None` for an integral float outside `[-2**63, 2**63)` (`1e19`), as the native languages do, instead of an integer past int64.

- The experimental C++ wrapper's authored `rlmesh::EnvironmentException("bad")`, `RecoverableEnvironmentException("bad")` and `ModelException("bad")` read `[INTERNAL] bad` from `what()`, as Python's `str()` and Rust's `Display` of the same error; thrown from a callback, the peer still receives the message once prefixed.

- `str()` of an authored env or model exception gains its code prefix: `EnvironmentException("bad")`, `RecoverableEnvironmentException("bad")` and `ModelException("bad")` read `[INTERNAL] bad`, as the same error reads in Rust, C and C++ and once it crosses the wire. `args[0]` is the raw message, including on the exceptions the clients raise, whose `str()` is unchanged.

- `describe` and `describe_json` raise `ValueError` when an explicit `kind` contradicts the object (`kind="env"` on a model with no `make`, `kind="model"` on a factory with no `predict`) instead of describing it the wrong way; a bare callable still takes the kind it is given. Describing a model whose class declares `native_chunk` without a `predict_chunk`/`predict_chunk_batch` corner raises `TypeError`, and one below 1 raises `ValueError`, as building the model would, instead of recording it.

- The experimental C API's `rlmesh_model_serve` and `rlmesh_env_bind` resolve the served edition as Python does: an `RLMeshServeOptions.workflow_edition` wins, else `RLMESH_WORKFLOW_EDITION` (a set-but-blank value floats deliberately); a server that declares neither prints one `rlmesh: WorkflowEditionWarning: ...` line to stderr per process.

- C API: the DLPack `(code, bits, lanes)` dtype struct is renamed `RLMeshDLPackDType` (deprecated; the tensor and value functions and the old space builders still take it), so `RLMeshDType` can name the dtype enum; the layout and the `RLMESH_F32`-style macros are unchanged. An owned spec from the old `rlmesh_space_*` builders is freed with `rlmesh_space_spec_free`; `rlmesh_space_free` now takes the new `RLMeshSpace` handle, and still frees an owned spec passed by a binary built against the previous header. The old builders are deprecated in favour of `rlmesh_box_new`, `rlmesh_discrete_new` and `rlmesh_dict_new`. The ABI version is unchanged.

- Rust: `rlmesh::spaces` is the shared spaces module above; the wire types it re-exported (spec payloads and builders, `SpaceValue`, the core `Tensor` and `DType`, `MetaMap`, render and request types) moved to the hidden `rlmesh::binding::spaces`. The crate-root `rlmesh::SpaceSpec`, `SpaceValue`, `EnvContract` and the prelude are unchanged; `rlmesh::binding::space_spec_wire` gives the wire spec of a `spaces::SpaceSpec` for the `Env` trait.

- `Space.seed()` is annotated `-> int`: it always returned the seed it applied (one drawn from OS entropy for `seed=None`), never `None`.

- `Box(spec)`, `Discrete(spec)` and the experimental `MultiBinary(spec)`, `MultiDiscrete(spec)` and `Text(spec)` raise `ValueError` for a spec of another kind, as `Dict(spec)` and `Tuple(spec)` already did. `Box` and `MultiBinary`/`MultiDiscrete` used to wrap any kind, and `Discrete` and `Text` failed with `KeyError`.

- `Discrete`'s `dtype` is annotated with the three dtypes it accepts, `"int64"`, `"int32"` and `"uint8"`; the runtime check is unchanged.

- A `Box` with integer bounds on an integer or bool dtype (`bounds_kind == "typed_uniform"`) reads `low` and `high` as one number, as a float Box does, instead of a one-element list. `Box(0, 255, [2], "uint8").high` is `255`. The describe envelope's space JSON is unchanged.

- `Box` refuses a fractional bound on an integer or bool dtype with `ValueError` instead of truncating it: `Box(0.5, 3.7, [2], "int32")` was the range 0..3. Integral floats (`Box(0.0, 10.0, [1], "int64")`) are accepted and stored exactly.

- `Box.contains` requires the space's exact shape, as Gymnasium does: a `(6,)` value is not a member of a `(2, 3)` Box, and a bare number is not a member of a `(1,)` Box. Before, only the element count and dtype were checked. Dict and Tuple members check their Box children the same way.

- `RANDOM_SAMPLE` seeds the action-space sampler with each episode's reset seed, so a seeded run reproduces its actions; an episode without a seed keeps the running stream. Before, the sampler always drew from OS entropy.

- `Tensor(buffer, shape, dtype)` raises `ValueError` instead of `OverflowError` when the element or byte count overflows, like its other invalid arguments.

- C API errors follow the Python classes: a wrong-kind value or space read returns `RLMESH_ERR_TYPE` instead of `RLMESH_ERR_INVALID_VALUE`, which is deprecated and no longer returned; a malformed tensor or non-UTF-8 text is `RLMESH_ERR_INVALID_ARGUMENT`; a server-side failure (a failed bind) is `RLMESH_ERR_INTERNAL` instead of `RLMESH_ERR_TRANSPORT`, which is renamed `RLMESH_ERR_CONNECTION` and kept as a deprecated alias; a protocol failure is `RLMESH_ERR_PROTOCOL` instead of `RLMESH_ERR_INTERNAL`. `rlmesh_last_error_message` is Python's `str(exc)`: the `connection error:`, `environment error:`, `model error:` and `internal error:` prefixes are gone, environment and model errors read `[CODE] message`, and a timeout reads `operation timed out after 5s`. `rlmesh_last_error_is_recoverable` is nonzero only for a recoverable environment or model error, no longer for a timeout or connection failure.

- Every error an env reports raises `EnvironmentException` (or `RecoverableEnvironmentException`) with its `code`, including the codes `TIMEOUT`, `INVALID_ACTION` and `CANCELLED`, which raised `TimeoutError`, `ValueError` and `RuntimeError`. This breaks an `except TimeoutError` or `except ValueError` around an env call; catch `EnvironmentException` and read `code`. A client-side deadline still raises `TimeoutError`.

- A model failure raises `ModelException` instead of `RuntimeError("model error: …")`; its text is `[CODE] message`. Internal and server-side failures raise `RLMeshException`, and protocol failures (a failed handshake, a malformed message, an invalid contract from the peer) raise `ProtocolException`, instead of a bare `RuntimeError`. All three subclass `RuntimeError`, so existing catches keep matching.

- An env code `UNSUPPORTED` reaches Python as `"UNSUPPORTED"` instead of `"INTERNAL"`.

- A Python env server treats a raised exception as recoverable only when it is an `EnvironmentException` with a truthy `is_recoverable`; another exception carrying the attribute, such as `ModelException(is_recoverable=True)`, now ends the session like any other failure.

- The C and C++ API's type names spell the project name `RLMesh` (`RLMeshStatus`, `RLMeshValue`, `RLMeshEpisode`, ...) instead of `Rlmesh`, matching the Python `RLMeshError`. This breaks source but not ABI: function names (`rlmesh_*`), macros (`RLMESH_*`), the `rlmesh::` C++ namespace, struct layouts, and the ABI version are unchanged.

- `rlmesh check` warns on an env without `tags` instead of failing it: an untagged env runs against spec-less models; tags are what let the platform adapt a spec'd model to it.

- `RemoteEnv` and `RemoteVectorEnv` log a warning, once per client, when an env's own `info` key shadows a runtime-reserved one (`episode_ids`, `completed_episodes`). The env's value is still kept.

- The live viewer shows the env's first declared image role by default instead of its `render()` frame. The role rides the step response, while `render()` costs one more env round trip per drawn frame; `render` stays selectable, and `View(source="render")` asks for it.

- Adapter resolution errors for a missing role now suggest near matches among the roles the other side offers (`did you mean "x/goal_body"?`), and, when an `x/` role is involved, say that `x/` roles bind only to the identical string. The suggestion is only a hint: binding still matches roles exactly, and one registered role is never suggested for another. The zero-fill caution for an optional state input names the absent role and part (`zero-filled because the env offers no match for "proprio/eef_pos" (part "right_arm")`) instead of only counting components.

## [0.1.0] - 2026-09-23

RLMesh connects models to environments across process, dependency, and machine boundaries with a Gymnasium-style API. RLMesh 0.1.0 ships the sealed `2026.06` edition and retains `rlmesh-wire-v1`. Declare the edition a model or environment was authored against to keep its behavior across package upgrades. The runtime selects a shared edition and refuses interactions a peer cannot express; see the compatibility policy for the contract and its current test coverage.

### Added

- `Model.from_config(**config)`: build an authored `Model` subclass with `load(**config)`, the keywords validated against `load`'s signature and the declared `params` (`ParamError` before any weights load), `load` run exactly once; the served binding (`RLMESH_MAKE_KWARGS`) takes the same path. A framework base class with no predict corner of its own refuses it.
- Sticky workflow-edition declarations: a participant writes down the edition it was authored against and keeps it across rlmesh upgrades (the NixOS `stateVersion` model). Declare it, highest surface first, with `run(workflow_edition=)` / `session(workflow_edition=)`, `RLMESH_WORKFLOW_EDITION`, `ServeOptions(workflow_edition=)` / `--workflow-edition`, `EnvFactory.workflow_edition` / `Model.workflow_edition`, or `[tool.rlmesh] workflow_edition` in `pyproject.toml`; public `rlmesh.run()` and `rlmesh.session()` accept it for served models and the random baseline too. An empty `RLMESH_WORKFLOW_EDITION` declares nothing deliberately and ends resolution there, clearing a lower-priority `ServeOptions` declaration, and declaring nothing at all floats to this build's newest edition; an authored `EnvFactory`/`Model` subclass or a served participant says so once per process at the caller's line (`rlmesh.WorkflowEditionWarning`), while an ad hoc callable in a local run floats quietly. An edition this build cannot run a session at is refused where it was written, not at the first connection.
- WANT/CAN edition negotiation: every handshake carries the declaration as `preferred_workflow_edition` (an additive `rlmesh-wire-v1` field on `HandshakeRequest` and `HandshakeResponse` that a peer may omit) next to the editions the build can drive, and the runtime runs the session at the highest edition all of env, model, and runtime support that every declaration admits (a bare base admits every cohort of itself; a cohort spelling uses the full edition ordering as its ceiling), refusing cleanly before any Join stream opens, naming each tier's declaration and supported set, when there is none. A served-model session declares on its model leg the same edition its env leg does, and hands the model client the env's real handshake offer, so a refusal never attributes one tier's value to another.
- The runtime pins the env to the session edition: `ConfigureEnvRequest.selected_workflow_edition` is sent as the first Join message and acked before the first Reset (a served-model session pins both legs to the three-way floor); a served env records the pin and reports conformance warnings under that edition's reserved key, falling back to its current edition for runtimes that send none.
- The editions a build can drive are its retained list, generated from `rlmesh.toml`'s `supported_editions` and offered and accepted from that one source, and the negotiated edition is a typed `Edition` in the runtime with a per-edition defaults table, so a sealed edition's behavior is read from its row rather than from scattered constants.
- `rlmesh.current_workflow_edition()` reports the bare `YYYY.MM` edition this build runs at (`"2026.06"`), the same on a release and on a prerelease or source build, and is the value to paste into a declaration; `rlmesh.build_info().workflow_edition` reports the build's exact spelling, which is also accepted as a declaration when you mean to pin to one moving build.
- `RemoteEnv.selected_workflow_edition`, `RemoteVectorEnv.selected_workflow_edition`, `SandboxEnv.selected_workflow_edition`, `SandboxVectorEnv.selected_workflow_edition`, and `Session.selected_workflow_edition` report the edition a connection or session settled on, in the spelling the peers agreed; `workflow_edition` everywhere means what this peer declares.
- A cross-version matrix, `mise run test:crossver`, drives this tree against the pinned published wheel on both legs in both directions and asserts the handshake, the negotiated edition, and the refusal of an unknown edition and a forged protocol generation on each build; cells that need a second sealed edition are listed as pending rather than dropped.
- Serve Gymnasium-style environments and drive them with `reset`, `step`, `render`, and `close` over local or remote gRPC transports: `EnvServer`, `RemoteEnv`, `RemoteVectorEnv`, and `python -m rlmesh.serve` as a universal container entrypoint.
- A blocking `EnvServer.serve()` (what `python -m rlmesh.serve` runs) keeps the env on the calling thread: `reset`/`step`/`render`/`close` run on the thread that built the env, usually the main thread, for a scalar env and for a lockstep vector env alike, while the gRPC server runs on a helper thread. Simulators that only work from the thread that created them, such as Isaac Sim, need no thread-hopping wrapper. Ctrl-C drains and closes the env first and then raises `KeyboardInterrupt` from `serve()`, never inside an env call; a second Ctrl-C interrupts an env call that will not return (Python code; a call stuck inside a native library cannot be preempted). `EnvServer.wait()` responds to Ctrl-C.
- `RLMESH_ALLOW_REMOTE_SHUTDOWN=1` opts a served environment into honoring the remote `shutdown` RPC, so an orchestrator that queues env workloads can tell a finished worker to exit and free its slot. The variable can only enable remote shutdown, never disable a programmatic `allow_remote_shutdown=True`.
- A vectorized env with `num_envs == 1` serves as the scalar env it is. Each value loses its batch axis (lane 0 of the observation and of the `info` under gymnasium's `key`/`_key` convention), actions gain one, and the runtime owns resets, so per-episode `seeds`, `trial_index` and `max_episode_steps` apply. A batched simulator configured with one lane, such as Isaac Lab at `num_envs=1`, needs no scalar rewrite. A one-lane env with `SAME_STEP` autoreset is refused, because its terminal observation is already the next episode's first.
- Lane serving: `EnvServer([env, ...])` (or `RLMESH_NUM_ENVS=N` on a prebuilt image) hosts N independent copies of a scalar env on one endpoint. Each lane runs on its own thread, and every lane must carry the same env contract (spaces, metadata, tags) as lane 0 or the server fails at construction. The endpoint advertises `subset_step`, `StepRequest.env_indices` and partial-width `StepResponse`s are honored, and the runtime driver treats each lane as its own reset/predict/step loop over one multiplexed Join stream, so lanes reset and step at their own pace while every episode's seed and index come from a route-global slot counter; lanes waiting for a prediction share one grouped predict on a model with a batched corner (`PredictScheduler`, one fused forward, `RuntimeModel::fuses_predicts`) and otherwise each predict on their own, applied as it lands, so a slow prediction on one lane never holds another. A served or managed model receives one predict per lane and batches on its own side. A single env is the one-lane case of the same server.
- Evaluate models locally, against a remote server, or inside a sandbox: `Model`, `RemoteModel`, and `SandboxModel`, with `run()` for whole evals and `session()`/`Session` for manual `reset`/`predict`/`step` control.
- `rlmesh.run()` and `rlmesh.session()` take a `Model` (an instance or subclass class) or a served handle and refuse a bare predict callable or policy object with a `TypeError` naming the fix: the library never picks a framework, so wrap it in `rlmesh.numpy.Model(fn)` / `rlmesh.torch.Model(fn)` / `rlmesh.jax.Model(fn)`, or `rlmesh.Model(fn)` for raw values. `python -m rlmesh.serve module:Policy` serves a policy object as a NumPy model. The live viewer belongs to `Model.session`, `Model.run` does not take `view`, and the module-level `run()` forwards it only for a served handle.
- A model instance passed to `run()` / `session()` is borrowed: neither the run nor closing the session calls its `close()` (a model built from a class you passed is closed with the call or session), and a caller's env is left open unless `close_env=True`; an env built from an `EnvFactory` is closed when the run or session ends, and also when adapter resolution or loopback setup fails. `Model.close()` drops the cached native worker, so a model that ran natively is collectable after close. `EnvServer(..., close_env_on_shutdown=False)` serves an env without closing it at shutdown, which the loopback server `Model.run` stands up uses.
- Tag-driven IO adapters that resolve environment tags against model specs at runtime. Environments tag what they emit (`ImageTag`, `StateTag`, `TextTag`, `Split`); models declare what they consume (`Image`, `State`, `Text`, `Concat`) and produce (`Action`, `Actuator`). Conversions cover rotation accept-sets, custom rotation encodings (`CustomEncoding`, published as a `module:callable` reference or a `<local>` marker for an in-process callable, with execution staying host-side), image `fit` and `normalize` ranges, channel validation, optional cameras, frame stacking, per-actuator `clip`/`scale`/`invert`/`threshold`, and role-less actuators; `adapter.explain()` prints the chosen transforms and `adapter.advisories()` surfaces severity-tiered data-loss notes (`info` for benign hints, `caution` when the adapter substituted or fabricated model-visible data). Rotation conversions out of a matrix (`rot6d`, `euler_xyz`, any post-rotated source) to `axis_angle` go through the quaternion, so they stay exact near 180 degrees and for rotations as small as 1e-4 rad.
- `Field` and `ConcatPart` carry unknown keys through a relay hop; the publish gate rejects them by name, and a typo on a split field surfaces there and as a read taint.
- Roles `ACTION_EEF_POS`, `ACTION_EEF_ROT`, `ACTION_JOINT_POS`, and `IMAGE_WRIST`, so an end-effector pose action, a joint command, and a wrist camera bind by role instead of by ad-hoc name; a second arm or camera is the same role under a `part`. A model-side ad-hoc role the env does not answer is an `info` advisory, and a fabricated fill on an optional roled action is a `caution`.
- Per-predict context for stochastic and stateful models: the trailing `context` a predict corner declares carries `predict_index` (the re-plan ordinal within the episode), `predict_seed` (a reproducible mix of the episode seed and that ordinal, also computed by `rlmesh.predict_seed(episode_seed, predict_index)`), and a per-episode `state` dict that lives as long as the episode does. Batched corners receive one `PredictContext` per row (`BatchPredictContext`), and the Rust `PredictFn::predict_batch` and `predict_chunk_batch` receive row-aligned `EpisodeInfo`. The `Model` hook that fires when an episode ends, `on_episode_end(self, episode_id="")`, drops one episode's state and shares its name with the constructor callback and the runtime; a wrapped policy object's `reset()` is picked up as that hook. `RLMESH_EPISODE_CAPACITY` (default 65,536) caps the SDK's live episode store: a new episode past the cap is refused with an error naming the variable, and a live episode's state is never evicted, its prediction ordinal reset, or its end callback fired early to make room.
- Trial ordinals for environments: `EnvFactory.reset_options = ("trial_index",)` opts an env into receiving the runtime's 0-based trial ordinal as `reset(options={"trial_index": k})`, read with `rlmesh.trial_index(options)`. An env that does not declare the key never sees it. The runtime mints the ordinal for every episode it starts, from `RuntimeSessionSpec.trial_index_base` (0 by default), and reports it on episode events, summaries, and `EpisodeResult.trial` whether or not the env asked for it; `run(trial_index_base=)` / `Session.run(trial_index_base=)` pick the first ordinal, so a local eval walks the same states as a platform shard. Under `NEXT_STEP` autoreset no ordinal is minted and a non-zero base is rejected. A reset that restarts several lanes of a lane-served env delivers each lane its own ordinal, so `rlmesh.trial_index(options)` reads an integer on every lane. The encoding is one Rust implementation shared by the driver and external probers, exported as `rlmesh_runtime::{reset_options_for, declares_reset_option, TRIAL_INDEX_OPTION}`, so a second caller cannot drift from what the driver sends.
- Declared chunk length: a model with a fixed chunk sets `native_chunk = K`. The runtime then refuses an `execution_horizon` above K when the adapter resolves and fails a predict whose chunk is not exactly K long, instead of quietly re-planning every K steps of an H-step plan. Undeclared, the contract stays elastic: a short chunk replays as far as it goes and warns once. The horizon is bounded at 1024.
- Image resample kernels `bicubic_aa`, `lanczos3_aa`, and `area` alongside `bilinear` and `bilinear_aa`, each anchored to Pillow and OpenCV within one 8-bit step, including the clamp Pillow applies between its two passes.
- Image spec fields `crop`, `crop_area`, `crop_mode`, `channel_order`, `jpeg_quality`, `render`, `offsets`, `stride`, and `stack_pad`, all keyword-only after `stack` and omitted from a published spec when default. `render` asserts the camera resolution the model was trained against rather than requesting one, and a bound camera that disagrees is a `RenderMismatch` at resolve. The jpeg round-trip is baseline 4:2:0 through `jpeg-encoder`, forced explicitly because that crate switches to 4:4:4 above quality 90; the IJG acknowledgment ships in the wheel notices.
- Frame windows in the core engine: `Adapter.observe`, `history_keys`, and `history_windows` keep a stacked model's window per episode, and chunk replay ticks it on every replayed step, so the model sees the same payloads at every execution horizon. Windows are keyed by structured placement, so a dotted `"camera.rgb"` input and a nested `{"camera": {"rgb": ...}}` input stack their own frames and two cameras never mix histories.
- Observation history on the wire, so a frame-stacked model works with action chunking on the native and served paths. The runtime declares on `ResolveAdapter` that it delivers history (`delivers_history`), a stacked route answers the inputs that hold a window (`ResolveAdapterResponse.history`), and each later `Predict` carries the env steps the runtime executed from a replayed chunk as `PredictRequest.history` rows, oldest first, stamped with a per-group `step` counter that the engine holds to consecutive values per episode (a gap or repeat fails the predict rather than stacking a wrong window). The four proto fields are additive; a runtime that never offers history and a model that never answers it exchange the same bytes as without them. `Model.run`, a served model under the Rust runtime driver, and `RemoteModel` all deliver it, and the Python session ticks its window locally. A served model advertises `rlmesh.model.observation_history.v1`, and `RemoteModel` offers `delivers_history` only to a served model that advertised it at handshake (`ModelClient::server_ingests_history`), so a model without the capability receives no history rows. A frame-stacked adapter at `execution_horizon > 1` on the native engine is refused only when the runtime did not offer observation history, and the error says so. The `history.rows` telemetry metric counts rows per predict.
- The frame-window budget (`RLMESH_FRAME_HISTORY_LIMIT_BYTES`, default 2 GiB) bounds the whole model endpoint: a predict that would open windows for a new lane is refused while every route's live lanes, charged at their full window size, would exceed it. Routes with no stacked input are never charged. The served resolve, which names no lanes, validates one lane per route and refuses a stacked route whose windows would exceed the budget.
- State geometry: a `CustomEncoding` can sit at any offset of a concatenated state and every piece records its width, which apply asserts. `Constant(dim=, fill=)` parts and `State(fill=)` declare a filler that never reads as fabricated data; `post_rotate` (with an exact `Rotation.from_matrix`), `scale`, and `offset` transform a piece after decoding.
- Body parts: `part=` on `ImageTag`, `StateTag`, `Field`, `Actuator`, `Image`, and `State`/`Concat` parts names where a role repeats on a body, matched as an identity key. A part is any identifier the env and the model agree on exactly; `LEFT_ARM`, `RIGHT_ARM`, `HEAD`, `TORSO`, `BASE`, `LEFT_LEG`, and `RIGHT_LEG` (`adapt.PARTS`) are the suggested spellings, not a registry. A model that names a part binds only that leaf; one that names none binds the env's only leaf of the role under any part with an `info`, and fails naming the parts when there are several. Duplicate detection in `Split`, `Action`, and `EnvTags` is keyed by `(role, part)`, so one `action/joint_pos` per arm is a valid layout. The kind prefixes `image/`, `proprio/`, `text/`, `action/`, and `command/` are a closed set enforced at authoring and resolve. A role with no `/` is ad-hoc and binds on exact-string agreement, and `x/` is the escape prefix for a whole role that is deliberately outside the registry. `explain()` shows a bound part as a `#part` suffix.
- Axis labels: `labels=` on `StateTag`, `Field`, `Actuator`, and `State`/`Concat` parts names the joints of a vector in that side's own order, and the resolver aligns the two sides by name, so a checkpoint trained in Isaac Lab joint order resolves against a Unitree SDK-order environment as a derived permutation (`explain()` prints `perm[3,4,5,0,1,2,9,10,11,6,7,8]`). The two tuples must name the same joints: a labeled model against an unlabeled env, or a label either side lacks, is a `LabelMismatch`, also on an `optional` model part. Labels are the env's own joint names, written from its configuration, at least one and none repeated; omitting them accepts positional order with no name check. `scale` and `offset` on a `State` part and an `Actuator` (which also takes `offset`) accept a per-axis sequence in label order, serialized as `axis_scale`/`axis_offset`; `explain()` prints them as `label:value`.
- Body roles and projected gravity: `BASE_ANG_VEL` (`proprio/base_ang_vel`), `BASE_ROT` (`proprio/base_rot`) and `COMMAND_BASE_VEL` (`command/base_vel`, the first role under the `command/` kind) register the floating base's gyro, orientation and velocity setpoint, all framed. A model reads the orientation as projected gravity with `encoding="gravity_xyz"` (`R_world_from_base^T · (0, 0, -1)`, 3 wide): any rotation encoding converts into it and nothing converts out of it, so an env publishing `gravity_xyz` binds only a model that reads it, and a `post_rotate` or an actuator naming it is a codec error. `provenance=` on `StateTag`, `Field` and `State`/`Concat` parts (`"sensed"`, `"estimated"`, `"privileged"`; a model may accept a sequence) says where a state leaf's numbers come from and follows the frame rules, with a disagreement a `ProvenanceMismatch`; it is part of the env leaf's identity, so a simulator may publish one role as its truth and as its estimate, and a model that pins none against both is `Ambiguous`. `State`/`Concat` take a container `clip=(low, high)` applied to the assembled vector before `pad_to`. `explain()` prints `#sensed` and `clip[-100.0,100.0]`.
- End-effector wrench: `EEF_WRENCH` (`proprio/eef_wrench`) registers the six-axis force/torque a wrist sensor reads, force first, 6 wide and framed; the frame vocabulary includes `tool`, the frame attached to the end effector, so a wrist-mounted sensor (`frame="tool"`, `provenance="sensed"`) and a controller's estimate (`frame="robot_base"`, `provenance="estimated"`) are different leaves of one role and a model binds the one it was trained on. Its `labels` (`fx`..`tz`) name its own axes.
- A `model.reset_adapter` telemetry row: the runtime driver records `rpc.total` for every eviction RPC it awaits, so the time a model spends ending episodes shows up in the runner's windows next to `model.predict` rather than only in the gap between episodes. Eviction is bounded by the predict timeout in the loop and by the close timeout at teardown, and is cancellation-aware; an unanswered eviction is logged and abandoned rather than holding the route. A route that ends mid-episode ends every episode it still holds on the model side before releasing, so a persistent endpoint keeps no failed run's Python episode state.
- Previous action: `adapt.Previous(role, part=None, fill=0.0)`, a `State`/`Concat` part with `source="action"`, reads the model's own output actuator of the same role and part back as the raw action executed at the previous step, in model order and before the actuator's affine, with `fill` before an episode's first action. It binds the spec's own actuator (none is a `MissingRole`), `labels` reorder from the actuator's labels, and an env observation tagged under `action/` is an `ActionRoleOnObservation` join error. Every executed action is recorded under its step at every replay site (the served engine per chunk frame and lane, `RemoteModel`'s replay through the history rows, the Python session and `Adapter.transform_action` with `Adapter.observe` counting a replayed step), an observation whose previous step recorded none fails loudly, and a route with the part negotiates observation history like a stacked one, so the runtime delivers replayed steps and a prefetched predict carries the rows buffered so far. `explain()` prints `previous action/joint_pos (fill 0.0)`.
- Coordinate frames: `frame=` on `StateTag`, `Field`, `State`, and `Actuator`, and `reference="current"` or `"target"` on delta actuators. A delta actuator (`action/delta_eef_*`) may declare the `frame` its axes are expressed in next to its `reference`. A disagreement is one `FrameMismatch` code on either axis, a model that declares a frame the env leaves unstated is a `caution`, and the spec gate can require frames on both sides. Spec descriptions render them as `@robot_base` and `~target` suffixes.
- Env contract branches: `EnvFactory.tag_params` names the make parameters that change an env's tags, `tags_for(**params)` returns the tags for one binding, and `describe()` lists every branch under `env_contracts`. The make wrapper stamps the chosen branch and the declared reset options into the env's metadata, and `EnvServer` asserts the branch the platform expects when `RLMESH_EXPECTED_ENV_BRANCH` is set.
- Action chunking and batched prediction in the runtime. Implement the most general of four corners and the runtime derives the rest: `predict`, `predict_chunk`, `predict_batch`, `predict_chunk_batch`, active in local `run()` evals and on the served wire path alike. The runtime owns chunk replay and the execution horizon, so one action still reaches the environment per step. Any unbatched corner may accept a trailing `context` argument carrying the episode's `episode_id` and `episode_seed`, locally and across the wire. Grouped predict requests spanning several environments fuse into one batched forward pass when the model's batched corner is the corner a direct predict would run, so grouping never changes model behavior; a fused failure keeps the model error's recoverable flag and annotates each group with its own input signature. `Model.allow_fusion = False` opts out a batched forward that assumes fixed-size, single-environment batches, such as a shape-pinned `jit` trace or per-batch statistics; grouped predicts then run one route at a time.
- Seeded evals: `run(seeds=[...])` gives each episode its own seed (and sets the episode count), threading it to the environment's `reset(seed=)` and to the model as episode context; `EpisodeResult.seed` records what each episode ran with.
- `episodes=` on `run()`, `Model.run`, and `Session.run` is exact: one episode by default, `len(seeds)` when only seeds are given, and the two must agree when both are (no unseeded tail); `episodes=0` runs nothing and a negative count is refused. On a vectorized env the budget bounds episode starts, so `result.num_episodes == episodes` on every path; a lockstep lane the env rolls past the budget under `NEXT_STEP` autoreset runs unscored (never counted, reported, or seen by hooks). Seeds and per-episode caps on an autoresetting vector env are refused before any episode starts.
- `RunResult.success_rate` counts only the env-reported task outcome, read from `is_success`, `success`, or `task_success` in `info`, in that order, and is `float | None`: `None` when the run is empty or any episode lacks the signal, never a rate inferred from `terminated`. A Gymnasium vector env with `NEXT_STEP` autoreset reports each lane's terminal outcome from the per-lane info arrays, and a runtime-imposed step or time cap keeps the last step's info, so `success_rate` on a vector or capped run reports the same outcome a scalar run does. The recorder's exported `successRate` follows the same rule and may be null, and the viewer's HUD shows `done` for a terminal state with no reported outcome.
- Startup phase marks: `python -m rlmesh.serve` records when it reached `imports`, `model` or `env`, and `listen`, in milliseconds since the process started (plus `process`, the interpreter and `rlmesh` import time before the entrypoint ran, from `/proc` on Linux), prints them on the serving line, and stamps them on the handshake as `PeerInfo.extra` keys `rlmesh.startup.<phase>_ms` beside the build keys. `rlmesh.serve.startup_marks()` returns the marks reached so far and `register_python_peer_info(extra=...)` exposes the extra map the Rust side merges.
- Run observability: pass `hooks=RunHooks(...)` to `run()` / `Model.run` / `Session.run` for per-step `StepEvent`s (action, reward, the step's own terminal flags, timing, lazy role-addressed reads) and episode/run boundaries, in the same order on the native loop and the session loop; `on_run_start` receives a `RunContext` (the `Session` itself, or the native run's context) for role reads and frame discovery. Cap episodes with `max_episode_steps`/`max_episode_seconds`, and read per-episode timing off `EpisodeResult`. `instruction=` works on `run()` too. Step telemetry records hook transform round-trips, so time spent in `RunHooks` transforms is visible per step.
- `EpisodeResult.predict_ms` / `step_ms` are that episode's own per-step means on every path (`float | None`, `None` for an episode that ended before its first step); the runtime times every predict and env step it issues and reports them per episode, so the record `on_episode_end` receives equals the one in the result, and `Recorder.capture()` and `Recorder.add(result)` record the same metrics. `StepEvent.predict_ms` is the predict that landed since the previous step (zero for a chunk-replay step; under prefetch, the next chunk's), the same definition the per-episode mean is built from.
- Read-only observation inspection: `Session.reader()`/`Session.read()` extract any role from a raw observation through the model's adapter, and `Session.observation_roles()`/`EnvTags.observation_roles` list the roles an env declares. An adapted `Session.predict` returns the action in the env's declared Box shape and dtype and refuses a value an integer Box cannot hold rather than truncating or wrapping it.
- PyTorch and JAX end to end: environments served with framework tensors (`EnvServer(env, framework="torch", device="cuda:0")`), `rlmesh.torch` and `rlmesh.jax` factory, model, and sandbox classes, and DLPack-native `Tensor` transport with zero-copy NumPy, Torch, and JAX backends. `Model.run(factory)` and an adapted `Model.session(factory)` on a `rlmesh.torch.EnvFactory` hand the env torch actions and accept its torch observations.
- Isolated sandboxes: rebuild an environment identically in a container (`SandboxEnv` with grouped `SandboxBuild`/`SandboxRuntime` config, including `SandboxRuntime.user` for writable bind mounts) or run a prebuilt image. A bare tagless image name resolves against local Docker images and never silently falls into a source build.
- An experimental C ABI: `crates/rlmesh-capi` is a C11 header plus a header-only C++17 wrapper that lets a C or C++ program implement `predict` and have the runtime drive it against an environment (`rlmesh_model_run_local`) or serve it as a gRPC model service. Observations reach C already decoded, one value handle per sub-env, and `RlmeshEpisode` carries each episode row's `predict_index` and `predict_seed` (the same mix as `rlmesh.predict_seed`; `seeded` says whether the seed is meaningful); actions return as owned handles Rust validates against the route's action space, and run options take a `trial_index_base`. `RlmeshServeOptions.workflow_edition` takes the same edition declaration as the Python surfaces. This is **ABI version 4** (`RLMESH_ABI_VERSION`, `rlmesh_abi_check()`, and the versioned SONAME). Built from source with `mise run test:cxx`; the crate is not published to crates.io yet.
- `policy:check` pins the additive-forever wire-v1 contract in `rlmesh.toml [wire]`: the 256 MiB gRPC message cap, every proto enum's value count, and the `MetaValue.kind` / `SpaceSpec.spec` oneof arm counts must be updated deliberately in the same change; the emitter-side house rule is documented under "Additive-forever rules" in the editions guide.
- Docs: the compatibility page states the sticky edition guarantee, the WANT/CAN negotiation, the runtime-as-interpreter and dual-stack rules, the 256 MiB cap and retained-edition contract, the cross-version matrix, and a release-anchored roadmap.
- `rlmesh-proto` ships its retained workflow-edition list (`supported_editions.txt`, current edition first) so a crate built from crates.io offers every retained edition, not just its own; the build fails if the file drifts from `rlmesh.toml`, `bump_version.py --sync-editions` regenerates it, and `policy:check` enforces it.
- The runtime records each served peer's ceiling (the highest edition both implement, the wire-v1 dtypes, capabilities, and the message cap) on `RuntimeSessionSpec` as `env_ceiling` / `model_ceiling`, exposed by `RemoteModel::ceiling()`.
- A `RelayPolicy` seam (`RefusingRelayPolicy` by default, `RuntimeDriver::with_relay_policy`) checks the env contract, observations, and actions against the target leg's ceiling; a converting policy can rewrite leaves and attach an advisory, which reaches `RuntimeReport.advisories`, a `relay_advisory` hook, and `RunResult.advisories` in Python. `Advisory` lives in `rlmesh-spaces` and is re-exported from `rlmesh-adapters`.
- Declared construction parameters: `EnvFactory.params = ParamSpec(Param(...))` validates `make()` arguments, `enumerate_variants()` lists a factory's concrete sub-environments, and `describe()`/`describe_json()`/`python -m rlmesh._describe` emit a JSON metadata envelope without loading a model (an env's spaces are read off one representative instance); a model envelope reports the predict `corners` the class actually defines, introspected from the code that ships rather than declared. `python -m rlmesh._describe --check IMAGE` validates a built image's rlmesh labels locally, the way the platform probe will, before pushing, and exits nonzero on a failure so it can gate a push in CI: packaged checkpoint declarations must be well-formed (DNS-label names, a `uri` per entry, a single default), a present `dev.rlmesh.describe` label gets the same class-level checks as `rlmesh check`, and a missing one is reported as not checked, since the platform reads describe off the `rlmesh.serve` handshake.
- A live debug viewer: pass `view="terminal"`, `view="http:9000"`, or `view="both"` to `session()` (or to the module-level `run()` for a served handle), or configure `rlmesh.View(...)`. It is best-effort and never breaks an eval.
- Record eval runs to a portable bundle for upload: `rlmesh.Recorder` accumulates per-episode metrics with `add()` (from any `RunResult`) or `capture()` (live `RunHooks` on the session path) and writes an `rlmesh.result.v1` folder or zip with `export()`. On the session path it records the same sources the live viewer offers (the env's `render()` frame plus every declared image role), each to its own AV1 `.mp4`, encoded in process (pure Rust, no ffmpeg or extra dependency; `Recorder(fps=, quality=)` set playback rate and size/fidelity); env-produced video files are carried into the bundle by path. Capture is best-effort: a source that fails to read or encode is dropped with a warning and never aborts the eval.
- `rlmesh.sanitize_metadata()` coerces a third-party sim's rich `info` objects into wire-safe metadata, and connection failures name the address and the likely fix.
- Client timeouts: `RemoteEnv`, `RemoteVectorEnv`, and `RemoteModel` accept `connect_timeout_seconds` and `request_timeout_seconds`, so a hung peer fails with a `TimeoutError` instead of blocking forever.
- Fail-loud argument handling: a parameter that cannot be honored (`instruction=` on a served model, an unknown `vectorization_mode`, a conflicting CLI flag) raises with a directive error instead of being silently ignored.
- Self-explanatory predict failures: when a model's `predict` raises, the error is annotated with the adapter-assembled input signature (key → dtype/shape), both in local `run()` loops and across the wire from a served model, so a shape mismatch names what the model was actually handed.
- Managed-platform sign-in from the CLI: `rlmesh login` (RFC 8628 device flow), `rlmesh logout`, `rlmesh whoami`, and `rlmesh registry login` (registers the bundled `docker-credential-rlmesh` helper, so docker fetches a fresh short-lived token per pull/push, and hands the registry host to the profile that logged in most recently), with named profiles (`rlmesh profile use`/`list`/`remove`, `--profile`, `RLMESH_PROFILE`) that each fall back to the hosted platform URL, and credentials held in the OS keychain with a 0600 file fallback. `rlmesh org list` shows the organizations the account belongs to, marking the active one and each organization's registry namespace (or that it is not provisioned yet), and `rlmesh org switch` re-issues the profile's session against another one, failing loudly with the organization the platform kept active if the switch did not take.
- The CLI has no built-in identity provider: a platform whose `/v1/info` does not advertise `deviceAuthorizationEndpoint` and `tokenEndpoint` cannot be signed in to, the platform URL itself must be https (loopback excepted), and the token endpoint's host is pinned per profile at sign-in so a later `/v1/info` cannot redirect a stored refresh token. Identity (email, display name, organization) comes from the platform's `/v1/me`, never from provider-specific fields on the token response, and `rlmesh login` reports a platform that cannot confirm the identity.
- The CLI reuses its access token until a minute before the `exp` claim and refreshes only then, under a per-profile lock that re-reads the credential store after acquiring it, so `rlmesh token`, `rlmesh eval`, and every docker pull cost no identity-provider round trip and concurrent commands rotate the single-use refresh token once. A request the platform still rejects is retried once after a forced refresh.
- Managed-platform evaluations from the signed-in session: `rlmesh eval submit` (with `--preview` and `--wait`), `rlmesh eval list`, `rlmesh eval get`, `rlmesh eval wait`, and `rlmesh eval cancel`; `rlmesh token` prints a fresh access token for scripts; and `rlmesh.platform.Client` wraps the same routes from Python with `scenario_tasks()` to expand a scenario group into tasks.
- Build identity: `rlmesh.build_info()` returns the native core's build identity as a frozen `BuildInfo` (`version`, `protocol_generation`, `workflow_edition`, `workflow_edition_base`, `build_cohort`, `build_source`, `git`), and it and `rlmesh version` report the workflow edition of the native core: the sealed `YYYY.MM` name on a release build, a cohort-suffixed name (`YYYY.MM-<prerelease>` / `YYYY.MM-dev.<git>`) on prerelease and source builds. `rlmesh.__build__` is a deprecated alias of `build_info().workflow_edition`.
- Runtime hook events `ObservationEmittedEvent` and `ActionReceivedEvent` carry `raw_observation` / `raw_action` alongside the transformed payload, so hooks can record both the pre- and post-transform leaves per step.
- `StepCompletedEvent` and reset `ObservationEmittedEvent`s carry the env's per-step / reset `infos` map, so hooks see dense rewards, success flags, and task diagnostics as they happen rather than only `final_info` at episode end. Under `NEXT_STEP` autoreset the roll step's `infos` land on the new episode's first `ObservationEmittedEvent`, not on the old episode's `StepCompletedEvent`, and `episode_completed` is the last event a hook receives under an episode id: it fires at the roll, after the ended lane's post-end observation and the autoreset step's event, mirroring the model side (the last predict under an id precedes its `on_episode_end`).
- `StepCompletedEvent` carries per-lane `terminated` / `truncated` (env-reported or a runtime cap, known at the step itself) and a per-lane `autoreset_roll` mask (lanes roll independently under `NEXT_STEP`), so a hook learns how a step ended without waiting for `episode_completed`. The `rlmesh` crate re-exports `RuntimeHooks` and the per-episode events, and `ModelWorker::run_local_hooked_async` drives a local session with a hook implementation.
- The recorder captures on `Model.run` as well as on the session loop: image roles always, and the env's `render()` frame for a local env object; a vector env is refused unless `cameras=[]`.
- `EpisodeStartedEvent` and `EpisodeCompletedEvent` carry the episode's `seed` (`None` when the runtime sent no per-episode seed, e.g. an env-owned `NEXT_STEP` autoreset), so hooks can record it from episode start.
- Gym vector envs served with `num_envs > 1` report each autoreset episode's seed as `info["seed"]`, derived from the lane's last explicit seed, on both the registry `make_vec` path and the factory fan-out path.
- Decomposable endpoint timing: every env and model response carries the split of its `endpoint_total_ns` into wire decode, the implementation's own work, and wire encode, and a model response adds the wait before its predict handler ran (from arrival to handler entry, excluding decode) plus the slots the endpoint had taken. An env response adds its env-lock wait the same way. The runtime records them as the `endpoint.decode`, `endpoint.user`, `endpoint.encode`, `endpoint.queue`, and `predict.in_flight` metrics, so a slow step can be attributed to serialization, user code, or queueing without attaching a profiler. A peer that does not stamp them is unchanged. The phase-summary log is enabled by `RLMESH_PROFILE_PHASES`; `RLMESH_PROFILE` also enables it when it reads as a boolean, but it primarily names the CLI's credential profile.
- Driver telemetry records each loop iteration's wall clock (`runner.round`), bracketing the full predict -> step -> transform body, so subtracting the per-op rows yields the driver's own residual overhead.
- `RunResult.telemetry` surfaces the run's aggregated timing/size telemetry on the `Model.run` native loop: one `TelemetryRow` per measured op/metric series (count, avg, p50/p95/p99, unit), with `result.format_telemetry()` rendering the table, so where an eval's time went is a printed property of the result, not a log to capture.
- The adapter engine measures its own share of each predict (observation assembly plus action apply), reported as `adapter_ns` on the model response and recorded as the `predict.adapter` metric (a sub-span of `endpoint.user`, so the model's own forward is the difference), on both the served endpoint and the in-process `Model.run` path.
- The engine reports the per-episode adapter state it is holding (episodes with live frame-stack windows and the bytes they occupy, summed across routes), recorded per predict as the `held.episodes` and `held.bytes` metrics, so unbounded episode-state growth (or an eviction that stopped firing) is visible as a trend instead of an OOM.
- A `lane_skew_ns` scalar on the env response and a matching `lane.skew` metric, for a vector env that times its own lanes: its slowest lane minus its median lane, one series no matter how many lanes it runs, so one pathologically slow lane can show up in p95/p99 instead of merely blurring the `env.step` aggregate. No in-tree env stamps it yet (the built-in Gymnasium vectorization hands the lane loop to Gymnasium), so the series stays empty until a lane-timing env does; a Rust `VectorEnv` can compute it with `rlmesh::env::lane_skew_ns` over a scratch buffer of per-lane durations.
- Async inference: `RuntimeDriver::with_prefetch(model, lead)` predicts the next action chunk on a second model handle while the current chunk's replay frames execute, firing when `lead` frames remain. The prefetched chunk is conditioned on an observation up to `lead` steps stale, so runs reflect deployment-realistic async timing and are not comparable to the synchronous predict-then-step loop; a chunk prefetched across an episode boundary is discarded. On a route that negotiated observation history the prefetched request carries the rows buffered so far and predicts from an observation of its own, so every env step still reaches the model exactly once. Opt-in: `RuntimeDriver::with_prefetch(lead)` in Rust, `prefetch_lead=` (keyword-only, default 0) on `Model.run()` and `rlmesh.run()` in Python; a negative lead is a `ValueError`, and the session loop and a served handle refuse a non-zero lead rather than faking it.
- Negotiated workflow editions content-pinned to the sealed `2026.06` edition spec, exact-match `rlmesh-wire-v1` protocol generation, and a per-lane `NEXT_STEP` autoreset contract for vector environments.
- Batched leaf-slab encode and decode on the wire parallelizes past 64KB, speeding up large batched observation and action payloads.
- Image adapters run as typed kernels: the 180° rotation, the uint8 to float32 normalisation, the HWC to CHW transpose, and a pad to the frame's own size bypass the dtype-generic scalar codec, and a camera plan that ends in a normalised float32 CHW tensor (the shape every vision policy asks for) runs as one fused pass from the raw bytes. Output is byte-identical to the generic codec's; a 256×256×3 frame costs about a sixth of what the generic path does.
- A fused grouped predict assembles its groups' inputs and applies their returned action chunks in parallel, one route per thread, when every group names a distinct route and no plan runs a Python custom transform (otherwise it stays sequential); results keep request order and the per-route entry locks guard each route's buffers, so the `predict.adapter` share of a served model's handler time is not serial across a batch's lanes.
- `rlmesh whoami --json`, `rlmesh org list --json`, and `rlmesh profile list --json` for scripts, and `expiresAt` on `rlmesh token --json`, so nothing has to scrape the human output.
- `RLMESH_API_KEY` (with `RLMESH_PLATFORM_URL`) drives `rlmesh token`, `rlmesh eval`, and `rlmesh whoami` without a browser sign-in, matching `rlmesh.platform.Client`; `RLMESH_CONFIG_DIR`, `RLMESH_DATA_DIR`, and `RLMESH_KEYCHAIN=off` confine the CLI's files and keep the OS keychain out, for CI runners and containers.
- `rlmesh logout` asks the platform to end the session (`DELETE /v1/me/session`) before deleting the local credential, so the refresh token stops working server-side too; a platform without the route still signs out locally.
- A CLI reference page covering every command, exit code, environment variable, file, JSON output, and the contract a platform must serve to be driven by the CLI.
- `rlmesh check MODULE:CLASS`, `rlmesh check-image IMAGE`, and `rlmesh describe MODULE:CLASS [--label]`: pre-push checks that sort what they find into failed, warnings, and not checked, exiting 1 only on a failure. `check` runs the describe on a class and fails on a model without a `spec`, an env without `tags`, a spec that does not resolve, or an edition declaration the build cannot run, reporting an env that needs a GPU or assets to build as not checked; `check-image` reads `docker image inspect` and checks the `rlmesh.serve` command, `--env`, a baked `--address`, `EXPOSE 50051`, `linux/amd64`, the rlmesh labels, and whether the image's rlmesh shares a workflow edition with the target platform (`--platform-editions` / `--platform-version`), negotiated the way the runtime does; `describe --label` prints the `dev.rlmesh.describe` value for a custom-entrypoint image, to be run inside the built image (`docker run --rm --entrypoint rlmesh IMAGE describe ... --label`) since the envelope records the machine it ran on and a label generated off linux fails admission, which `check-image` reports too.
- The describe envelope's `runtime` block advertises the edition handshake under the wire's names: `protocol_generation`, `supported_workflow_editions`, and `preferred_workflow_edition`, and `rlmesh.build_info().supported_workflow_editions` lists the editions a build can drive.
- `python -m rlmesh.serve` warns at startup when the served model declares no `spec`: the managed probe cannot synthesize inputs for it.
