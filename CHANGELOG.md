# Changelog

All notable changes to RLMesh are documented here. This changelog tracks the `rlmesh` Python package on PyPI. The Rust crates are internal implementation detail and currently carry no separate user stability promise.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/2.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

## [0.1.0] - 2026-09-23

RLMesh connects models to environments across process, dependency, and machine boundaries with a Gymnasium-style API. RLMesh 0.1.0 ships the sealed `2026.06` edition and retains `rlmesh-wire-v1`. Declare the edition a model or environment was authored against to keep its behavior across package upgrades. The runtime selects a shared edition and refuses interactions a peer cannot express; see the compatibility policy for the contract and its current test coverage.

### Added

- `Model.from_config(**config)`: build an authored `Model` subclass with `load(**config)`, the keywords validated against `load`'s signature and the declared `params` (`ParamError` before any weights load), `load` run exactly once; the served binding (`RLMESH_MAKE_KWARGS`) takes the same path. A framework base class with no predict corner of its own refuses it.
- Sticky workflow-edition declarations: a participant writes down the edition it was authored against and keeps it across rlmesh upgrades (the NixOS `stateVersion` model). Declare it, highest surface first, with `run(workflow_edition=)` / `session(workflow_edition=)`, `RLMESH_WORKFLOW_EDITION`, `ServeOptions(workflow_edition=)` / `--workflow-edition`, `EnvFactory.workflow_edition` / `Model.workflow_edition`, or `[tool.rlmesh] workflow_edition` in `pyproject.toml`; public `rlmesh.run()` and `rlmesh.session()` accept it for served models and the random baseline too. An empty `RLMESH_WORKFLOW_EDITION` declares nothing deliberately and ends resolution there, clearing a lower-priority `ServeOptions` declaration, and declaring nothing at all floats to this build's newest edition; an authored `EnvFactory`/`Model` subclass or a served participant says so once per process at the caller's line (`rlmesh.WorkflowEditionWarning`), while an ad hoc callable in a local run floats quietly. An edition this build cannot run a session at is refused where it was written, not at the first connection.
- WANT/CAN edition negotiation: every handshake carries the declaration as `preferred_workflow_edition` (an additive `rlmesh-wire-v1` field on `HandshakeRequest` and `HandshakeResponse` that a peer may omit) next to the editions the build can drive, and the runtime runs the session at the highest edition all of env, model, and runtime support that every declaration admits (a bare base admits every cohort of itself; a cohort spelling uses the full edition ordering as its ceiling), refusing cleanly before any Join stream opens, naming each tier's declaration and supported set, when there is none. A served-model session declares on its model leg the same edition its env leg does, and hands the model client the env's real handshake offer, so a refusal never attributes one tier's value to another.
- The runtime pins the env to the session edition: `ConfigureEnvRequest.selected_workflow_edition` is sent as the first Join message and acked before the first Reset (a served-model session pins both legs to the three-way floor); a served env records the pin and reports conformance warnings under that edition's reserved key, falling back to its current edition for runtimes that send none.
- The editions a build can drive are its retained list, generated from `rlmesh.toml`'s `supported_editions` and offered and accepted from that one source, and the negotiated edition is a typed `Edition` in the runtime with a per-edition defaults table, so a sealed edition's behavior is read from its row rather than from scattered constants.
- `rlmesh.current_workflow_edition()` reports the bare `YYYY.MM` edition this build runs at (`"2026.06"`), the same on a release and on a prerelease or source build, and is the value to paste into a declaration; `rlmesh.build_info().workflow_edition` reports the build's exact spelling, which is also accepted as a declaration when you mean to pin to one moving build.
- `RemoteEnv.selected_workflow_edition`, `RemoteVectorEnv.selected_workflow_edition`, `SandboxEnv.selected_workflow_edition`, `SandboxVectorEnv.selected_workflow_edition`, and `Session.selected_workflow_edition` report the edition a connection or session settled on, in the spelling the peers agreed; `workflow_edition` everywhere means what this peer declares.
- A cross-version matrix, `mise run test:crossver`, drives this tree against the pinned published wheel on both legs in both directions and asserts the handshake, the negotiated edition, and the refusal of an unknown edition and a forged protocol generation on each build; cells that need a second sealed edition are listed as pending rather than dropped.
- Serve Gymnasium-style environments and drive them with `reset`, `step`, `render`, and `close` over local or remote gRPC transports: `EnvServer`, `RemoteEnv`, `RemoteVectorEnv`, and `python -m rlmesh.serve` as a universal container entrypoint.
- A blocking `EnvServer.serve()` (what `python -m rlmesh.serve` runs) keeps the env on the calling thread: `reset`/`step`/`render`/`close` run on the thread that built the env, usually the main thread, for a scalar env and for a lockstep vector env alike, while the gRPC server runs on a helper thread. Simulators that only work from the thread that created them, such as Isaac Sim, need no thread-hopping wrapper. Ctrl-C drains and closes the env first and then raises `KeyboardInterrupt` from `serve()`, never inside an env call; a second Ctrl-C interrupts an env call that will not return (Python code; a call stuck inside a native library cannot be preempted). `EnvServer.wait()` responds to Ctrl-C.
- `RLMESH_ALLOW_REMOTE_SHUTDOWN=1` opts a served environment into honoring the remote `shutdown` RPC, so an orchestrator that queues env workloads can tell a finished worker to exit and free its slot. The variable can only enable remote shutdown, never disable a programmatic `allow_remote_shutdown=True`.
- A vectorized env with `num_envs == 1` serves as the scalar env it is. Each value loses its batch axis (lane 0 of the observation and of the `info` under gymnasium's `key`/`_key` convention), actions gain one, and the runtime owns resets, so per-episode `seeds`, `trial_index` and `max_episode_steps` apply. A batched simulator configured with one lane, such as Isaac Lab at `num_envs=1`, needs no scalar rewrite. A one-lane env with `SAME_STEP` autoreset is refused, because its terminal observation is already the next episode's first.
- Lane serving: `EnvServer([env, ...])` (or `RLMESH_NUM_ENVS=N` on a prebuilt image) hosts N independent copies of a scalar env on one endpoint. Each lane runs on its own thread, and every lane must carry the same env contract (spaces, metadata, tags) as lane 0 or the server fails at construction. The endpoint advertises `subset_step`, `StepRequest.env_indices` and partial-width `StepResponse`s are honored, and the runtime driver treats each lane as its own reset/predict/step loop over one multiplexed Join stream, so lanes reset and step at their own pace while every episode's seed and index come from a route-global slot counter; lanes waiting for a prediction share one grouped predict on a model with a batched corner (`PredictScheduler`, one fused forward, `RuntimeModel::fuses_predicts`) and otherwise each predict on their own, applied as it lands, so a slow prediction on one lane never holds another. A served or managed model receives one predict per lane and batches on its own side. A single env is the one-lane case of the same server.
- Evaluate models locally, against a remote server, or inside a sandbox: `Model`, `RemoteModel`, and `SandboxModel`, with `run()` for whole evals and `session()`/`Session` for manual `reset`/`predict`/`step` control.
- `rlmesh.run()` and `rlmesh.session()` take a `Model` (an instance or subclass class) or a served handle and refuse a bare predict callable or policy object with a `TypeError` naming the fix: the library never picks a framework, so wrap it in `rlmesh.numpy.Model(fn)` / `rlmesh.torch.Model(fn)` / `rlmesh.jax.Model(fn)`, or `rlmesh.Model(fn)` for raw values. `python -m rlmesh.serve module:Policy` serves a policy object as a NumPy model. The live viewer belongs to `Model.session`, `Model.run` does not take `view`, and the module-level `run()` forwards it only for a served handle.
- A model instance passed to `run()` / `session()` is borrowed: neither the run nor closing the session calls its `close()` (a model built from a class you passed is closed with the call or session), and a caller's env is left open unless `close_env=True`; an env built from an `EnvFactory` is closed when the run or session ends, and also when adapter resolution or loopback setup fails. `Model.close()` drops the cached native worker, so a model that ran natively is collectable after close. `EnvServer(..., close_env_on_shutdown=False)` serves an env without closing it at shutdown, which the loopback server `Model.run` stands up uses.
- Tag-driven IO adapters that resolve environment tags against model specs at runtime. Environments tag what they emit (`ImageTag`, `StateTag`, `TextTag`, `Split`); models declare what they consume (`Image`, `State`, `Text`, `Concat`) and produce (`Action`, `Actuator`). Conversions cover rotation accept-sets, custom rotation encodings (`CustomEncoding`, published as a `module:callable` reference or a `<local>` marker for an in-process callable, with execution staying host-side), image `fit` and `normalize` ranges, channel validation, optional cameras, frame stacking, per-actuator `clip`/`scale`/`invert`/`threshold`, and role-less actuators; `adapter.explain()` prints the chosen transforms and `adapter.advisories()` surfaces severity-tiered data-loss notes (`info` for benign hints, `caution` when the adapter substituted or fabricated model-visible data). Rotation conversions out of a matrix (`rot6d`, `euler_xyz`, any post-rotated source) to `axis_angle` go through the quaternion, so they stay exact near 180 degrees and for rotations as small as 1e-4 rad.
- `Field` and `ConcatPart` carry unknown keys through a relay hop; the publish gate rejects them by name, and a typo on a split field surfaces there and as a read taint.
- Roles `ACTION_EEF_POS`, `ACTION_EEF_ROT`, `ACTION_JOINT_POS`, and `IMAGE_WRIST`, so an end-effector pose action, a joint command, and a wrist camera bind by role instead of by ad-hoc name; a second arm or camera is the same role under a `part`. A model-side ad-hoc role the env does not answer is an `info` advisory, and a fabricated fill on an optional roled action is a `caution`.
- Per-predict context for stochastic and stateful models: the trailing `context` a predict corner declares carries `predict_index` (the re-plan ordinal within the episode), `predict_seed` (a reproducible mix of the episode seed and that ordinal, also computed by `rlmesh.predict_seed(episode_seed, predict_index)`), and a per-episode `state` dict that lives as long as the episode does. Batched corners receive one `PredictContext` per row (`BatchPredictContext`), and the Rust `PredictFn::predict_batch` and `predict_chunk_batch` receive row-aligned `EpisodeInfo`. The `Model` hook that fires when an episode ends, `on_episode_end(self, episode_id="")`, drops one episode's state and shares its name with the constructor callback and the runtime; a wrapped policy object's `reset()` is picked up as that hook. `RLMESH_EPISODE_CAPACITY` (default 65,536) caps the SDK's live episode store: a new episode past the cap is refused with an error naming the variable, and a live episode's state is never evicted, its prediction ordinal reset, or its end callback fired early to make room.
- Trial ordinals for environments: `EnvFactory.reset_options = ("trial_index",)` opts an env into receiving the runtime's 0-based trial ordinal as `reset(options={"trial_index": k})`, read with `rlmesh.trial_index(options)`. An env that does not declare the key never sees it. The runtime mints the ordinal for every episode it starts, from `RuntimeSessionSpec.trial_index_base` (0 by default), and reports it on episode events, summaries, and `EpisodeResult.trial` whether or not the env asked for it; `run(trial_index_base=)` / `Session.run(trial_index_base=)` pick the first ordinal, so a local eval walks the same states as a platform shard. Under `NEXT_STEP` autoreset no ordinal is minted and a non-zero base is rejected. A reset that restarts several lanes of a lane-served env delivers each lane its own ordinal, so `rlmesh.trial_index(options)` reads an integer on every lane. The encoding is one Rust implementation shared by the driver and external probers, exported as `rlmesh_runtime::{reset_options_for, declares_reset_option, TRIAL_INDEX_OPTION}`, so a second caller cannot drift from what the driver sends.
- Declared chunk length: a model with a fixed chunk sets `native_chunk = K`. The runtime then refuses an `execution_horizon` above K when the adapter resolves and fails a predict whose chunk is not exactly K long, instead of quietly re-planning every K steps of an H-step plan. Undeclared, the contract stays elastic: a short chunk replays as far as it goes and warns once. The horizon is bounded at 1024.
- Image resample kernels `bicubic_aa`, `lanczos3_aa`, and `area` alongside `bilinear` and `bilinear_aa`, each anchored to Pillow and OpenCV within one 8-bit step, including the clamp Pillow applies between its two passes.
- Image spec fields `crop`, `crop_area`, `crop_mode`, `channel_order`, `jpeg_quality`, `render`, `offsets`, `stride`, and `stack_pad`, all keyword-only after `stack` and omitted from a published spec when default. `render` asserts the camera resolution the model was trained against rather than requesting one, and a bound camera that disagrees is a `RenderMismatch` at resolve. The jpeg round-trip is baseline 4:2:0 through `jpeg-encoder`, forced explicitly because that crate switches to 4:4:4 above quality 90; the IJG acknowledgment ships in the wheel notices.
- Frame windows in the core engine: `Adapter.observe`, `history_keys`, and `history_windows` keep a stacked model's window per episode, and chunk replay ticks it on every replayed step, so the model sees the same payloads at every execution horizon. Windows are keyed by structured placement, so a dotted `"camera.rgb"` input and a nested `{"camera": {"rgb": ...}}` input stack their own frames and two cameras never mix histories.
- Observation history on the wire, so a frame-stacked model works with action chunking on the native and served paths. The runtime declares on `ResolveAdapter` that it delivers history (`delivers_history`), a stacked route answers the inputs that hold a window (`ResolveAdapterResponse.history`), and each later `Predict` carries the env steps the runtime executed from a replayed chunk as `PredictRequest.history` rows, oldest first, stamped with a per-group `step` counter that the engine holds to consecutive values per episode (a gap or repeat fails the predict rather than stacking a wrong window). The four proto fields are additive; a runtime that never offers history and a model that never answers it exchange the same bytes as without them. `Model.run`, a served model under the Rust runtime driver, and `RemoteModel` all deliver it, and the Python session ticks its window locally. A served model advertises `rlmesh.model.observation_history.v1`, and `RemoteModel` offers `delivers_history` only to a served model that advertised it at handshake (`ModelClient::server_ingests_history`), so a model without the capability receives no history rows. A frame-stacked adapter at `execution_horizon > 1` on the native engine is refused only when the runtime did not offer observation history, and the error says so. The `history.rows` telemetry metric counts rows per predict.
- The frame-window budget (`RLMESH_FRAME_HISTORY_LIMIT_BYTES`, default 2 GiB) bounds the whole model endpoint: a predict that would open windows for a new lane is refused while every route's live lanes, charged at their full window size, would exceed it. Routes with no stacked input are never charged. The served resolve, which names no lanes, validates one lane per route and refuses a stacked route whose windows would exceed the budget.
- State geometry: a `CustomEncoding` can sit at any offset of a concatenated state and every piece records its width, which apply asserts. `Constant(dim=, fill=)` parts and `State(fill=)` declare a filler that never reads as fabricated data; `post_rotate` (with an exact `Rotation.from_matrix`), `scale`, and `offset` transform a piece after decoding.
- Body parts: `part=` on `ImageTag`, `StateTag`, `Field`, `Actuator`, `Image`, and `State`/`Concat` parts names where a role repeats on a body, matched as an identity key. A part is any identifier the env and the model agree on exactly; `LEFT_ARM`, `RIGHT_ARM`, `HEAD`, `TORSO`, `BASE`, `LEFT_LEG`, and `RIGHT_LEG` (`adapt.PARTS`) are the suggested spellings, not a registry. A model that names a part binds only that leaf; one that names none binds the env's only leaf of the role under any part with an `info`, and fails naming the parts when there are several. Duplicate detection in `Split`, `Action`, and `EnvTags` is keyed by `(role, part)`, so one `action/joint_pos` per arm is a valid layout. The kind prefixes `image/`, `proprio/`, `text/`, `action/`, and `command/` are a closed set enforced at authoring and resolve. A role with no `/` is ad-hoc and binds on exact-string agreement, and `x/` is the escape prefix for a whole role that is deliberately outside the registry. `explain()` shows a bound part as a `#part` suffix.
- Axis labels: `labels=` on `StateTag`, `Field`, `Actuator`, and `State`/`Concat` parts names the joints of a vector in that side's own order, and the resolver aligns the two sides by name, so a checkpoint trained in Isaac Lab joint order resolves against a Unitree SDK-order environment as a derived permutation (`explain()` prints `perm[3,4,5,0,1,2,9,10,11,6,7,8]`). The two tuples must name the same joints: a labeled model against an unlabeled env, or a label either side lacks, is a `LabelMismatch`, also on an `optional` model part. Labels are the env's own joint names, written from its configuration, at least one and none repeated; omitting them accepts positional order with no name check. `scale` and `offset` on a `State` part and an `Actuator` (which also takes `offset`) accept a per-axis sequence in label order, serialized as `axis_scale`/`axis_offset`; `explain()` prints them as `label:value`.
- Body roles and projected gravity: `BASE_ANG_VEL` (`proprio/base_ang_vel`), `BASE_ROT` (`proprio/base_rot`) and `COMMAND_BASE_VEL` (`command/base_vel`, the first role under the `command/` kind) register the floating base's gyro, orientation and velocity setpoint, all framed. A model reads the orientation as projected gravity with `encoding="gravity_xyz"` (`R_world_from_base^T · (0, 0, -1)`, 3 wide): any rotation encoding converts into it and nothing converts out of it, so an env publishing `gravity_xyz` binds only a model that reads it, and a `post_rotate` or an actuator naming it is a codec error. `provenance=` on `StateTag`, `Field` and `State`/`Concat` parts (`"sensed"`, `"estimated"`, `"privileged"`; a model may accept a sequence) says where a state leaf's numbers come from and follows the frame rules, with a disagreement a `ProvenanceMismatch`; it is part of the env leaf's identity, so a simulator may publish one role as its truth and as its estimate, and a model that pins none against both is `Ambiguous`. `State`/`Concat` take a container `clip=(low, high)` applied to the assembled vector before `pad_to`. `explain()` prints `#sensed` and `clip[-100.0,100.0]`.
- End-effector wrench: `EEF_WRENCH` (`proprio/eef_wrench`) registers the six-axis force/torque a wrist sensor reads, force first, 6 wide and framed; the frame vocabulary includes `tool`, the frame attached to the end effector, so a wrist-mounted sensor (`frame="tool"`, `provenance="sensed"`) and a controller's estimate (`frame="robot_base"`, `provenance="estimated"`) are different leaves of one role and a model binds the one it was trained on. Its `labels` (`fx`..`tz`) name its own axes.
- A `model.reset_adapter` telemetry row: the runtime driver records `rpc.total` for every eviction RPC it awaits, so the time a model spends ending episodes shows up in the runner's windows next to `model.predict` rather than only in the gap between episodes. Eviction is bounded by the predict timeout in the loop and by the close timeout at teardown, and is cancellation-aware; an unanswered eviction is logged and abandoned rather than holding the route. A route that ends mid-episode ends every episode it still holds on the model side before releasing, so a persistent endpoint keeps no failed run's Python episode state.
- Previous action: `adapt.Previous(role, part=None, fill=0.0)`, a `State`/`Concat` part with `source="action"`, reads the model's own output actuator of the same role and part back as the raw action executed at the previous step, in model order and before the actuator's affine, with `fill` before an episode's first action. It binds the spec's own actuator (none is a `MissingRole`), `labels` reorder from the actuator's labels, and an env observation tagged under `action/` is an `ActionRoleOnObservation` join error. Every executed action is recorded under its step at every replay site (the served engine per chunk frame and lane, `RemoteModel`'s replay through the history rows, the Python session and `Adapter.transform_action` with `Adapter.observe` counting a replayed step), an observation whose previous step recorded none fails loudly, and a route with the part negotiates observation history like a stacked one, so the runtime delivers replayed steps and a prefetched predict carries the rows buffered so far. `explain()` prints `previous action/joint_pos (fill 0.0)`.
- Coordinate frames: `frame=` on `StateTag`, `Field`, `State`, and `Actuator`, and `reference="current"` or `"target"` on delta actuators. A delta actuator (`action/delta_eef_*`) may declare the `frame` its axes are expressed in next to its `reference`. A disagreement is one `FrameMismatch` code on either axis, a model that declares a frame the env leaves unstated is a `caution`, and the spec gate can require frames on both sides. Spec descriptions render them as `@robot_base` and `~target` suffixes.
- Env contract branches: `EnvFactory.tag_params` names the make parameters that change an env's tags, `tags_for(**params)` returns the tags for one binding, and `describe()` lists every branch under `env_contracts`. The make wrapper stamps the chosen branch and the declared reset options into the env's metadata, and `EnvServer` asserts the branch the platform expects when `RLMESH_EXPECTED_ENV_BRANCH` is set.
- Action chunking and batched prediction in the runtime. Implement the most general of four corners and the runtime derives the rest: `predict`, `predict_chunk`, `predict_batch`, `predict_chunk_batch`, active in local `run()` evals and on the served wire path alike. The runtime owns chunk replay and the execution horizon, so one action still reaches the environment per step. Any unbatched corner may accept a trailing `context` argument carrying the episode's `episode_id` and `episode_seed`, locally and across the wire. Grouped predict requests spanning several environments fuse into one batched forward pass when the model's batched corner is the corner a direct predict would run, so grouping never changes model behavior; a fused failure keeps the model error's recoverable flag and annotates each group with its own input signature. `Model.allow_fusion = False` opts out a batched forward that assumes fixed-size, single-environment batches, such as a shape-pinned `jit` trace or per-batch statistics; grouped predicts then run one route at a time.
- Seeded evals: `run(seeds=[...])` gives each episode its own seed (and sets the episode count), threading it to the environment's `reset(seed=)` and to the model as episode context; `EpisodeResult.seed` records what each episode ran with.
- `episodes=` on `run()`, `Model.run`, and `Session.run` is exact: one episode by default, `len(seeds)` when only seeds are given, and the two must agree when both are (no unseeded tail); `episodes=0` runs nothing and a negative count is refused. On a vectorized env the budget bounds episode starts, so `result.num_episodes == episodes` on every path; a lockstep lane the env rolls past the budget under `NEXT_STEP` autoreset runs unscored (never counted, reported, or seen by hooks). Seeds and per-episode caps on an autoresetting vector env are refused before any episode starts.
- `RunResult.success_rate` counts only the env-reported task outcome, read from `is_success`, `success`, or `task_success` in `info`, in that order, and is `float | None`: `None` when the run is empty or any episode lacks the signal, never a rate inferred from `terminated`. A Gymnasium vector env with `NEXT_STEP` autoreset reports each lane's terminal outcome from the per-lane info arrays, and a runtime-imposed step or time cap keeps the last step's info, so `success_rate` on a vector or capped run reports the same outcome a scalar run does. The recorder's exported `successRate` follows the same rule and may be null, and the viewer's HUD shows `done` for a terminal state with no reported outcome.
- Startup phase marks: `python -m rlmesh.serve` records when it reached `imports`, `model` or `env`, and `listen`, in milliseconds since the process started (plus `process`, the interpreter and `rlmesh` import time before the entrypoint ran, from `/proc` on Linux), prints them on the serving line, and stamps them on the handshake as `PeerInfo.extra` keys `rlmesh.startup.<phase>_ms` beside the build keys. `rlmesh.serve.startup_marks()` returns the marks reached so far and `register_python_peer_info(extra=...)` exposes the extra map the Rust side merges.
- Run observability: pass `hooks=RunHooks(...)` to `run()` / `Model.run` / `Session.run` for per-step `StepEvent`s (action, reward, the step's own terminal flags, timing, lazy role-addressed reads) and episode/run boundaries, in the same order on the native loop and the session loop; `on_run_start` receives a `RunContext` (the `Session` itself, or the native run's context) for role reads and frame discovery. Cap episodes with `max_episode_steps`/`max_episode_seconds`, and read per-episode timing off `EpisodeResult`. `instruction=` works on `run()` too. Step telemetry records hook transform round-trips, so time spent in `RunHooks` transforms is visible per step.
- `EpisodeResult.predict_ms` / `step_ms` are that episode's own per-step means on every path (`float | None`, `None` for an episode that ended before its first step); the runtime times every predict and env step it issues and reports them per episode, so the record `on_episode_end` receives equals the one in the result, and `Recorder.capture()` and `Recorder.add(result)` record the same metrics. `StepEvent.predict_ms` is the predict that landed since the previous step (zero for a chunk-replay step; under prefetch, the next chunk's), the same definition the per-episode mean is built from.
- Read-only observation inspection: `Session.reader()`/`Session.read()` extract any role from a raw observation through the model's adapter, and `Session.observation_roles()`/`EnvTags.observation_roles` list the roles an env declares. An adapted `Session.predict` returns the action in the env's declared Box shape and dtype and refuses a value an integer Box cannot hold rather than truncating or wrapping it.
- PyTorch and JAX end to end: environments served with framework tensors (`EnvServer(env, framework="torch", device="cuda:0")`), `rlmesh.torch` and `rlmesh.jax` factory, model, and sandbox classes, and DLPack-native `Tensor` transport with zero-copy NumPy, Torch, and JAX backends. `Model.run(factory)` and an adapted `Model.session(factory)` on a `rlmesh.torch.EnvFactory` hand the env torch actions and accept its torch observations.
- Isolated sandboxes: rebuild an environment identically in a container (`SandboxEnv` with grouped `SandboxBuild`/`SandboxRuntime` config, including `SandboxRuntime.user` for writable bind mounts) or run a prebuilt image. A bare tagless image name resolves against local Docker images and never silently falls into a source build.
- An experimental C ABI: `crates/rlmesh-capi` is a C11 header plus a header-only C++17 wrapper that lets a C or C++ program implement `predict` and have the runtime drive it against an environment (`rlmesh_model_run_local`) or serve it as a gRPC model service. Observations reach C already decoded, one value handle per sub-env, and `RlmeshEpisode` carries each episode row's `predict_index` and `predict_seed` (the same mix as `rlmesh.predict_seed`; `seeded` says whether the seed is meaningful); actions return as owned handles Rust validates against the route's action space, and run options take a `trial_index_base`. `RlmeshServeOptions.workflow_edition` takes the same edition declaration as the Python surfaces. This is **ABI version 4** (`RLMESH_ABI_VERSION`, `rlmesh_abi_check()`, and the versioned SONAME). Built from source with `mise run test:cxx`; the crate is not published to crates.io yet.
- `policy:check` pins the additive-forever wire-v1 contract in `rlmesh.toml [wire]`: the 256 MiB gRPC message cap, every proto enum's value count, and the `MetaValue.kind` / `SpaceSpec.spec` oneof arm counts must be updated deliberately in the same change; the emitter-side house rule is documented under "Additive-forever rules" in the editions guide.
- Docs: the compatibility page states the sticky edition guarantee, the WANT/CAN negotiation, the runtime-as-interpreter and dual-stack rules, the 256 MiB cap and retained-edition contract, the cross-version matrix, and a release-anchored roadmap.
- `rlmesh-proto` ships its retained workflow-edition list (`supported_editions.txt`, current edition first) so a crate built from crates.io offers every retained edition, not just its own; the build fails if the file drifts from `rlmesh.toml`, `bump_version.py --sync-editions` regenerates it, and `policy:check` enforces it.
- The runtime records each served peer's ceiling (the highest edition both implement, the wire-v1 dtypes, capabilities, and the message cap) on `RuntimeSessionSpec` as `env_ceiling` / `model_ceiling`, exposed by `RemoteModel::ceiling()`.
- A `RelayPolicy` seam (`RefusingRelayPolicy` by default, `RuntimeDriver::with_relay_policy`) checks the env contract, observations, and actions against the target leg's ceiling; a converting policy can rewrite leaves and attach an advisory, which reaches `RuntimeReport.advisories`, a `relay_advisory` hook, and `RunResult.advisories` in Python. `Advisory` lives in `rlmesh-spaces` and is re-exported from `rlmesh-adapters`.
- Declared construction parameters: `EnvFactory.params = ParamSpec(Param(...))` validates `make()` arguments, `enumerate_variants()` lists a factory's concrete sub-environments, and `describe()`/`describe_json()`/`python -m rlmesh._describe` emit a JSON metadata envelope without loading a model (an env's spaces are read off one representative instance); a model envelope reports the predict `corners` the class actually defines, introspected from the code that ships rather than declared. `python -m rlmesh._describe --check IMAGE` validates a built image's rlmesh labels locally, the way the platform probe will, before pushing, and exits nonzero on a failure so it can gate a push in CI: packaged checkpoint declarations must be well-formed (DNS-label names, a `uri` per entry, a single default), a present `dev.rlmesh.describe` label gets the same class-level checks as `rlmesh check`, and a missing one is reported as not checked, since the platform reads describe off the `rlmesh.serve` handshake.
- A live debug viewer: pass `view="terminal"`, `view="http:9000"`, or `view="both"` to `session()` (or to the module-level `run()` for a served handle), or configure `rlmesh.View(...)`. It is best-effort and never breaks an eval.
- Record eval runs to a portable bundle for upload: `rlmesh.Recorder` accumulates per-episode metrics with `add()` (from any `RunResult`) or `capture()` (live `RunHooks` on the session path) and writes an `rlmesh.result.v1` folder or zip with `export()`. On the session path it records the same sources the live viewer offers (the env's `render()` frame plus every declared image role), each to its own AV1 `.mp4`, encoded in process (pure Rust, no ffmpeg or extra dependency; `Recorder(fps=, quality=)` set playback rate and size/fidelity); env-produced video files are carried into the bundle by path. Capture is best-effort: a source that fails to read or encode is dropped with a warning and never aborts the eval.
- `rlmesh.sanitize_metadata()` coerces a third-party sim's rich `info` objects into wire-safe metadata, and connection failures name the address and the likely fix.
- Client timeouts: `RemoteEnv`, `RemoteVectorEnv`, and `RemoteModel` accept `connect_timeout_seconds` and `request_timeout_seconds`, so a hung peer fails with a `TimeoutError` instead of blocking forever.
- Fail-loud argument handling: a parameter that cannot be honored (`instruction=` on a served model, an unknown `vectorization_mode`, a conflicting CLI flag) raises with a directive error instead of being silently ignored.
- Self-explanatory predict failures: when a model's `predict` raises, the error is annotated with the adapter-assembled input signature (key → dtype/shape), both in local `run()` loops and across the wire from a served model, so a shape mismatch names what the model was actually handed.
- Managed-platform sign-in from the CLI: `rlmesh login` (RFC 8628 device flow), `rlmesh logout`, `rlmesh whoami`, and `rlmesh registry login` (registers the bundled `docker-credential-rlmesh` helper, so docker fetches a fresh short-lived token per pull/push, and hands the registry host to the profile that logged in most recently), with named profiles (`rlmesh profile use`/`list`/`remove`, `--profile`, `RLMESH_PROFILE`) that each fall back to the hosted platform URL, and credentials held in the OS keychain with a 0600 file fallback. `rlmesh org list` shows the organizations the account belongs to, marking the active one and each organization's registry namespace (or that it is not provisioned yet), and `rlmesh org switch` re-issues the profile's session against another one, failing loudly with the organization the platform kept active if the switch did not take.
- The CLI has no built-in identity provider: a platform whose `/v1/info` does not advertise `deviceAuthorizationEndpoint` and `tokenEndpoint` cannot be signed in to, the platform URL itself must be https (loopback excepted), and the token endpoint's host is pinned per profile at sign-in so a later `/v1/info` cannot redirect a stored refresh token. Identity (email, display name, organization) comes from the platform's `/v1/me`, never from provider-specific fields on the token response, and `rlmesh login` reports a platform that cannot confirm the identity.
- The CLI reuses its access token until a minute before the `exp` claim and refreshes only then, under a per-profile lock that re-reads the credential store after acquiring it, so `rlmesh token`, `rlmesh eval`, and every docker pull cost no identity-provider round trip and concurrent commands rotate the single-use refresh token once. A request the platform still rejects is retried once after a forced refresh.
- Managed-platform evaluations from the signed-in session: `rlmesh eval submit` (with `--preview` and `--wait`), `rlmesh eval list`, `rlmesh eval get`, `rlmesh eval wait`, and `rlmesh eval cancel`; `rlmesh token` prints a fresh access token for scripts; and `rlmesh.platform.Client` wraps the same routes from Python with `scenario_tasks()` to expand a scenario group into tasks.
- Build identity: `rlmesh.build_info()` returns the native core's build identity as a frozen `BuildInfo` (`version`, `protocol_generation`, `workflow_edition`, `workflow_edition_base`, `build_cohort`, `build_source`, `git`), and it and `rlmesh version` report the workflow edition of the native core: the sealed `YYYY.MM` name on a release build, a cohort-suffixed name (`YYYY.MM-<prerelease>` / `YYYY.MM-dev.<git>`) on prerelease and source builds. `rlmesh.__build__` is a deprecated alias of `build_info().workflow_edition`.
- Runtime hook events `ObservationEmittedEvent` and `ActionReceivedEvent` carry `raw_observation` / `raw_action` alongside the transformed payload, so hooks can record both the pre- and post-transform leaves per step.
- `StepCompletedEvent` and reset `ObservationEmittedEvent`s carry the env's per-step / reset `infos` map, so hooks see dense rewards, success flags, and task diagnostics as they happen rather than only `final_info` at episode end. Under `NEXT_STEP` autoreset the roll step's `infos` land on the new episode's first `ObservationEmittedEvent`, not on the old episode's `StepCompletedEvent`, and `episode_completed` is the last event a hook receives under an episode id: it fires at the roll, after the ended lane's post-end observation and the autoreset step's event, mirroring the model side (the last predict under an id precedes its `on_episode_end`).
- `StepCompletedEvent` carries per-lane `terminated` / `truncated` (env-reported or a runtime cap, known at the step itself) and a per-lane `autoreset_roll` mask (lanes roll independently under `NEXT_STEP`), so a hook learns how a step ended without waiting for `episode_completed`. The `rlmesh` crate re-exports `RuntimeHooks` and the per-episode events, and `ModelWorker::run_local_hooked_async` drives a local session with a hook implementation.
- The recorder captures on `Model.run` as well as on the session loop: image roles always, and the env's `render()` frame for a local env object; a vector env is refused unless `cameras=[]`.
- `EpisodeStartedEvent` and `EpisodeCompletedEvent` carry the episode's `seed` (`None` when the runtime sent no per-episode seed, e.g. an env-owned `NEXT_STEP` autoreset), so hooks can record it from episode start.
- Gym vector envs served with `num_envs > 1` report each autoreset episode's seed as `info["seed"]`, derived from the lane's last explicit seed, on both the registry `make_vec` path and the factory fan-out path.
- Decomposable endpoint timing: every env and model response carries the split of its `endpoint_total_ns` into wire decode, the implementation's own work, and wire encode, and a model response adds the wait before its predict handler ran (from arrival to handler entry, excluding decode) plus the slots the endpoint had taken. An env response adds its env-lock wait the same way. The runtime records them as the `endpoint.decode`, `endpoint.user`, `endpoint.encode`, `endpoint.queue`, and `predict.in_flight` metrics, so a slow step can be attributed to serialization, user code, or queueing without attaching a profiler. A peer that does not stamp them is unchanged. The phase-summary log is enabled by `RLMESH_PROFILE_PHASES`; `RLMESH_PROFILE` also enables it when it reads as a boolean, but it primarily names the CLI's credential profile.
- Driver telemetry records each loop iteration's wall clock (`runner.round`), bracketing the full predict -> step -> transform body, so subtracting the per-op rows yields the driver's own residual overhead.
- `RunResult.telemetry` surfaces the run's aggregated timing/size telemetry on the `Model.run` native loop: one `TelemetryRow` per measured op/metric series (count, avg, p50/p95/p99, unit), with `result.format_telemetry()` rendering the table, so where an eval's time went is a printed property of the result, not a log to capture.
- The adapter engine measures its own share of each predict (observation assembly plus action apply), reported as `adapter_ns` on the model response and recorded as the `predict.adapter` metric (a sub-span of `endpoint.user`, so the model's own forward is the difference), on both the served endpoint and the in-process `Model.run` path.
- The engine reports the per-episode adapter state it is holding (episodes with live frame-stack windows and the bytes they occupy, summed across routes), recorded per predict as the `held.episodes` and `held.bytes` metrics, so unbounded episode-state growth (or an eviction that stopped firing) is visible as a trend instead of an OOM.
- A `lane_skew_ns` scalar on the env response and a matching `lane.skew` metric, for a vector env that times its own lanes: its slowest lane minus its median lane, one series no matter how many lanes it runs, so one pathologically slow lane can show up in p95/p99 instead of merely blurring the `env.step` aggregate. No in-tree env stamps it yet (the built-in Gymnasium vectorization hands the lane loop to Gymnasium), so the series stays empty until a lane-timing env does; a Rust `VectorEnv` can compute it with `rlmesh::env::lane_skew_ns` over a scratch buffer of per-lane durations.
- Async inference: `RuntimeDriver::with_prefetch(model, lead)` predicts the next action chunk on a second model handle while the current chunk's replay frames execute, firing when `lead` frames remain. The prefetched chunk is conditioned on an observation up to `lead` steps stale, so runs reflect deployment-realistic async timing and are not comparable to the synchronous predict-then-step loop; a chunk prefetched across an episode boundary is discarded. On a route that negotiated observation history the prefetched request carries the rows buffered so far and predicts from an observation of its own, so every env step still reaches the model exactly once. Opt-in: `RuntimeDriver::with_prefetch(lead)` in Rust, `prefetch_lead=` (keyword-only, default 0) on `Model.run()` and `rlmesh.run()` in Python; a negative lead is a `ValueError`, and the session loop and a served handle refuse a non-zero lead rather than faking it.
- Negotiated workflow editions content-pinned to the sealed `2026.06` edition spec, exact-match `rlmesh-wire-v1` protocol generation, and a per-lane `NEXT_STEP` autoreset contract for vector environments.
- Batched leaf-slab encode and decode on the wire parallelizes past 64KB, speeding up large batched observation and action payloads.
- Image adapters run as typed kernels: the 180° rotation, the uint8 to float32 normalisation, the HWC to CHW transpose, and a pad to the frame's own size bypass the dtype-generic scalar codec, and a camera plan that ends in a normalised float32 CHW tensor (the shape every vision policy asks for) runs as one fused pass from the raw bytes. Output is byte-identical to the generic codec's; a 256×256×3 frame costs about a sixth of what the generic path does.
- A fused grouped predict assembles its groups' inputs and applies their returned action chunks in parallel, one route per thread, when every group names a distinct route and no plan runs a Python custom transform (otherwise it stays sequential); results keep request order and the per-route entry locks guard each route's buffers, so the `predict.adapter` share of a served model's handler time is not serial across a batch's lanes.
- `rlmesh whoami --json`, `rlmesh org list --json`, and `rlmesh profile list --json` for scripts, and `expiresAt` on `rlmesh token --json`, so nothing has to scrape the human output.
- `RLMESH_API_KEY` (with `RLMESH_PLATFORM_URL`) drives `rlmesh token`, `rlmesh eval`, and `rlmesh whoami` without a browser sign-in, matching `rlmesh.platform.Client`; `RLMESH_CONFIG_DIR`, `RLMESH_DATA_DIR`, and `RLMESH_KEYCHAIN=off` confine the CLI's files and keep the OS keychain out, for CI runners and containers.
- `rlmesh logout` asks the platform to end the session (`DELETE /v1/me/session`) before deleting the local credential, so the refresh token stops working server-side too; a platform without the route still signs out locally.
- A CLI reference page covering every command, exit code, environment variable, file, JSON output, and the contract a platform must serve to be driven by the CLI.
- `rlmesh check MODULE:CLASS`, `rlmesh check-image IMAGE`, and `rlmesh describe MODULE:CLASS [--label]`: pre-push checks that sort what they find into failed, warnings, and not checked, exiting 1 only on a failure. `check` runs the describe on a class and fails on a model without a `spec`, an env without `tags`, a spec that does not resolve, or an edition declaration the build cannot run, reporting an env that needs a GPU or assets to build as not checked; `check-image` reads `docker image inspect` and checks the `rlmesh.serve` command, `--env`, a baked `--address`, `EXPOSE 50051`, `linux/amd64`, the rlmesh labels, and whether the image's rlmesh shares a workflow edition with the target platform (`--platform-editions` / `--platform-version`), negotiated the way the runtime does; `describe --label` prints the `dev.rlmesh.describe` value for a custom-entrypoint image, to be run inside the built image (`docker run --rm --entrypoint rlmesh IMAGE describe ... --label`) since the envelope records the machine it ran on and a label generated off linux fails admission, which `check-image` reports too.
- The describe envelope's `runtime` block advertises the edition handshake under the wire's names: `protocol_generation`, `supported_workflow_editions`, and `preferred_workflow_edition`, and `rlmesh.build_info().supported_workflow_editions` lists the editions a build can drive.
- `python -m rlmesh.serve` warns at startup when the served model declares no `spec`: the managed probe cannot synthesize inputs for it.
