# Changelog

All notable changes to RLMesh are documented here. This changelog tracks the `rlmesh` Python package on PyPI, the `rlmesh` Rust facade crate, the C API (`rlmesh.h`) and the C++ header (`rlmesh.hpp`), and the CLI. The other Rust crates are internal implementation detail with no stability promise. Each surface's stability label is in [compatibility](docs/compatibility.md).

The format is based on [Keep a Changelog](https://keepachangelog.com/en/2.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

This release gives the Rust facade crate (`rlmesh`), the C API (`rlmesh.h`, now C ABI 6) and the C++ wrapper (`rlmesh.hpp`, now C++17) the same nouns, options, defaults and error classes as the Python package, each in its own language's conventions. Python also fixes several inconsistent behaviours along the way. Breaking changes are listed first, by language, each with what to do instead.

### Breaking

#### Python

- Two lossy fits the resolver made silently are now refused unless the model spec allows them by name: reading the leading `dim` elements of a wider env state field (`allow=("select_state",)`; before, one finger joint of a two-finger gripper reading bound silently) and feeding a camera input from the env's only camera under another role (`allow=("rebind_camera",)`; before, a wrist input bound a third-person view with a caution). An allowed fit is recorded in `describe()` under `projections:` and in the run's advisories. The Rust facade's `ModelSpec` gains `with_allow` and `allow()` so Rust specs can allow them too.
- Trusted custom-input entrypoints that cannot be imported or whose attribute path cannot be resolved raise `AdapterResolutionError`, chained from the original `ImportError` / `AttributeError`, through `resolve`, `Model`, `run` and `session` (before: those lookup errors escaped). Malformed entrypoint strings still raise `ValueError`; non-callable targets still raise `TypeError`. Native unregistered entrypoints already use `AdapterResolutionError`.

- Missing keys in Dict-space values raise `ValueError` with native structural-conformance text and the value's path when encoding, including batched lanes (before: `KeyError`). Missing keys when decoding received single or batched values raise `ProtocolException` instead of `KeyError`. Existing call-site error wrappers remain; Dict `__getitem__` still raises `KeyError`. Every language uses the same structural encoding text and rejects structural deviations in received values (including missing or extra Dict keys) as protocol errors; range deviations remain subject to the served-value validation policy.

- Every error an env reports raises `EnvironmentException` (or `RecoverableEnvironmentException`) with its `code`, including the codes `TIMEOUT`, `INVALID_ACTION` and `CANCELLED`, which raised `TimeoutError`, `ValueError` and `RuntimeError`. This breaks an `except TimeoutError` or `except ValueError` around an env call; catch `EnvironmentException` and read `code`. A client-side deadline still raises `TimeoutError`.
- `str()` of an authored env or model exception gains its code prefix: `EnvironmentException("bad")`, `RecoverableEnvironmentException("bad")` and `ModelException("bad")` read `[INTERNAL] bad`, as the same error reads in Rust, C and C++ and once it crosses the wire. `args[0]` is the raw message, including on the exceptions the clients raise, whose `str()` is unchanged. Read `args[0]` where you need the bare message.
- The remote text of a Python env failure is `{op} failed: {message}` with no type name: an env that raises `ValueError("x")` in `step` reaches the client as `[INTERNAL] step failed: x` (it read `[INTERNAL] step failed: ValueError: x`), and an authored `EnvironmentException("bad")` as `[INTERNAL] step failed: bad`, as from a Rust, C or C++ env. A served model's failure reads `[INTERNAL] x` in every language, instead of carrying the type name or a doubled `[INTERNAL] [INTERNAL]` prefix. Servers send the message without the code and the client adds it once.
- Timeout texts are one format, `operation timed out after 5s` (the `Duration` of the bound), instead of `remote environment call timed out after 5.000s`, `remote environment connect timed out after 5.000s`, `remote model connect timed out after 5.000s` and `remote model request timed out after 5.000s`.
- Calling `reset`, `step`, `render` or `shutdown` on a `RemoteEnv` or `RemoteVectorEnv` after `close()` (or after an accepted `shutdown()`) raises `RuntimeError("RemoteEnv is closed")` (`RemoteVectorEnv is closed`) instead of `ConnectionError("not connected")`; `close()` stays idempotent and the accessors keep working.
- `Model.run` checks its options before dialing anything, with `ValueError`, also when `episodes=0`: `execution_horizon` above 1024 or above the model's `native_chunk` (before, a model error at route resolution), `max_episode_steps` below 1 or above `2**63 - 1`, `max_episode_seconds` not above 0, and `prefetch_lead` above `2**32 - 1` (before, an `OverflowError` or a runtime error). `max_episode_seconds=float("nan")` is a `ValueError` on both loops instead of meaning no cap; `float("inf")` stays no cap and is now accepted by a `NEXT_STEP` env on the native loop, as `None` is. A `NEXT_STEP` env's refusal of seeds, caps or a trial base, a lockstep vector env's refusal of `execution_horizon > 1`, and a vector env without a lane endpoint under driver-owned resets raise `ValueError` at connect instead of `RuntimeError`. `Session.run` resolves the episode budget and checks `max_episode_steps` (now also its upper bound) before connecting; `rlmesh.run` on the session loop (`RANDOM_SAMPLE`, a served model) checks the budget, caps and `trial_index_base` before the session dials; and `RemoteModel.session` checks `execution_horizon` (1 to 1024) and resolves `view` before dialing the env or the model.
- `RemoteModel.session` over a multi-lane target (a `RemoteVectorEnv`, or an `EnvServer` whose contract reports `num_envs > 1`) raises `ValueError` instead of `RuntimeError`, with the same text and still before the model is dialed.
- A Python `Model`'s `close()` is terminal and runs once: it stops a `serve` still running on the model (requests it already received finish, and that `serve` returns), waits for in-flight corner calls, then fires the close hook once; a subclass's authored `close()` no longer re-runs on every call. Afterwards `run`, `session` and `serve` on the model, and `predict`, `step` and `run` on a session opened before, raise `RuntimeError("the model is closed")`, and a session closed afterwards fires no `on_episode_end`. Before, a closed model kept working and the next serve rebuilt it; build a new model instead of reusing a closed one.
- All corner and hook calls on one Python `Model` run one at a time, across its sessions, runs and serves, so two threaded sessions on one model no longer overlap inside it. A corner or hook that calls back into its own model (a predict, `run`, `session`, `serve` or `close()` on it, or a predict through a session on it) raises `RuntimeError` instead of deadlocking.
- A second `Model.run` on a model while one is in progress, from any thread (a hook included), fails at once with `RuntimeError`; before, the two runs shared the model's per-run instruction, trust override and hook context. Predicts from other sessions on the model still run, one at a time.
- `Model(on_close=...)` replaces a subclass's authored `close()` body, as the constructor's docstring says: with `on_close` set, `close()` runs the hook once instead of the authored body. A subclass passing both loses its authored body.
- `native_chunk` is read once, after `load()`, and a value below 1 is refused there with `ValueError("native_chunk must be >= 1 ...")`. A `native_chunk` set in `load()` on a model with no chunk corner is refused by the constructor or `from_config` with `TypeError`, as a class-level one is; before, `Model.run` and `serve` refused it only at route resolve with `RuntimeError("model error: ...")`, and a local session never did.
- A model returning a tuple as an action chunk now replays (and de-chunks) it as one frame, as the native engine already did when the model was served; return a list of frames instead. Only a list, an array or tensor (along its leading axis) and a mapping (per field) split into frames.
- `Model.run` raises `ValueError` for a chunk that is not exactly the declared `native_chunk` frames and for an empty chunk at a horizon above 1, as a local session already does, instead of `RuntimeError("model error: ...")`.
- Inside its own `Session.run` hooks a session offers only the `RunContext` protocol: `contract`, `num_envs`, `read` and `frame_sources` keep working, and `reset`, `step`, `predict`, `run`, `close`, `reader`, `observation_roles`, `selected_workflow_edition` and `done` raise `RuntimeError`. Before, a hook could step or close the session under its own loop and corrupt it. Outside the hooks every member works as before.
- A retained run context exposes a local env's render source only during hook dispatch on that thread. A saved render callable raises when used outside dispatch, during another session operation, after the session closes or is dropped, and during a recursive render. Direct idle `Session.frame_sources()` and remote session contexts still render.
- `describe` and `describe_json` raise `ValueError` when an explicit `kind` contradicts the object (`kind="env"` on a model with no `make`, `kind="model"` on a factory with no `predict`) instead of describing it the wrong way; a bare callable still takes the kind it is given. Describing a model whose class declares `native_chunk` without a `predict_chunk`/`predict_chunk_batch` corner raises `TypeError`, and one below 1 raises `ValueError`, as building the model would, instead of recording it.
- `EnvServer` raises `RLMeshException` (a `RuntimeError`) for a failed serve or close, from `serve()`, `wait()` and `shutdown()` alike, with the one text `serve failed: <message>` (`serve failed: close failed: boom`, `serve failed: close timed out after 5000ms`); a foreground `serve()` failure gains the `serve failed: ` prefix it lacked. Misuse (`wait()` before `start()`, a second `serve()`) stays `RuntimeError`.
- `EnvServer(path=..., transport="tcp")` raises `ValueError` instead of silently binding `unix://<path>`.
- An env without its observation or action space (or `single_*` spaces for a vector env) raises `TypeError` (`env must have 'observation_space'`) from `EnvServer(...)`, checked first: before, it leaked `AttributeError`, or `AdapterResolutionError` when tags were given.
- A one-lane vector env's `metadata["autoreset_mode"]` is checked as any env's is before the scalar view strips it: a present `None`, a non-string, an unknown string or `"SameStep"` raises `ValueError` (before, only a `SAME_STEP` enum was refused).
- `rlmesh.trial_index(options)` raises a `ValueError` saying to pass `lane=` when it reads the per-lane list a multi-lane reset sends, instead of returning `None`; the new `lane=` argument reads one lane's ordinal.
- `view="http:PORT"` takes only ASCII digits for the port: a sign, `_` separators, inner spaces and other scripts' digits, which `int()` accepted, raise `ValueError`.
- Spaces follow Gymnasium and the native languages more strictly:
  - `Box` refuses a fractional bound on an integer or bool dtype with `ValueError` instead of truncating it: `Box(0.5, 3.7, [2], "int32")` was the range 0..3. Integral floats (`Box(0.0, 10.0, [1], "int64")`) are accepted and stored exactly.
  - Integer Box bounds must fit together in a signed or unsigned 64-bit range: bound pairs such as `Box(-1, 2**63, [1], "int64")` and `Box(0, 2**64, [1], "uint64")` raise `ValueError` instead of rounding or saturating.
  - `Box.contains` requires the space's exact shape: a `(6,)` value is not a member of a `(2, 3)` Box, and a bare number is not a member of a `(1,)` Box. Before, only the element count and dtype were checked. Dict and Tuple members check their Box children the same way.
  - A `Box` with integer bounds on an integer or bool dtype (`bounds_kind == "typed_uniform"`) reads `low` and `high` as one number, as a float Box does, instead of a one-element list: `Box(0, 255, [2], "uint8").high` is `255`. The describe envelope's space JSON is unchanged.
  - `Box(spec)`, `Discrete(spec)` and the experimental `MultiBinary(spec)`, `MultiDiscrete(spec)` and `Text(spec)` raise `ValueError` for a spec of another kind, as `Dict(spec)` and `Tuple(spec)` already did. `Box` and `MultiBinary`/`MultiDiscrete` used to wrap any kind, and `Discrete` and `Text` failed with `KeyError`.
  - `Tensor(buffer, shape, dtype)` raises `ValueError` instead of `OverflowError` when the element or byte count overflows, like its other invalid arguments.

#### Rust

The `rlmesh` facade crate now exposes spaces, values, envs, models, runs and sessions (see Added). Code written against 0.1.0 migrates as follows:

- Envs implement the sync, Gymnasium-shaped `Env` / `VectorEnv` traits and are served with `EnvServer` (or `EnvFactoryExt::serve`). The async request/result traits, `VectorEnvServer`, `BoundEnvServer`, the request and result types, `EndpointPhases` and `TRIAL_INDEX_OPTION` moved to the hidden `rlmesh::binding`.
- Models implement `Policy` (or are a closure) and are wrapped in `Model`. `ModelHandler`, `ModelWorker`, `PredictFn`, `RunLocalOptions`, `ServeModelOptions`, `BoundModelServer`, the route and observation types, `EnvRuntimeError` and the `async_trait` re-export moved to `rlmesh::binding`, and left the prelude.
- Runs use `run` / `Model::run` and `RunHooks`; `Model::bind` (or `rlmesh::bind`) binds a model to one env to step by hand, as Python's `Model.bind` does. The runtime driver's `RuntimeHooks`, its event types, `HookError`, `NoopRuntimeHooks`, `RuntimeReport`, `PeerCeiling`, `telemetry` and the `CancellationToken` re-export moved to `rlmesh::binding`; cancel with `ext::CancelToken`.
- `rlmesh::spaces` exposes stateful spaces and their specifications. The wire types it re-exported (spec payloads and builders, `SpaceValue`, the core `Tensor` and `DType`, `MetaMap`, render and request types) moved to `rlmesh::binding::spaces`, and the crate-root `SpaceSpec`, `SpaceValue` and `RenderFrame` are gone; `rlmesh::binding::space_spec_wire` gives the wire spec of a `spaces::SpaceSpec`.
- `CURRENT_WORKFLOW_EDITION`, `parse_declared_edition`, `PROTOCOL_GENERATION`, `supported_workflow_editions` and the `PeerInfo` override moved to `rlmesh::binding`; use `current_workflow_edition()` and `build_info()`.
- `ServeOptions` holds shared serving configuration: its `token`, `predict_concurrency` and `peer_info_extra` moved to `ext::EnvServerOptions` and `ext::ModelServeOptions`.
- `RemoteEnv` and `RemoteVectorEnv` are built from `RemoteEnvOptions` and connect at `new`; an endpoint token is sent as `RemoteEnvOptions::api_key`.
- `Error` has one variant per error class and is `#[non_exhaustive]`: `Address` became `InvalidArgument`, `Server` became `Internal`, and `Protocol`, `Type`, `Runtime`, `Os` and `Cancelled` are new. `Error::class()` returns the exact `ErrorClass` (with `is_subclass_of` testing the class hierarchy). Error classes and rendered text (`Display`, last-error messages, `what()` and exception strings) are the same in every RLMesh language. `ErrorCode` gains `Unsupported`.

#### C

The experimental C API moves to **ABI generation 6** (`RLMESH_ABI_VERSION` 6, SONAME `librlmesh_capi.so.6`, CMake package version 6). ABI 4 and 5 binaries and sources do not build or load against it:

- A model is bound to one env as Python's `Model.bind` does: `rlmesh_model_bind` (`rlmesh_bind` for a model target, `RANDOM_SAMPLE` included) returns an `RLMeshBinding`, stepped with `rlmesh_binding_reset(seed, options)` and `rlmesh_binding_step(action)` (NULL: the model's action). ABI 5's `RLMeshSession` and its `rlmesh_session_*` / `rlmesh_ext_session_*` functions are removed, with no predict, run, hooks, view, cancel token or trial index on a binding: use `rlmesh_model_run` for whole episodes.
- A model served elsewhere is an `RLMeshModel` built from its participant address, `rlmesh_model_from_address`, as Python's `Model(address)`; `RLMeshRemoteModel`, its options and `RLMESH_MODEL_TARGET_KIND_REMOTE_MODEL` are removed.

- Type names spell the project `RLMesh` (`RLMeshStatus`, `RLMeshValue`, `RLMeshEpisode`, ...) instead of `Rlmesh`. Function names (`rlmesh_*`), macros (`RLMESH_*`) and the `rlmesh::` C++ namespace are unchanged.
- `RLMeshValue` holds ten core kinds (None, Bool, Int, Float, Text, Bytes, Tensor, List, Tuple, Dict) instead of the space-specific projection: a Discrete action is an Int, and a Box observation or a MultiBinary or MultiDiscrete sample is a Tensor. `rlmesh_value_box`, `rlmesh_value_discrete`, `rlmesh_value_as_discrete`, `rlmesh_value_copy_multi_*` and the `RLMESH_VALUE_BOX`-style kinds are removed.
- `RLMeshTensor` is an opaque handle: the tensor POD, `rlmesh_tensor_release`, the DLPack `(code, bits, lanes)` dtype triple with its `RLMESH_F32`-style macros, `RLMESH_DTYPE_INIT` and `rlmesh_dtype_size` are removed. `RLMeshDType` is now the dtype enum, and `rlmesh_ext_dtype_size` gives its size.
- The space readers (`rlmesh_space_type`, `_ndim`, `_copy_shape`, `_box_bounds`, `_discrete_n`, `_dict_*`, `_tuple_get`, `_text_*`, `_copy_nvec`, `_len`) are replaced by the `RLMeshSpace` handle and the `rlmesh_space_spec_*` readers; `rlmesh_space_dtype` takes a Space handle, and specs use `rlmesh_space_spec_dtype`.
- `RLMeshContract` and `rlmesh_contract_*` are replaced by `RLMeshEnvContract`; the JSON adapter-plan exports (`rlmesh_adapter_resolve`, `rlmesh_adapter_plan_*`) by the typed adapters.
- Models are a four-corner `RLMeshModelVtable` passed to `rlmesh_model_new`; `rlmesh_model_run_local` and `rlmesh_model_cancel` are replaced by `rlmesh_model_run` / `rlmesh_run` with `RLMeshRunOptions` and by `RLMeshExtCancelToken`. A run executes one episode by default, or one per seed; it borrows the model, so its `close` no longer fires when a run ends; and a model refuses a new episode past 65,536 live ones with `RLMESH_ERR_RUNTIME` instead of evicting the least recently used.
- `rlmesh_abi_version_major/minor/patch` and the `RLMESH_ABI_VERSION_MAJOR/MINOR/PATCH` macros are removed; read the package version from `RLMESH_VERSION` or `rlmesh_build_info`.
- Every options, vtable and attributes struct carries `struct_size` with `_INIT` and `_MIN_SIZE` macros: start from the `_INIT` macro (or pass NULL for defaults). A zero-initialized struct, a size below the minimum and nonzero unknown trailing bytes are refused, and input bool fields must hold 0 or 1. Enums reserve `INVALID = 0`.
- Errors distinguish classes: a wrong-kind value or space read returns `RLMESH_ERR_TYPE` instead of `RLMESH_ERR_INVALID_VALUE`, which is deprecated and no longer returned; a malformed tensor or non-UTF-8 text is `RLMESH_ERR_INVALID_ARGUMENT`; a server-side failure (a failed bind) is `RLMESH_ERR_INTERNAL` instead of `RLMESH_ERR_TRANSPORT`, which is renamed `RLMESH_ERR_CONNECTION` and kept as a deprecated alias; a protocol failure is `RLMESH_ERR_PROTOCOL` instead of `RLMESH_ERR_INTERNAL`. `rlmesh_last_error_message` reports the error text: the `connection error:`, `environment error:`, `model error:` and `internal error:` prefixes are gone, environment and model errors read `[CODE] message`, and a timeout reads `operation timed out after 5s`. `rlmesh_last_error_is_recoverable` is nonzero only for a recoverable environment or model error, no longer for a timeout or connection failure.

#### C++

- `rlmesh::Binding` (`Model::bind`, `rlmesh::bind`) replaces `rlmesh::Session` and `rlmesh::session`, and `Model::from_address` replaces `rlmesh::RemoteModel`, as in C.
- `rlmesh.hpp` keeps its C++17 minimum and now requires exceptions (`#error` otherwise); `-fno-exceptions` builds are no longer supported. `Result<T>`, `Error`, `RLMESH_TRY`, the aborting `value()` / `unwrap()` accessors, `ValueRef`, `SpaceRef`, the worker `Batch` / `Request`, `RunReport` and the ABI-4 wrapper types are removed. Fallible calls return their value and throw the corresponding exception class instead (see Added); write `try` / `catch` where you checked a `Result`. A `Model` is built from a policy or callable whose `predict` takes and returns `rlmesh::Value`, and options are aggregates with named fields and `std::chrono::duration<double>` durations that drop the `_seconds` suffix (`max_episode_seconds` becomes `max_episode`).

### Added

#### Python

- Gripper polarity and delta units are declared and checked. `Actuator(polarity="open" | "close", unit=0.05)`, `StateTag(polarity=...)`, `Field(polarity=...)` and `State(polarity=...)` say which way a gripper command or reading rises and the SI size of one delta unit, on the model (its network's convention) and on the env (its simulator's). When both sides declare one, the resolver composes both sides' `invert`/`scale` and the range map, and a difference raises `AdapterResolutionError` unless the model allows `"flip_gripper"` (reflected in the declared range) or `"convert_units"` (rescaled). A side that declares nothing is not checked, with an info advisory. The Rust facade's `Actuator`, `State`, `StateTag` and `Field` carry the same fields; the C and C++ APIs do not yet.
- `RunResult.advisories` holds what the model's adapter resolve tolerated or applied (a zero-filled camera, an allowed projection), whether the model runs in process or is served: on a session, the driver asks for them on resolve (`ModelResolve.reads_advisories`) and the model answers them on `ModelResolved.advisories`. Before, they were only logged.
- A served model's resolve that cannot pair its spec with the env reaches the driver as `AdapterResolutionError`, not `ModelException("[INTERNAL] AdapterResolutionError: …")`. On a session the fault carries the `ADAPTER_RESOLUTION` code. On the v1 model wire, `MODEL_ERROR_CODE_ADAPTER_RESOLUTION` (6) is capability-gated: a served model advertises `rlmesh.model.adapter_resolution_code.v1`, the runtime then sets `ResolveAdapterRequest.reads_adapter_resolution_code`, and only then is the code sent; any other pairing answers `INTERNAL` as before (`ModelClient::server_types_resolution_errors`).
- Ctrl-C during `Model.run` raises `rlmesh.Interrupted` (Experimental), a `KeyboardInterrupt` whose `.result` is the `RunResult` of the episodes that completed before it, whether the interrupt cut the loop or landed inside a predict or a hook; the episode in progress is not in it.
- `EnvFactory.render_params = ("height_param", "width_param")` names the env's camera dial and `EnvFactory.requires_episode_cap = True` says the env never truncates on its own (both Experimental; native counterparts deferred). `make` publishes them under `rlmesh.env.v1.render_params` and `rlmesh.env.v1.requires_episode_cap`. A run against an env that requires a cap raises `ValueError` before its first reset unless it passes `max_episode_steps`. `SandboxEnv(..., model=...)` and `SandboxVectorEnv(..., model=...)` take the model (a `ModelSpec`, a model, or a `SandboxModel`, served first to read its spec) and bind its `Image(render=...)` size on a prebuilt image's camera dial before `make`, under any param you pass; inputs asserting different sizes raise `ValueError`.
- `RunResult.save(path, *, model=, env=, config=)` writes the run as an `rlmesh.result.v1` bundle (a folder, or a zip for `.zip`), and `RunResult.load(path)` reads a one-workload bundle back, with the episode outcomes the bundle keeps.
- `hooks=` on `Model.run`, `Model.bind` and `rlmesh.run` takes a list of `RunHooks`, each called in order; every hook sees `on_run_end` even when an earlier one raises, and the first exception is raised after.
- `RemoteModel`, `RemoteEnv` and `RemoteVectorEnv` dial `https://host[:port]` addresses over TLS (HTTP/2 negotiated by ALPN, port 443 by default) and take `api_key=` and `tls_ca_file=`. The key is sent as `authorization: Bearer <key>`; without one, `RLMESH_API_KEY` is read and sent only to `https://` addresses. `tls_ca_file` trusts only that PEM bundle; otherwise the system roots are trusted. A key a header cannot carry, an unreadable CA bundle or one holding a certificate that does not parse, or an address with userinfo, a query, a fragment or a path raises `ValueError` before any dial, and the error never echoes them; a failed TLS handshake raises `ConnectionError` reading `TLS handshake with host:port failed: …`, and a key the server rejects raises `ConnectionError` pointing at `api_key` / `RLMESH_API_KEY`. Constructors check the key and CA bundle; each dial reads them again, so a rotated `RLMESH_API_KEY` reaches the next session. An explicit key sent unencrypted to a host other than loopback warns once per address. The key never appears in `repr` or error text. Rust (`RemoteModelOptions::api_key`, `tls_ca_file`), C (`api_key` and `tls_ca_file` appended to `RLMeshRemoteEnvOptions` and `RLMeshRemoteModelOptions`; `_MIN_SIZE` stays at the ABI-5 size, so existing callers keep working) and C++ (`with_api_key`, `with_tls_ca_file`) have the same options.
- A served model drives a plain local env with no `EnvServer`: `rlmesh.run(RemoteModel(address), MyEnv())` and `rlmesh.session(...)` step the env on the calling thread, and an `EnvFactory`'s env is built for the session and closed with it, in every language. A local vector env raises `TypeError` (a served model drives one env). Before, any local env raised `TypeError`.
- `RemoteModel` reaches a model served on a `unix://` socket, as `RemoteEnv` does.

- `rlmesh.ModelException` (a `RLMeshException`, so `except RuntimeError` still catches it) is raised when a model fails a request, instead of `RuntimeError("model error: …")`. It carries `code` (the model error code, `"INTERNAL"` for an authored failure) and `is_recoverable`, and its text is `[CODE] message`. A model raises `ModelException(message, is_recoverable=True)` to fail one request as recoverable: a served model sends that flag to the client, instead of every raised exception being a permanent internal failure.
- Env errors can be recoverable: the request fails but the client's session stays usable. After a fatal env error the client's next reset opens a new session instead of every later call failing; Python raises `RecoverableEnvironmentException` for a recoverable one, and env exceptions carry `code` and `is_recoverable`. In a multi-lane batch a fatal lane error wins over a recoverable one, and a batch where some lanes failed recoverably while others advanced ends the session, since replaying it would step the advanced lanes twice.
- `rlmesh.FrameSources` is now a Stable root export. `rlmesh.recorder` and its `WorkloadRecord`, `EpisodeRecord`, `MediaRef`, and `SCHEMA` exports are Stable; `ResultSet` and `EpisodeRecord.from_result` remain Internal.
- `View(hold=...)` keeps the live viewer up after the session ends, showing the final frame and HUD (marked `[held]`, with every source still selectable): `hold=True` until you quit it, or a number of seconds. The default still closes the viewer with the session. The hold follows only a session that ended normally: one closing on an error or Ctrl-C (`KeyboardInterrupt`) skips it, releases the env and model, and raises at once. An unbounded hold with no interactive terminal (stdin not a tty, as in CI, on any backend) is skipped with a warning, so a non-interactive run never blocks on it; a number of seconds still holds.
- `View(step_hz=...)` paces a viewed session's env steps to at most that rate, so a fast simulator plays back at a watchable speed (the env's control rate for real time). `View.fps` still only thins the drawing. The pacing sleep is left out of the run's step and round timings.
- The HTTP viewer has a quit button (and a `/quit` route) that does what `q` does in the terminal: stop the run, or close a held viewer.
- `Model.run`, `rlmesh.run` and `SandboxModel.run` take a `SandboxEnv`: the sandbox lends its container to the run and attaches again after, and a `SandboxModel` joins the env container's session over their shared Docker network. `RANDOM_SAMPLE` and a local model run against it too.
- `Model.run(env, view=...)` and `rlmesh.run(model, env, view=...)` watch a native run live, as a binding does (the first lane of a vector env): skip truncates the episodes in flight at the next step and the run goes on; quit truncates them and returns the partial result.
- `Session.run()` fills `RunResult.telemetry`, so `format_telemetry()` works on the Python loop a served model or a viewed run drives. It reports the client-observed `rpc.total` of `model.predict`, `env.reset`, `env.step`, and `runner.round`, under the names the native `Model.run` loop uses.
- `ServeOptions(compress_responses=True)` has an env server compress its responses (zstd, else gzip) for clients that accept it; every RLMesh client now accepts compressed responses. Compression is responses-only: RLMesh clients never compress requests, and servers refuse a compressed request (`UNIMPLEMENTED`) before reading it, so a peer without the endpoint token cannot make a server decompress one. It is off by default: on loopback a ~200 KB rendered-image observation shrinks to ~1.4 KB on the wire but the step takes as long, so it only pays on a slow link with compressible observations.
- One model image can serve several checkpoints that each need their own adapter. `python -m rlmesh.serve` serves the `module:Class` in `RLMESH_SERVE_TARGET` instead of its command-line target when it is set (a model only; `--env` ignores it), and a `dev.rlmesh.package` checkpoint names that class as its `entrypoint`, which the managed platform sets. `rlmesh check-image` fails a malformed `entrypoint` (not `module:Class`). See [Checkpoints](docs/compute-variants.md#checkpoints).

#### CLI

- `rlmesh registry publish TARGET` with no sources builds and publishes the variants declared in `rlmesh.toml`, so compute variants need no hand-written JSON label. The file is the `dev.rlmesh.package` label in TOML under its own key names, plus `dockerfile`, `target` (the Dockerfile stage), `context` and `build_args`; each `[variant.KEY]` table is one build, in priority order, with its requirements as `accel.*` keys, and `[profile.KEY]` tables are shared by every build. Every problem in the file is reported at once, by the same rules as `check-image`. Each variant is built for `linux/amd64` with its label rendered in and pushed as `TARGET-TAG-KEY`, then the builds are published as one version with the file's version-level keys as the index annotation. A version tag already in use, or a `TARGET-TAG-KEY` tag holding an image other than an earlier build of that variant (its label differs), is refused before anything is built, unless `--force`. A publish that stopped after pushing TARGET is finished by running it again: when TARGET already holds the index of the builds at the `TARGET-TAG-KEY` tags, each labelled as the file renders it, nothing is rebuilt and only the remaining tags are pointed at it (`--force` rebuilds instead). `--dry-run` builds nothing, prints the builds, and fails on a tag the real run would refuse; `--dry-run --json` only renders, printing each label and the index annotation; `--config FILE` names another manifest (`-` reads stdin).
- `rlmesh registry publish TARGET SOURCE...` publishes a version with several compute variants: it assembles already-pushed per-variant images (a PyTorch CUDA build, a ROCm build, a JAX build) into one OCI image index and pushes it under the target tag, plus `--tag` and `--channel` tags. Each child must be one linux image whose `dev.rlmesh.package` label declares a valid `variant` block. Variant and row keys must be unique, all children must serve the same kind, and at least one must be `linux/amd64`. Every carried attestation must describe a child, and an index source's declared platform must match its image config. Every check that can run before pushing runs first (the sources, their labels, the assembled index, where each tag points), and every problem it finds is reported at once, before anything is pushed. `--index-package FILE` sets version-level data as the index's `dev.rlmesh.package` annotation; it is refused when every manifest the sources carry (images and attestations) is a Docker schema2 manifest, which would turn the index into a Docker manifest list without it, the assembled index is checked to carry it before the push and as stored after it, and a lone index source's own annotation is checked by the same rules. The target and `--tag` tags do not move to a different index without `--force`, and are pushed only over a tag the registry said was absent when checked (the check and the push are separate calls, so this is not a lock): one that cannot be read (authorization, transport, registry errors) is refused without `--force`. A tag already holding the same index, compared field by field as stored, is not pushed again, except that another tag holding it at a digest other than the target's is re-pointed at the target's. The index is pushed to the target tag alone and checked as the registry stores it (the index assembled and, with `--index-package`, an OCI image index carrying the annotation); only then are the `--tag` and `--channel` tags pointed at the target's digest, which is also what they point at when the target already holds the index, so every tag is the same manifest. If that check fails, only the target tag has moved: the error says what it pointed at before and how to recover (put the previous digest back with `docker buildx imagetools create`, or publish again with `--force` once the cause is fixed). If pointing those tags fails, the error gives the `imagetools create` command that points them, and running the same publish again finishes it. What a tag holds is read by the digest it resolved to, so a tag moving mid-read is not mistaken for this index. The `--channel` tag moves and reports the digest it moved from, unless it is also the target or a `--tag`. `--dry-run` prints the per-variant table, the index JSON, and each tag's state. See [Publishing compute variants](docs/compute-variants.md).
- `rlmesh check-image` checks an image's compute variant by the managed platform's rules:
  - fails what the platform fails: keys (`^[a-z0-9][a-z0-9-]{0,31}$`), the `framework`/`accel`/`render` facets, `requires` constraints (comma-joined `>=`, `>`, `<=`, `<`, `==`, `=` clauses, a bare version meaning a minimum; `accel.vram`, the minimum VRAM per GPU, as a positive whole-byte quantity string within the signed 64-bit range: `"24Gi"`, with `Ki`, `Mi`, `Gi`, `Ti` powers of 1024, `K`, `M`, `G`, `T` powers of 1000, and no suffix meaning bytes) and their vendor rules, `priority` as an integer in `[-1000, 1000]`, `gpu.count` up to 8, at most one default profile, and derived row keys
  - warns where `requires` disagree with the image's `CUDA_VERSION`, `NVIDIA_REQUIRE_CUDA`, `ROCM_VERSION`, or describe `framework_versions`, including an `accel.cuda` constraint without a lower bound (`<13`), which admits drivers older than the image's CUDA runtime
  - reports the requires the platform infers for an image without a variant block, and the row keys the image gets

#### Rust

- `ext::unregister_entrypoint(name, expected)` removes a trusted entrypoint by transform identity, or any registration when `expected` is `None`. Existing routes retain their transforms; removed and replaced transforms are dropped outside the registry lock so deleters can re-enter safely.
- Spaces, `Tensor` and dtypes: `rlmesh::spaces::{Space, Box, Discrete, Dict, SpaceSpec, space_from_spec}` with `seed` (a `u64`, returned), `sample`, `contains`, `kind`/`shape`/`dtype`, Box `low`/`high`/`bounds_kind` as exact typed `Bound`s, Discrete `n`/`start`, and Dict's read-only mapping in declaration order (`keys`, `values`, `items`, `get`, `len`, `contains_key`, `d["key"]`). Clones of a space share its sampler; `as_box()`/`TryFrom` downcast and `From` upcasts to `Space`. `rlmesh::Tensor` provides storage and shape operations (`new`, `shape`, `dtype`, `ndim`, `size`, `nbytes`, byte `strides`, `device`, `buffer`, `is_contiguous`, `reshape`, `copy`, `tobytes`), `rlmesh::DType` the twelve named dtypes, and `rlmesh::ext` holds the Rust-only extras (`TensorExt`, `SpaceExt::contains_detail`, `Storage`, `dtype_size`).
- Values and metadata: `rlmesh::Value` (also `rlmesh::types::Value`) with ten kinds (`None`, `Bool`, `Int`, `Float`, `Text`, `Bytes`, `Tensor`, `List`, `Tuple`, `Dict`), strict reads (`as_int` refuses a `Bool`, `as_float` an `Int`, with `Error::Type`), `kind()` and kind-strict equality; `rlmesh::Metadata` (with the `InfoDict` and `Kwargs` aliases) is an insertion-ordered map (`insert` keeps an existing key's place, `remove` keeps the rest in order, collecting repeated keys keeps the first position and the last value) whose equality ignores order. `Space::sample` returns a `Value` (a Box a `Tensor`, a Discrete an `Int`, a Dict a dict in its declaration order, MultiBinary and MultiDiscrete a `Tensor`) and `Space::contains` takes one: for a Box a `Tensor` of its dtype or numbers and nested lists of its exact shape (integer dtypes refuse floats), for a Discrete an `Int`, `Bool`, integral `Float` or one-element `Tensor`.
- `Tensor::from_dlpack`, `to_dlpack(ToDlpackOptions)` and `dlpack_device` provide CPU DLPack exchange. Imports copy and consume the producer only on success; versioned exports retain shared read-only storage or own a writable copy, with raw ownership helpers in `ext::dlpack`.
- Env authoring and serving: `rlmesh::Env` and `rlmesh::VectorEnv` are sync Gymnasium-shaped traits: `observation_space()` / `action_space()` return a `Space`, `reset(seed, options)` returns `(observation, info)`, `step(action)` returns `(observation, reward, terminated, truncated, info)` with `Value` and `InfoDict`, and `render`, `render_mode`, `metadata` and `id` default to `None`, while `close` defaults to a no-op (`id` `None` serves `"UnknownEnv-v1"`; a render frame is any numeric image `Value`, cast to uint8 and PNG-encoded, accepting channel-first RGB and RGBA layouts too). A vector env takes a `VectorSeed` and sees values stacked along a leading lane axis, recursively by field for Dicts and component for Tuples. `rlmesh::EnvServer` is one server built with `new`, `lanes` or `vector` and `EnvServerOptions` (`address`, `host`, `port`, `path`, `transport`, `options`, `tags`, `close_env_on_shutdown`, and the Rust-only `ext` with `token`, `peer_info_extra` and `publish_describe`): it binds at construction (`address()`, `env_contract()`), then `serve()` keeps lane 0 on the calling thread (SIGINT drains, closes and returns the cancellation class; SIGTERM stops it; both dispositions are restored on return), `start()` runs in the background, `wait(timeout)` awaits completion and `shutdown()` drains it, and `serve_async` / `wait_async` / `shutdown_async` are the async twins; dropping a server shuts it down. It checks the served contract at construction (a one-lane vector env served as a scalar lane, tags, `RLMESH_EXPECTED_ENV_BRANCH`, `autoreset_mode`, lane agreement, address, workflow edition, endpoint token) and keeps served value validation. `ServeOptions` configures serving (`allow_remote_shutdown`, `idle_timeout`, `drain_timeout`, `close_timeout`, `workflow_edition`, `compress_responses`; an env server caps a `None` drain or close at 5 s, and a zero timeout is a `ValueError`-class error). `EnvFactory` (associated `tags`, `tag_params` of `TagParam { name, default_, choices }`, `reset_options`, `workflow_edition`, `tags_for`, `enumerate_variants`; `prepare`, `make`, `close`) with `EnvFactoryExt::make_env` (binds discriminant defaults and stamps tags, branch and reset options), `serve` / `serve_async` (`EnvFactoryServeOptions` with `num_envs`, `workflow_edition`, `make_kwargs` and an `ext::CancelToken`), `MadeEnv`, `Variant` / `VariantOptions`, `rlmesh::trial_index`, `rlmesh::specs::EnvContract` (read-only, with `to_dict`, `env` and `spec`) and `Transport` are new. An authored env failure reaches the client as `[INTERNAL] {op} failed: {message}`, and a blocking server call made from async code fails with the `RuntimeError` class naming its async twin.
- Model authoring and serving: `rlmesh::Policy` defines model behavior: it implements any of the four corners (`predict`, `predict_batch`, `predict_chunk`, `predict_chunk_batch`, each with a `<corner>_with_context` twin) and lists them in `const CORNERS` and, for the ones that read the context, `const CONTEXT` (`rlmesh::Corners`); `load(&Kwargs)` (the default accepts only an empty config, and `const LOAD_KEYS` of `LoadKey::required` / `LoadKey::optional` is checked first with the standard load-error texts), `on_episode_end`, `close`, `spec()`, `workflow_edition()`, `allow_fusion` and `NATIVE_CHUNK` / `native_chunk()` are its other members. A closure is a policy, and `rlmesh::with_context` wraps one that reads the context. `rlmesh::Model::new(policy, ModelOptions)` and `Model::from_config::<P>(config)` load eagerly and refuse invalid declarations first (`TypeError` class); missing corners derive from their batched counterparts (`predict` from `predict_batch`, `predict_chunk` from `predict_chunk_batch`). `Model` is a shared handle whose corner and hook calls run one at a time on a library thread, refuse re-entry from their own corner, and keep each episode's `rlmesh::types::PredictContext` (`episode_id`, `episode_seed`, `predict_index`, `predict_seed`, `state: EpisodeState`) for the corners that read it, refusing a new episode past 65,536 (`RLMESH_EPISODE_CAPACITY`) instead of evicting. `close()` / `close_async()` stop any serve, wait for queued calls and fire the hook once; later calls fail with the `RuntimeError` class, and dropping the last handle closes it. `Model::serve(address, ModelServeOptions)` / `serve_async` serve with bounded shutdown and edition resolution (5 s drain and close caps, the call's edition first, SIGINT and a `cancel` token drain, close and return the cancellation class, SIGTERM returns `Ok`) and close the model when they stop; the model-only `token` and `predict_concurrency` are in `ext::ModelServeOptions` (`Some(0)` is a `ValueError`). `NO_ADAPTER` and `rlmesh::types::{SpecArg, LoadKey, BatchPredictContext}` are new.
- Typed adapters in `rlmesh::adapters`: `EnvTags` and `ModelSpec` built from typed observation and input trees and leaves (`ImageTag`, `StateTag`, `TextTag`, `Split`, `Field`; `Image`, `State`, `Concat`, `Constant`, `Text`, `Action`, `Actuator`), the role and part constants and tolerant vocabularies, custom `ObsTransform` / `CustomEncoding` callables, `tag` / `tag_vector`, and `resolve` / `resolve_from_contract` returning a shared `Adapter` (transforms, `explain`, `advisories`, history) that executes the model engine; `AdapterBase` authors a custom adapter, `ext::register_entrypoint` registers a trusted custom input, and `ext::env_tags_from_json` / `ext::model_spec_from_json` parse the JSON forms. A model's spec attaches through `Policy::spec()`.
- Runs and sessions: `rlmesh::run(model, env, RunOptions)` and `Model::run(env, RunOptions)` (with `run_async` twins) take `RunOptions` (`episodes`, `seeds`, `max_episode_steps`, `max_episode` as a `Duration`, `hooks`, `instruction`, `view`, `close_env`, `trust_entrypoints`, `execution_horizon`, `prefetch_lead`, `workflow_edition`, `trial_index_base` and an `ext::CancelToken`), check them before anything dials (`ValueError` class), resolve the run's workflow edition from the call, `RLMESH_WORKFLOW_EDITION` and the model's type, and return a `RunResult` of `EpisodeResult`s (0-based `index`, `reward`, `duration_s` in seconds, `success`, `trial`, per-episode `predict_ms` / `step_ms`) and `TelemetryRow`s, with `num_episodes`, `total_steps`, `mean_reward`, `success_rate`, `format_telemetry` and a printable representation. The env is an `EnvTarget`: an address, a served `&EnvServer`, a borrowed `&mut` env, `EnvTarget::vector(&mut venv)` or `EnvTarget::factory(&mut factory)` (built only when an episode needs it and closed after); the model is a borrowed `&Model`, a `&RemoteModel` or `RANDOM_SAMPLE` (the last two run on the session loop). A run borrows both: it never closes the model, closes the env only on `close_env`, and a model runs one run at a time (`RuntimeError` class). `RunHooks` (`on_run_start` with an `Arc<dyn RunContext>`, `on_episode_start`, `on_step` with a `StepEvent` carrying the observation and action, `on_episode_end`, `on_run_end`, which fires once also on an error) run on the thread that called a sync run, so a hook may make sync rlmesh calls; under an `_async` twin they run inside its future. `rlmesh::session` / `Model::session` return a `Session<'a>` that borrows the model and the env: `reset(seed, trial_index)`, `predict`, `step`, `run(SessionRunOptions)`, `done`, `contract`, `num_envs`, `selected_workflow_edition`, `run_context`, `reader`, `read`, `observation_roles`, `frame_sources`, `cancel_handle` and `close`, each I/O call with an `_async` twin; dropping it ends the open episode and releases what it made. A sync call made from async code fails with the `RuntimeError` class naming its twin.
- `View` on run and session options, with shorthand parsing, validation, terminal/HTTP display, pacing, skip/quit and hold; a local `Model::run` refuses a set view. `Recorder` records completed runs and live capture hooks, takes record snapshots (`WorkloadRecord`, `EpisodeRecord`, `MediaRef`), and exports a portable folder or ZIP; filesystem operations have async twins, and capture hooks retain shared state independently of the recorder handle.
- `RemoteEnv` and `RemoteVectorEnv` take `RemoteEnvOptions` (`address`, `host`, `port`, `path`, `transport`, `connect_timeout`, `request_timeout`, `workflow_edition`; a zero timeout is no timeout) and connect at `new`, with Gymnasium-shaped calls: `reset(seed, options)`, `step(action)`, `render(env_index)` decoding the frame to a uint8 tensor, `close()` (bounded, detaching on a lost peer, idempotent) and `shutdown(reason)`, each with an `_async` twin that runs on any executor. Spaces are built once per client, `info` carries `episode_ids` and `completed_episodes`, I/O after `close` is the `RuntimeError` class, `cancel_handle()` cancels a call, and dropping an unclosed client closes it. A session or run takes `&mut RemoteEnv` / `&mut RemoteVectorEnv` as its env. Endpoint tokens go in `api_key`; partial resets are a Rust-only extra (`ext::reset_lanes`).
- `RemoteModel` is an env-agnostic handle: `RemoteModel::new(RemoteModelOptions)` checks the address and timeouts without I/O (clones share it), and `session(env, SessionOptions)` / `session_async` dial the model and bind it to an address, an `EnvServer` or a borrowed `RemoteEnv`, pinning the env to the session's edition floor. An endpoint token goes in `RemoteModelOptions::api_key`.
- `rlmesh::describe(obj, DescribeOptions { kind, generated_at })` returns a describe envelope as `Metadata`, and `rlmesh::describe_json(obj, DescribeJsonOptions { kind, generated_at, served_env, workflow_edition })` its canonical string. `obj` is a `Describable`: `Describable::model::<P>()` reads a policy type's declarations without constructing it (a static `native_chunk` that construction would refuse is refused, `TypeError` or `ValueError` class), `Describable::env_factory::<F>()` default-constructs one factory per build, and `&Model` / `&mut factory` describe an instance. `Model::describe::<P>()` and `EnvFactoryExt::describe()` describe type declarations. A factory envelope carries the default branch's `env_spec` (or a badge whose `error_type` is the failure's error class), `env_tags`, `params` from `tag_params`, `variants.catalog`, and, for a branched factory, `env_contracts` with every branch's tags and spaces; a model envelope carries `model_spec`, `corners`, `native_chunk` and `params` from `LOAD_KEYS`; `target.qualname` is `rust:<type>`, `runtime` is the Rust host plus the edition offer, `DescribeKind` cross-checks the kind, and `rlmesh::ServedEnv` (`env`, `vector`, `lanes`, `From<&MadeEnv>`) replaces the default build. `EnvFactoryExt::serve` publishes this full envelope on its handshake, read off the env it serves.
- Workflow edition resolution: `rlmesh::current_workflow_edition()` is the bare `YYYY.MM` base to declare, and every native serve takes the call's own value, then `RLMESH_WORKFLOW_EDITION`, then the served peer's option, then the type's declaration (natives read no `pyproject.toml`); a blank value declares nothing, a set-but-blank variable floats deliberately, and an edition this build cannot run is a `ValueError`-class error. `RemoteEnv::selected_workflow_edition()` reports the edition the handshake selected. Warnings carry a category: `rlmesh::WarningCategory` (`UserWarning`, `RuntimeWarning`, `WorkflowEditionWarning`, with `name` and `is_subclass_of`), `rlmesh::Warning`, and `rlmesh::set_warning_handler`, whose failing handler fails the call that warned; by default each distinct warning prints once to stderr as `rlmesh: <Category>: <message>`.
- `rlmesh::build_info()` returns `rlmesh::BuildInfo` (`version`, `protocol_generation`, `workflow_edition`, `workflow_edition_base`, `supported_workflow_editions`, `build_cohort`, `build_source` as the `BuildSource` enum, and `git` as an `Option`), with a structured `Display` representation; `rlmesh::VERSION`, `DESCRIBE_METADATA_KEY` and `DESCRIBE_SCHEMA_VERSION` (an `i64`) join `ENV_RESET_OPTIONS_KEY` at the root.
- Remote env calls check closed state before subscribing to cancellation, returning `RuntimeError` without consuming an idle firing. Factory-backed sessions check busy state and cancellation before lazy `make`; pending cancellation skips construction, and reentrant calls during `make` return busy `RuntimeError`.
- Remote and session calls, including run completion hooks, synchronously check cancellation when completing their result processing. A firing before completion returns `Cancelled`, even when the polling watcher has not run; a retained run hook error still wins. A firing after completion remains pending when the token is idle.

#### C

The C API (`rlmesh.h`, ABI 5) exposes values, spaces, envs, models, runs and sessions through opaque handles and typed callbacks. Every new struct follows the ABI-5 sizing rules above; constructors transfer callback state only on success, and `free_user_data` runs once after the last library reference.

- `rlmesh_ext_unregister_entrypoint` removes a trusted entrypoint by transform identity, or any registration when `expected` is NULL. Existing routes retain their transforms, and foreign deleters can re-enter the registry safely.
- `rlmesh_ext_session_reset`, `_predict`, `_step`, `rlmesh_ext_remote_env_reset`, `_step` and `rlmesh_ext_remote_vector_env_reset`, `_step` take an explicit borrowed per-call cancellation token; NULL preserves the original call behavior.
- Factory serves can start in the background with `rlmesh_ext_env_factory_start` (C++ `rlmesh::ext::start`), returning an independently owned env server. Model serve options can disable signal handlers for embedding hosts. ABI-5 struct minima stay unchanged.
- Values and tensors: immutable, shareable `RLMeshValue` handles with all ten kinds, strict typed reads (`RLMESH_ERR_TYPE` for another kind), insertion-ordered dicts with length-bearing `RLMeshStr` keys (empty and embedded-NUL keys allowed) and composite constructors that retain their children. `RLMeshTensor` copies on construction, shares storage on clone, Value conversion and contiguous reshape, reports byte strides and read-only buffers, and makes an independent copy with `rlmesh_tensor_copy`.
- Versioned CPU DLPack exchange: `rlmesh_tensor_from_dlpack`, `rlmesh_tensor_to_dlpack` with `RLMeshToDlpackOptions` and `rlmesh_tensor_dlpack_device`. Imports copy and consume the producer only on success; read-only shared or writable copied exports retain their data and metadata after the source is freed. `rlmesh.h` vendors the complete upstream DLPack v1.0 header (Apache-2.0, license in `include/dlpack.LICENSE`), works in either include order with DLPack 1.x headers, and still compiles warning-free as C++98 under GCC and Clang.
- Stateful spaces: `RLMeshSpace` (with `RLMeshBox`, `RLMeshDiscrete` and `RLMeshDict` as typedefs of it) built with `rlmesh_box_new(low, high, shape, ndim, options, &out)`, `rlmesh_discrete_new(n, options, &out)` and `rlmesh_dict_new(keys, specs, n, &out)` (experimental MultiBinary, MultiDiscrete, Text and Tuple too), or from a spec with `rlmesh_space_new`, `rlmesh_*_from_spec` and `rlmesh_spaces_space_from_spec`; `rlmesh_space_seed` (a `uint64_t`, `NULL` draws one), `rlmesh_space_sample`, `rlmesh_space_contains`, `rlmesh_space_equals`, `rlmesh_space_repr`, `rlmesh_space_clone` (shares the sampler) and `rlmesh_space_free`. Bounds are typed `RLMeshBound`s (`rlmesh_bound_int`, `_uint`, `_float`, `_bool`) read back exactly with `rlmesh_box_low`/`_high`/`_bounds_kind`; `rlmesh_ext_box_elementwise_new` builds a per-element Box. Dicts are read with `rlmesh_dict_key_at`/`_value_at`/`_get`/`_len`/`_contains_key`. `RLMeshDType` (`RLMESH_DTYPE_FLOAT32`, ..., `rlmesh_dtype_str`) is taken by `RLMeshBoxOptions` and `RLMeshDiscreteOptions`; the spec readers `rlmesh_space_spec_kind`/`_shape`/`_dtype`/`_repr`/`_clone`/`_free` return `RLMeshSpaceKind` and the enum.
- Error class introspection: `rlmesh_last_error_class()` returns an `RLMeshErrorClass` (`RLMESH_ERROR_CLASS_RECOVERABLE_ENVIRONMENT_EXCEPTION`, `RLMESH_ERROR_CLASS_CONNECTION_ERROR`, ...), with `rlmesh_error_class_name` and `rlmesh_error_class_is_subclass` testing the class hierarchy. `rlmesh_last_error_code` and `rlmesh_last_error_code_str` read an environment or model error's code (`RLMeshErrorCode`, `RLMeshModelErrorCode`; `rlmesh_error_code_str`, `rlmesh_model_error_code_str`). New statuses `RLMESH_ERR_PROTOCOL` (9), `RLMESH_ERR_TYPE` (10), `RLMESH_ERR_RUNTIME` (11) and `RLMESH_ERR_OS` (12) join the existing ones, whose values are unchanged. A callback can fail with any of these classes: `rlmesh_callback_set_error_class(RLMESH_ERROR_CLASS_TYPE_ERROR, "bad observation")` makes the in-process call fail with that class (`ADAPTER_RESOLUTION_ERROR` included, returned as `RLMESH_ERR_INVALID_ARGUMENT`), while across the wire the peer still sees an environment or model failure; `rlmesh_callback_set_error(message, true)` fails one request as recoverable.
- `rlmesh_build_info(&info)` fills an `RLMeshBuildInfo` (`RLMESH_BUILD_INFO_INIT`, `_MIN_SIZE`; static strings, nothing to free), with `rlmesh_build_info_repr`, `RLMeshBuildSource` and `rlmesh_build_source_str`, `rlmesh_current_workflow_edition()`, and the `RLMESH_VERSION`, `RLMESH_DESCRIBE_METADATA_KEY`, `RLMESH_DESCRIBE_SCHEMA_VERSION` and `RLMESH_ENV_RESET_OPTIONS_KEY` macros. Warnings go through `rlmesh_set_warning_handler(fn, user_data, free_user_data)` with `RLMeshWarningCategory`, `rlmesh_warning_category_name` and `rlmesh_warning_category_is_subclass`.
- Env authoring and serving: separate `RLMeshEnv` and `RLMeshVectorEnv` handles from `rlmesh_env_new` / `rlmesh_vector_env_new` with Gymnasium-shaped callbacks (Value observations, typed info dicts) and copied attributes, and an `RLMeshEnvServer` from `rlmesh_env_server_new` (one or more scalar envs served as the lanes of one endpoint) or `rlmesh_env_server_new_vector`, with `start` for background serving, blocking `serve`, `wait` for completion and `shutdown` for draining (`serve` keeps lane 0 on the calling thread). `RLMeshServeOptions` uses seconds with explicit `has_*` fields. A server holds an exclusive lease on its envs, each env's `close` runs at most once, and freeing a server drains every C callback, even past a shutdown deadline. A failed callback reaches the client as `[INTERNAL] {op} failed: {message}`, an env with no id serves `"UnknownEnv-v1"`, and render accepts numeric images (any numeric image is cast to uint8; `[3, H, W]` and `[4, H, W]` encode too). The immutable `RLMeshEnvContract` (id, spaces, render mode, lane count, typed metadata, `to_dict`, repr) describes a served env, and `rlmesh_trial_index` reads a typed reset-options dict with an optional lane.
- Served env describe envelopes report the host's language, language standard and compiler: `RLMESH_EXT_ENV_SERVER_OPTIONS_INIT` fills `RLMeshExtEnvServerOptions.host_runtime_json` with what the header detects at compile time, and compilers appear under `runtime.toolchain` as `{"name":"gcc","version":"16.2"}` (`clang`, `gcc`, or `msvc`, with `major.minor` versions); `framework_versions` is populated only by explicit declarations, which can also override detection. `rlmesh_ext_env_server_describe_json` reads a server's envelope.
- `RLMeshEnvFactory` with `TagParam` lists and mutable `Variant` catalogs uses the facade's default binding, branch checks, metadata stamping and serving pipeline; factory hooks are exclusive and report re-entry as `RuntimeError`, free never closes the factory, and a reusable `RLMeshExtCancelToken` stops serving.
- `RLMeshModel` wraps a four-corner `RLMeshModelVtable` with per-corner context opt-in, checked load keys (`rlmesh_model_from_config`), the loaded native chunk, shared clones, hook overrides, `close` and `rlmesh_model_serve`. `RLMeshPredictContext` exposes the facade's episode state, holding owned `void*` values with C deleters. A served model or env resolves its workflow edition in order: `RLMeshServeOptions.workflow_edition` wins, else `RLMESH_WORKFLOW_EDITION` (a set-but-blank value floats deliberately), and a server that declares neither prints one `rlmesh: WorkflowEditionWarning: ...` line to stderr per process.

Accessors stay usable while a call or session borrows the client, `selected_workflow_edition` reads the session's pin, and reset, step, render, shutdown and close return typed values; vector buffers are capacity-checked before any I/O. Remote envs and models serve as run and session targets.

Factory serving publishes the same native identity.

Factory-backed sessions check busy state and cancellation before lazy `make`; pending cancellation skips construction, and reentrant calls during `make` return `RLMESH_ERR_RUNTIME`.

A firing before completion returns `RLMESH_ERR_CANCELLED`, subject to run hook error precedence; an idle firing after completion remains pending.

### Changed

#### Python

- Rotation conversions compute in f64 (0.1 rounded through f32), and a quaternion reorder (`quat_wxyz` to `quat_xyzw` and back) is a plain permutation that keeps the input's sign. 0.1 sent a reorder through a rotation matrix, which could flip the sign, unlike upstream eval clients (Isaac-GR00T's SimplerEnv client uses `np.roll`). Both can shift trajectories bit-for-bit against 0.1; success rates were unchanged across a 13-pair catalog parity table. A model that needs a canonical quaternion sign declares it in its spec.
- Internal and server-side failures raise `RLMeshException`, and protocol failures (a failed handshake, a malformed message, an invalid contract from the peer) raise `ProtocolException`, instead of a bare `RuntimeError`; a render frame that does not decode raises `ProtocolException` too. Both subclass `RuntimeError`, so existing catches keep matching.
- An env code `UNSUPPORTED` reaches Python as `"UNSUPPORTED"` instead of `"INTERNAL"`.
- A Python env server treats a raised exception as recoverable only when it is an `EnvironmentException` with a truthy `is_recoverable`; another exception carrying the attribute, such as `ModelException(is_recoverable=True)`, now ends the session like any other failure.
- `Model.run`'s hooks run on the thread that called `Model.run`, between the native loop's steps, instead of on a worker thread of the extension's blocking pool; they still run one at a time with the env idle, and the first exception still aborts the run. A hook's own sync rlmesh calls (a `RemoteModel` session's `predict`, a `RemoteEnv.render`) and thread-bound state (a GL context, `threading.local`) now see the caller's thread.
- When `Session.run` fails, the run's own exception is raised even if the model's `on_episode_end` for the last episode also fails, as `Model.run` does; before, that `on_episode_end` error replaced it. On success, an `on_run_end` error now wins over the last episode end's.
- A native `Model.run` step event without its action is an internal `RLMeshException` instead of a `StepEvent` whose `action` is `None`: `StepEvent.action` is never `None`.
- A `Model` subclass's declarations (a derivable `predict`, a class-level `native_chunk` with a chunk corner) are checked before `load()` runs, so a bad declaration no longer costs a full weight load.
- A wrapping `Model(policy)` reads its declarations from the policy: `allow_fusion` is the policy's (a wrapped policy that sets `allow_fusion = False` is no longer fused), and the wrapper's `allow_fusion`, `native_chunk` and `workflow_edition` attributes report the policy's. A wrapped bare callable keeps the defaults.
- A served model drops an env's per-episode context entries when that env's route is torn down (an evict-all `ResetAdapter` or a `ReleaseAdapter`), without firing `on_episode_end`, so episodes ended by teardown no longer leak until the 65,536-episode capacity refuses new ones.
- `Model.run` and `serve` warn `RuntimeWarning` (once per episode, with the session's text) when a model with no `native_chunk` returns a chunk shorter than the execution horizon, as a local session does; before they only logged it. Native warnings in a Python process now go through Python's `warnings` machinery.
- `rlmesh.trial_index(options)` returns `None` for an integral float outside `[-2**63, 2**63)` (`1e19`), as the native languages do, instead of an integer past int64.
- `RANDOM_SAMPLE` seeds the action-space sampler with each episode's reset seed, so a seeded run reproduces its actions; an episode without a seed keeps the running stream. Before, the sampler always drew from OS entropy.
- `Space.seed()` is annotated `-> int`: it always returned the seed it applied (one drawn from OS entropy for `seed=None`), never `None`. `Discrete`'s `dtype` is annotated with the three dtypes it accepts, `"int64"`, `"int32"` and `"uint8"`; the runtime check is unchanged.
- `ModelSpec.to_json()` and `EnvTags.to_json()` emit the shared compact, sorted UTF-8 JSON format every language emits. Parsed values are unchanged; older JSON remains readable.
- Adapter construction and `Adapter.serve_route` are labelled Internal; `transform_obs_value` and `transform_action_value` are labelled Bridge.
- `rlmesh check` warns on an env without `tags` instead of failing it: an untagged env runs against spec-less models; tags are what let the platform adapt a spec'd model to it.
- `RemoteEnv` and `RemoteVectorEnv` log a warning, once per client, when an env's own `info` key shadows a runtime-reserved one (`episode_ids`, `completed_episodes`). The env's value is still kept.
- The live viewer shows the env's first declared image role by default instead of its `render()` frame. The role rides the step response, while `render()` costs one more env round trip per drawn frame; `render` stays selectable, and `View(source="render")` asks for it.
- Adapter resolution errors for a missing role now suggest near matches among the roles the other side offers (`did you mean "x/goal_body"?`), and, when an `x/` role is involved, say that `x/` roles bind only to the identical string. The suggestion is only a hint: binding still matches roles exactly, and one registered role is never suggested for another. The zero-fill caution for an optional state input names the absent role and part (`zero-filled because the env offers no match for "proprio/eef_pos" (part "right_arm")`) instead of only counting components.
- `sanitize_metadata` is labelled Bridge (Python-only), and the `params` module with `Model.params` / `EnvFactory.params` is labelled Experimental.

#### All languages

- A lane endpoint served from Rust, C or C++ reports each range warning (`rlmesh.conformance.warning`) once per lane for the server's life, as a Python server does, instead of once for all lanes; a vector env still reports once for all its lanes.
- The Rust `run_model` quickstart uses `Model::run` with a `Policy` and public `RunOptions` instead of the internal binding runner, and reports the episode and step totals. It still connects to the paired `serve_env` example.
- The Rust crates are consolidated, and the workspace is versioned `0.2.0-alpha.0` because it no longer matches the published `0.1.0` crates. The v2 session is one crate, `rlmesh-session`, with `wire`, `spec`, `edge`, `record` (feature `record`), `gateway` (feature `gateway`, still the `rlmesh-gateway` binary), `lease` and `sdk` modules; `rlmesh-session-core` keeps the sans-IO core the browser build runs, and `rlmesh_session::{wire, spec}` re-export it. The facade gains `rlmesh::lockstep` (feature `lockstep`, formerly `rlmesh-gym`) and the live viewer as `rlmesh::viewer` (feature `viewer`, on by default); the recorder's AV1 writer is `rlmesh::recorder::video`. `rlmesh-sandbox` is part of the Python extension and no longer published. The hidden `rlmesh viewtest` command is gone.

### Fixed

#### Python

- Env and model servers send HTTP/2 keepalive pings every 30 s (10 s to answer): a dead peer is detected, and NAT mappings and proxies that count pings as traffic keep a Join stream that idles between episodes. Many L7 load balancers (AWS ALB among them) ignore pings, so their stream idle timeout must exceed the longest gap between predicts.

- A process that exits while a model is still serving (`serve` on a daemon thread) no longer dies with SIGSEGV during interpreter shutdown: the model is closed from an `atexit` hook, stopping the serve and firing its close hook, as an `EnvServer` left running already stops itself. A native thread that outlives the interpreter no longer attaches to it.

- Model run and session warnings identify the caller’s source location, including calls through the top-level run helper, so module warning filters apply to user code.

- `describe(rlmesh.Model(policy))` describes what `describe(policy)` does: the target qualname, the edition declaration, the `load` params, the variants, the predict corners and a class-level `native_chunk` come from the wrapped policy (only `model_spec` is the model's own). Before, they came from the `rlmesh.Model` wrapper class (`rlmesh._native:Model`, no corners). `describe(rlmesh.Model(predict_callable))` keeps the wrapper's model kind and reads its declarations from the callable.
- `describe` reads `native_chunk` from the class, never from an instance, so describing a `Model` subclass instance no longer reports a K that `load()` set from a checkpoint.
- `describe_json(..., served_env=[])` raises `ValueError` instead of `IndexError`.
- A `Model(policy)` wrapping a policy object reads its workflow edition from the policy's class (`type(policy).workflow_edition`) for `run`, `session` and `serve`, and, when that class declares none, warns once with `WorkflowEditionWarning` as a `Model` subclass does. Before, it read the `rlmesh.Model` wrapper's `None` and never warned. A `Model` wrapping a bare predict callable still floats quietly.
- `Model.serve(address, options=ServeOptions(workflow_edition=X))` declares `X` even when `RLMESH_WORKFLOW_EDITION` is set, as `EnvServer` and the method's own docstring already did: the options' edition is the serve call's own value. Before, the environment variable won.
- Native model batch and chunk-batch failures preserve `ModelException` identity, recoverability, and wire message text. Engine warnings run on the calling thread, point to the Python caller, and retain their original warning class under an `"error"` warnings filter.
- Concurrent model close waits behind already-admitted predicts and episode hooks in submission order.
- `EnvServer.shutdown()` called from inside one of the server's own env callbacks under `start()` triggers the drain and returns, as it already did under `serve()`; the owner's `wait()` or `shutdown()` reports the stop. Before, it waited on its own callback and failed with `serve failed: close timed out` after both 5 s caps. Under a foreground `serve()`, the same call marks the server stopped at once, so `wait()` succeeds there.
- A vector env served with `start()` runs every call on one dedicated thread for the server's life, as each lane already did, so a thread-bound vector env (a GL context) works there; before, its calls could hop threads on the blocking pool.
- A foreground `EnvServer.serve()` restores the process's SIGTERM disposition when it returns; before, its SIGTERM handler was never removed, so a later SIGTERM no longer ended the process.
- A run's `RunContext` carries the env contract (and decodes in the env's framework) when the target is a `SandboxEnv` or an address and the model resolves no route of its own (a served model, `Model(RANDOM_SAMPLE)`), so a hook's `event.read(role)`, the recorder's camera discovery and the live viewer work there too. The runtime's `SessionStartedEvent` carries the connected env's contract.
- An `rlmesh.Tensor` in an env's `info`, reset `options` or any other metadata is sent as the nested list of its elements, as a NumPy array is, and `sanitize_metadata` turns it into that list too; before, the codec raised `TypeError` and `sanitize_metadata` stringified it.
- An integer `Box` samples in its dtype's exact integer domain instead of through `float`: a `uint64` Box with bounds above 2^63 no longer saturates at 2^63 - 1, and `int64`/`uint64` bounds beyond 2^53 no longer round. Samples of integer Boxes whose bounds are exact as floats, and of bool Boxes, are unchanged.
- `Discrete(1, start=2**63 - 1).sample()` returns its sole member without overflowing. Box membership accepts ranges, generators, and `tolist()` wrappers and checks nested namedtuple shapes consistently.
- `spaces.Text` accepts `min_length=0` (and `max_length=0`), as Gymnasium does, so a Gymnasium `Text(min_length=0)` converts instead of failing; only negative lengths are rejected.
- `rlmesh.trial_index(options)` reads a NumPy integer.
- `rlmesh.run()` and `Session` read an episode's success the way the runtime does. Of `is_success`, `success`, and `task_success` in the final step's `info`, the first holding a bool, integer, or float decides; a string such as `"False"`, `None`, or a list is skipped instead of counting as success or ending the search. NumPy scalars and 0-d arrays count as their values.
- `RemoteEnv.step` reports `completed_episodes` in its `info` on every step (`0` mid-episode), as `RemoteVectorEnv.step` does; it used to appear only on the step that ended an episode.
- The `env_id` and `selected_workflow_edition` of a `RemoteEnv` or `RemoteVectorEnv`, and `RemoteVectorEnv.num_envs`, answer while another thread is inside a call on the same client; before, they raised `RuntimeError: Already borrowed`.
- `render(env_index=...)` above `2**32 - 1` raises `ValueError` before any request; before, the index was truncated and another lane was rendered.
- A `reset`, `step` or `render` that outlives its `request_timeout_seconds` always raises `TimeoutError`: a reply that arrives at or after the deadline is discarded, and the deadline sent to the server is rounded up to whole milliseconds. Before, a reply landing within the client's 100 ms check interval past the deadline was returned, and a server-side expiry could surface as `TimeoutError("[TIMEOUT] env.step timed out after ...")`.
- `RemoteModel(...)` raises `ValueError` for an address that does not parse or a negative or non-finite timeout, as `RemoteEnv` does; before, the handle was built and every `session()` raised it, for an address target after its env had been dialed. An empty remote TCP host defaults to `127.0.0.1`.
- A `RemoteModel.session(address)` whose model dial or handshake fails closes the env connection it dialed before raising, instead of leaving it to the garbage collector.
- `RemoteModel.session(env, workflow_edition=...)` declares that edition on the env connection it dials for an address or an `EnvServer`, as its docstring says, ahead of `RLMESH_WORKFLOW_EDITION` and the project; before, the dialed env resolved its own declaration and could be refused although the call named an edition it runs.
- Remote model prediction deadlines cover adapter resolution and pending episode cleanup as well as prediction itself.
- Ctrl-C during a served model's `predict` or route close (a `RemoteModel` session) raises `KeyboardInterrupt` promptly, as it does during an env call, instead of after the request returns.
- Importing `rlmesh` in an embedded interpreter that installed no signal handlers ignores SIGPIPE, as CPython itself does, so a peer that hangs up mid-write fails that write instead of killing the host process. A handler the host installed is left alone.
- Model run, session and serve resolution use the tolerant contract-tag reader: unknown, unreferenced env leaf kinds no longer fail a strict preflight.
- `adapters.tag(validate=True)` validates vector env tags against their single-lane observation and action spaces.
- Tag serialization failures raise `AdapterResolutionError` also with `validate=False`; metadata stays unchanged on failure.
- Unknown `State` and `Concat` dtypes fail at adapter resolution with `AdapterResolutionError`, before the first prediction.
- Advisories compare and hash by severity and message, including equality of `RunResult.advisories`. `Advisory.severity` is typed as `Literal["info", "caution"]` in the generated stub.
- Equal custom encodings sharing the same callbacks are inverse-checked once per resolve, including separately constructed equal values.
- A single `Previous(...)` model input retains `source="action"` when read back from dict or JSON; a nonzero initial fill no longer fails reconstruction as an observation-source state.
- Custom adapter inputs on the native model engine retain integer and boolean kinds, `None`, and tuples instead of coercing scalars to floats or tuples to lists.
- `rlmesh check`, `rlmesh check-image`, and `python -m rlmesh._describe --check` join an env's tags against its spaces, per contract branch, the way `rlmesh.serve` does at startup, so tags whose widths or space classes do not fit now fail the check instead of passing it and crashing the server. A contract branch without tags, or whose tags fail to load, fails, as the platform probe does.

#### C and C++

- Factory serves' describe envelopes report the caller's declared host runtime instead of always reporting C. Factory and ordinary env servers carry their endpoint's host language, version and frameworks in handshake PeerInfo, without changing process-wide identity.
- C output-buffer capacities use output parameter names, and tensor shape lengths use `shape_len`. C++ image helpers take `size` and `stride`, and the space constructor takes `spec`.
- C++ recorder add and capture options preserve an absent `config` separately from an explicitly empty configuration, including their `with_config` setters.

#### All languages

- Back-to-back environment sessions and runs no longer fail spuriously with an active-session refusal after the previous client closes, detaches, or is dropped. The server releases its Join slot before sending the Close reply, including for older clients. A new Join from the same process waits up to five seconds, bounded by its request timeout, for a dropped or detached client's stream to finish; a stream still draining after that and genuinely concurrent clients receive the active-session refusal.
- C callbacks reporting `TimeoutError` preserve their authored message through model and session calls instead of returning a fabricated zero-duration timeout.
- DLPack 1.0 exports requested with `copy=True` set the standard `IS_COPIED` flag as well as exposing writable, independent storage, and DLPack imports reject overflowing sizes and strides before accessing producer data.
- Model and env servers disable Nagle's algorithm on accepted TCP connections, which removed a ~40 ms stall on some env steps.
- Served model endpoints enforce `RLMESH_MODEL_ENDPOINT_TOKEN` when set, taking precedence over token options, and served env endpoints enforce `RLMESH_ENV_ENDPOINT_TOKEN` the same way. Empty or invalid environment values fail startup instead of disabling authentication, as does a token no client could send in an HTTP header (leading or trailing whitespace such as a secret file's trailing newline, or control or non-ASCII characters): the error names the variable and the problem, and the value is never trimmed.
- An endpoint token that cannot be sent in an HTTP header no longer locks every client out silently: a model or env server given one through its token option fails startup naming the problem, and a model or env client given one fails with an error naming the problem instead of `invalid address: invalid token`.
- Model and environment servers accept the endpoint token as `authorization: Bearer <token>` as well as the raw token.
- `Model.run()` presents `RLMESH_ENV_ENDPOINT_TOKEN` to the loopback env server it starts, so setting the variable does not lock the run out of its own env.

Environments tag what they emit (`ImageTag`, `StateTag`, `TextTag`, `Split`); models declare what they consume (`Image`, `State`, `Text`, `Concat`) and produce (`Action`, `Actuator`). Rotation conversions out of a matrix (`rot6d`, `euler_xyz`, any post-rotated source) to `axis_angle` go through the quaternion, so they stay exact near 180 degrees and for rotations as small as 1e-4 rad.

A model-side ad-hoc role the env does not answer is an `info` advisory, and a fabricated fill on an optional roled action is a `caution`.
- Per-predict context for stochastic and stateful models: the trailing `context` a predict corner declares carries `predict_index` (the re-plan ordinal within the episode), `predict_seed` (a reproducible mix of the episode seed and that ordinal, also computed by `rlmesh.predict_seed(episode_seed, predict_index)`), and a per-episode `state` dict that lives as long as the episode does. Batched corners receive one `PredictContext` per row (`BatchPredictContext`), and the Rust `PredictFn::predict_batch` and `predict_chunk_batch` receive row-aligned `EpisodeInfo`. The `Model` hook that fires when an episode ends, `on_episode_end(self, episode_id="")`, drops one episode's state and shares its name with the constructor callback and the runtime; a wrapped policy object's `reset()` is picked up as that hook. `RLMESH_EPISODE_CAPACITY` (default 65,536) caps the SDK's live episode store: a new episode past the cap is refused with an error naming the variable, and a live episode's state is never evicted, its prediction ordinal reset, or its end callback fired early to make room.

An env that does not declare the key never sees it. The runtime mints the ordinal for every episode it starts, from `RuntimeSessionSpec.trial_index_base` (0 by default), and reports it on episode events, summaries, and `EpisodeResult.trial` whether or not the env asked for it; `run(trial_index_base=)` / `Session.run(trial_index_base=)` pick the first ordinal, so a local eval walks the same states as a platform shard. Undeclared, the contract stays elastic: a short chunk replays as far as it goes and warns once. The horizon is bounded at 1024.

- Observation history on the wire, so a frame-stacked model works with action chunking on the native and served paths. The runtime declares on `ResolveAdapter` that it delivers history (`delivers_history`), a stacked route answers the inputs that hold a window (`ResolveAdapterResponse.history`), and each later `Predict` carries the env steps the runtime executed from a replayed chunk as `PredictRequest.history` rows, oldest first, stamped with a per-group `step` counter that the engine holds to consecutive values per episode (a gap or repeat fails the predict rather than stacking a wrong window). The four proto fields are additive; a runtime that never offers history and a model that never answers it exchange the same bytes as without them. `Model.run`, a served model under the Rust runtime driver, and `RemoteModel` all deliver it, and the Python session ticks its window locally. A frame-stacked adapter at `execution_horizon > 1` on the native engine is refused only when the runtime did not offer observation history, and the error says so. The `history.rows` telemetry metric counts rows per predict.

Routes with no stacked input are never charged. The served resolve, which names no lanes, validates one lane per route and refuses a stacked route whose windows would exceed the budget.

A part is any identifier the env and the model agree on exactly; `LEFT_ARM`, `RIGHT_ARM`, `HEAD`, `TORSO`, `BASE`, `LEFT_LEG`, and `RIGHT_LEG` (`adapt.PARTS`) are the suggested spellings, not a registry. A model that names a part binds only that leaf; one that names none binds the env's only leaf of the role under any part with an `info`, and fails naming the parts when there are several. Duplicate detection in `Split`, `Action`, and `EnvTags` is keyed by `(role, part)`, so one `action/joint_pos` per arm is a valid layout. The kind prefixes `image/`, `proprio/`, `text/`, `action/`, and `command/` are a closed set enforced at authoring and resolve. - Docs: the compatibility page states the sticky edition guarantee, the WANT/CAN negotiation, the runtime-as-interpreter and dual-stack rules, the 256 MiB cap and retained-edition contract, the cross-version matrix, and a release-anchored roadmap.
- `rlmesh-proto` ships its retained workflow-edition list (`supported_editions.txt`, current edition first) so a crate built from crates.io offers every retained edition, not just its own; the build fails if the file drifts from `rlmesh.toml`, `bump_version.py --sync-editions` regenerates it, and `policy:check` enforces it.
- The runtime records each served peer's ceiling (the highest edition both implement, the wire-v1 dtypes, capabilities, and the message cap) on `RuntimeSessionSpec` as `env_ceiling` / `model_ceiling`, exposed by `RemoteModel::ceiling()`.
- A `RelayPolicy` seam (`RefusingRelayPolicy` by default, `RuntimeDriver::with_relay_policy`) checks the env contract, observations, and actions against the target leg's ceiling; a converting policy can rewrite leaves and attach an advisory, which reaches `RuntimeReport.advisories`, a `relay_advisory` hook, and `RunResult.advisories` in Python. `Advisory` lives in `rlmesh-spaces` and is re-exported from `rlmesh-adapters`.
- Declared construction parameters: `EnvFactory.params = ParamSpec(Param(...))` validates `make()` arguments, `enumerate_variants()` lists a factory's concrete sub-environments, and `describe()`/`describe_json()`/`python -m rlmesh._describe` emit a JSON metadata envelope without loading a model (an env's spaces are read off one representative instance); a model envelope reports the predict `corners` the class actually defines, introspected from the code that ships rather than declared. `python -m rlmesh._describe --check IMAGE` validates a built image's rlmesh labels locally, the way the platform probe will, before pushing, and exits nonzero on a failure so it can gate a push in CI: packaged checkpoint declarations must be well-formed (DNS-label names, a `uri` per entry, a single default), a present `dev.rlmesh.describe` label gets the same class-level checks as `rlmesh check`, and a missing one is reported as not checked, since the platform reads describe off the `rlmesh.serve` handshake.
- A live debug viewer: pass `view="terminal"`, `view="http:9000"`, or `view="both"` to `session()` (or to the module-level `run()` for a served handle), or configure `rlmesh.View(...)`. It is best-effort and never breaks an eval.
- Record eval runs to a portable bundle for upload: `rlmesh.Recorder` accumulates per-episode metrics with `add()` (from any `RunResult`) or `capture()` (live `RunHooks` on the session path) and writes an `rlmesh.result.v1` folder or zip with `export()`. On the session path it records the same sources the live viewer offers (the env's `render()` frame plus every declared image role), each to its own AV1 `.mp4`, encoded in process (pure Rust, no ffmpeg or extra dependency; `Recorder(fps=, quality=)` set playback rate and size/fidelity); env-produced video files are carried into the bundle by path. Capture is best-effort: a source that fails to read or encode is dropped with a warning and never aborts the eval.
- `rlmesh.sanitize_metadata()` coerces a third-party sim's rich `info` objects into wire-safe metadata, and connection failures name the address and the likely fix.
- Client timeouts: `RemoteEnv`, `RemoteVectorEnv`, and `RemoteModel` accept `connect_timeout_seconds` and `request_timeout_seconds`, so a hung peer fails with a `TimeoutError` instead of blocking forever.
- Fail-loud argument handling: a parameter that cannot be honored (`instruction=` on a served model, an unknown `vectorization_mode`, a conflicting CLI flag) raises with a directive error instead of being silently ignored.
- Self-explanatory predict failures: when a model's `predict` raises, the error is annotated with the adapter-assembled input signature (key → dtype/shape), both in local `run()` loops and across the wire from a served model, so a shape mismatch names what the model was actually handed.
- Managed-platform sign-in from the CLI: `rlmesh login` (RFC 8628 device flow), `rlmesh logout`, `rlmesh whoami`, and `rlmesh registry login` (registers the bundled `docker-credential-rlmesh` helper, so docker fetches a fresh short-lived token per pull/push, and hands the registry host to the profile that logged in most recently), with named profiles (`rlmesh profile use`/`list`/`remove`, `--profile`, `RLMESH_PROFILE`) that each fall back to the hosted platform URL, and credentials held in the OS keychain with a 0600 file fallback. `rlmesh org list` shows the organizations the account belongs to, marking the active one and each organization's registry namespace (or that it is not provisioned yet), and `rlmesh org switch` re-issues the profile's session against another one, failing loudly with the organization the platform kept active if the switch did not take.
- The CLI has no built-in identity provider: a platform whose `/v1/info` does not advertise `deviceAuthorizationEndpoint` and `tokenEndpoint` cannot be signed in to, the platform URL itself must be https (loopback excepted), and the token endpoint's host is pinned per profile at sign-in so a later `/v1/info` cannot redirect a stored refresh token. Identity (email, display name, organization) comes from the platform's `/v1/me`, never from provider-specific fields on the token response, and `rlmesh login` reports a platform that cannot confirm the identity.
- The CLI reuses its access token until a minute before the `exp` claim and refreshes only then, under a per-profile lock that re-reads the credential store after acquiring it, so `rlmesh token`, `rlmesh eval`, and every docker pull cost no identity-provider round trip and concurrent commands rotate the single-use refresh token once. A request the platform still rejects is retried once after a forced refresh.
- Managed-platform evaluations from the signed-in session: `rlmesh eval submit` (with `--preview` and `--wait`), `rlmesh eval list`, `rlmesh eval get`, `rlmesh eval wait`, and `rlmesh eval cancel`; `rlmesh token` prints a fresh access token for scripts; and `rlmesh.platform.Client` wraps the same routes from Python with `scenario_tasks()` to expand a scenario group into tasks.
- Build identity: `rlmesh.build_info()` returns the native core's build identity as a frozen `BuildInfo` (`version`, `protocol_generation`, `workflow_edition`, `workflow_edition_base`, `build_cohort`, `build_source`, `git`), and it and `rlmesh version` report the workflow edition of the native core: the sealed `YYYY.MM` name on a release build, a cohort-suffixed name (`YYYY.MM-<prerelease>` / `YYYY.MM-dev.<git>`) on prerelease and source builds. `rlmesh.__build__` is a deprecated alias of `build_info().workflow_edition`.
- Runtime hook events `ObservationEmittedEvent` and `ActionReceivedEvent` carry `raw_observation` / `raw_action` alongside the transformed payload, so hooks can record both the pre- and post-transform leaves per step.
- `StepCompletedEvent` and reset `ObservationEmittedEvent`s carry the env's per-step / reset `infos` map, so hooks see dense rewards, success flags, and task diagnostics as they happen rather than only `final_info` at episode end. Under `NEXT_STEP` autoreset the roll step's `infos` land on the new episode's first `ObservationEmittedEvent`, not on the old episode's `StepCompletedEvent`, and `episode_completed` is the last event a hook receives under an episode id: it fires at the roll, after the ended lane's post-end observation and the autoreset step's event, mirroring the model side (the last predict under an id precedes its `on_episode_end`).
- `StepCompletedEvent` carries per-lane `terminated` / `truncated` (env-reported or a runtime cap, known at the step itself) and a per-lane `autoreset_roll` mask (lanes roll independently under `NEXT_STEP`), so a hook learns how a step ended without waiting for `episode_completed`. The `rlmesh` crate re-exports `RuntimeHooks` and the per-episode events, and `ModelWorker::run_local_hooked_async` drives a local session with a hook implementation.
- The recorder captures on `Model.run` as well as on the session loop: image roles always, and the env's `render()` frame for a local env object; a vector env is refused unless `cameras=[]`.
- `EpisodeStartedEvent` and `EpisodeCompletedEvent` carry the episode's `seed` (`None` when the runtime sent no per-episode seed, e.g. an env-owned `NEXT_STEP` autoreset), so hooks can record it from episode start.
- Gym vector envs served with `num_envs > 1` report each autoreset episode's seed as `info["seed"]`, derived from the lane's last explicit seed, on both the registry `make_vec` path and the factory fan-out path.
- Decomposable endpoint timing: every env and model response carries the split of its `endpoint_total_ns` into wire decode, the implementation's own work, and wire encode, and a model response adds the wait before its predict handler ran (from arrival to handler entry, excluding decode) plus the slots the endpoint had taken. An env response adds its env-lock wait the same way. The runtime records them as the `endpoint.decode`, `endpoint.user`, `endpoint.encode`, `endpoint.queue`, and `predict.in_flight` metrics, so a slow step can be attributed to serialization, user code, or queueing without attaching a profiler. A peer that does not stamp them is unchanged. The phase-summary log is enabled by `RLMESH_PROFILE_PHASES`; `RLMESH_PROFILE` also enables it when it reads as a boolean, but it primarily names the CLI's credential profile.
- Driver telemetry records each loop iteration's wall clock (`runner.round`), bracketing the full predict -> step -> transform body, so subtracting the per-op rows yields the driver's own residual overhead.
- `RunResult.telemetry` surfaces the run's aggregated timing/size telemetry on the `Model.run` native loop: one `TelemetryRow` per measured op/metric series (count, avg, p50/p95/p99, unit), with `result.format_telemetry()` rendering the table, so where an eval's time went is a printed property of the result, not a log to capture.
- The adapter engine measures its own share of each predict (observation assembly plus action apply), reported as `adapter_ns` on the model response and recorded as the `predict.adapter` metric (a sub-span of `endpoint.user`, so the model's own forward is the difference), on both the served endpoint and the in-process `Model.run` path.
- The engine reports the per-episode adapter state it is holding (episodes with live frame-stack windows and the bytes they occupy, summed across routes), recorded per predict as the `held.episodes` and `held.bytes` metrics, so unbounded episode-state growth (or an eviction that stopped firing) is visible as a trend instead of an OOM.
- A `lane_skew_ns` scalar on the env response and a matching `lane.skew` metric, for a vector env that times its own lanes: its slowest lane minus its median lane, one series no matter how many lanes it runs, so one pathologically slow lane can show up in p95/p99 instead of merely blurring the `env.step` aggregate. No in-tree env stamps it yet (the built-in Gymnasium vectorization hands the lane loop to Gymnasium), so the series stays empty until a lane-timing env does; a Rust `VectorEnv` can compute it with `rlmesh::env::lane_skew_ns` over a scratch buffer of per-lane durations.
- Async inference: `RuntimeDriver::with_prefetch(model, lead)` predicts the next action chunk on a second model handle while the current chunk's replay frames execute, firing when `lead` frames remain. The prefetched chunk is conditioned on an observation up to `lead` steps stale, so runs reflect deployment-realistic async timing and are not comparable to the synchronous predict-then-step loop; a chunk prefetched across an episode boundary is discarded. On a route that negotiated observation history the prefetched request carries the rows buffered so far and predicts from an observation of its own, so every env step still reaches the model exactly once. Opt-in: `RuntimeDriver::with_prefetch(lead)` in Rust, `prefetch_lead=` (keyword-only, default 0) on `Model.run()` and `rlmesh.run()` in Python; a negative lead is a `ValueError`, and the session loop and a served handle refuse a non-zero lead rather than faking it.
- Negotiated workflow editions content-pinned to the sealed `2026.06` edition spec, exact-match `rlmesh-wire-v1` protocol generation, and a per-lane `NEXT_STEP` autoreset contract for vector environments.
- Batched leaf-slab encode and decode on the wire parallelizes past 64KB, speeding up large batched observation and action payloads.
- Image adapters run as typed kernels: the 180° rotation, the uint8 to float32 normalisation, the HWC to CHW transpose, and a pad to the frame's own size bypass the dtype-generic scalar codec, and a camera plan that ends in a normalised float32 CHW tensor (the shape every vision policy asks for) runs as one fused pass from the raw bytes. Output is byte-identical to the generic codec's; a 256×256×3 frame costs about a sixth of what the generic path does.
- A fused grouped predict assembles its groups' inputs and applies their returned action chunks in parallel, one route per thread, when every group names a distinct route and no plan runs a Python custom transform (otherwise it stays sequential); results keep request order and the per-route entry locks guard each route's buffers, so the `predict.adapter` share of a served model's handler time is not serial across a batch's lanes.
- `rlmesh whoami --json`, `rlmesh org list --json`, and `rlmesh profile list --json` for scripts, and `expiresAt` on `rlmesh token --json`, so nothing has to scrape the human output.
- `RLMESH_API_KEY` (with `RLMESH_PLATFORM_URL`) drives `rlmesh token`, `rlmesh eval`, and `rlmesh whoami` without a browser sign-in, matching `rlmesh.platform.Client`; `RLMESH_CONFIG_DIR`, `RLMESH_DATA_DIR`, and `RLMESH_KEYCHAIN=off` confine the CLI's files and keep the OS keychain out, for CI runners and containers.
- `rlmesh logout` asks the platform to end the session (`DELETE /v1/me/session`) before deleting the local credential, so the refresh token stops working server-side too; a platform without the route still signs out locally.
- A CLI reference page covering every command, exit code, environment variable, file, JSON output, and the contract a platform must serve to be driven by the CLI.
- `rlmesh check MODULE:CLASS`, `rlmesh check-image IMAGE`, and `rlmesh describe MODULE:CLASS [--label]`: pre-push checks that sort what they find into failed, warnings, and not checked, exiting 1 only on a failure. `check` runs the describe on a class and fails on a model without a `spec`, an env without `tags`, a spec that does not resolve, or an edition declaration the build cannot run, reporting an env that needs a GPU or assets to build as not checked; `check-image` reads `docker image inspect` and checks the `rlmesh.serve` command, `--env`, a baked `--address`, `EXPOSE 50051`, `linux/amd64`, the rlmesh labels, and whether the image's rlmesh shares a workflow edition with the target platform (`--platform-editions` / `--platform-version`), negotiated the way the runtime does; `describe --label` prints the `dev.rlmesh.describe` value for a custom-entrypoint image, to be run inside the built image (`docker run --rm --entrypoint rlmesh IMAGE describe ... --label`) since the envelope records the machine it ran on and a label generated off linux fails admission, which `check-image` reports too.
- The describe envelope's `runtime` block advertises the edition handshake under the wire's names: `protocol_generation`, `supported_workflow_editions`, and `preferred_workflow_edition`, and `rlmesh.build_info().supported_workflow_editions` lists the editions a build can drive.
- `python -m rlmesh.serve` warns at startup when the served model declares no `spec`: the managed probe cannot synthesize inputs for it.
