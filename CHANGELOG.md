# Changelog

All notable changes to RLMesh are documented here. This changelog tracks the `rlmesh` Python package on PyPI. The Rust crates are internal implementation detail and currently carry no separate user stability promise.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/2.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.1.0] - 2026-09-22

RLMesh connects models to environments across process, dependency, and machine boundaries with a Gymnasium-style API. This release seals the `2026.06` behavioral contract and commits to retaining `rlmesh-wire-v1`. Declare the edition a model or environment was authored against to keep its behavior across package upgrades. The runtime selects a shared edition and refuses interactions a peer cannot express; see the compatibility policy for the contract and its current test coverage.

### Added

- `Model.from_config(**config)`: build an authored `Model` subclass with `load(**config)`, the keywords validated against `load`'s signature and the declared `params` (`ParamError` before any weights load), `load` run exactly once; the served binding (`RLMESH_MAKE_KWARGS`) takes the same path. A framework base class with no predict corner of its own refuses it.
- Sticky workflow-edition declarations: a participant writes down the edition it was authored against and keeps it across rlmesh upgrades (the NixOS `stateVersion` model). Declare it, highest surface first, with `run(workflow_edition=)` / `session(workflow_edition=)`, `RLMESH_WORKFLOW_EDITION`, `ServeOptions(workflow_edition=)` / `--workflow-edition`, `EnvFactory.workflow_edition` / `Model.workflow_edition`, or `[tool.rlmesh] workflow_edition` in `pyproject.toml`; an empty `RLMESH_WORKFLOW_EDITION` declares nothing deliberately and ends resolution there, and declaring nothing at all floats to this build's newest edition and says so once per process, at the caller's line. An edition this build cannot run a session at is refused where it was written, not at the first connection.
- WANT/CAN edition negotiation: every handshake carries the declaration as `preferred_workflow_edition` (an additive field on `HandshakeRequest` and `HandshakeResponse`; `rlmesh-wire-v1` is unchanged and a peer that sends none is read exactly as before) next to the editions the build can drive, and the runtime runs the session at the highest edition all of env, model, and runtime support that every declaration admits -- a bare base admits every cohort of itself, a cohort spelling uses the full edition ordering as its ceiling -- refusing cleanly before any Join stream opens, naming each tier's declaration and supported set, when there is none. A served-model session declares on its model leg the same edition its env leg does, and hands the model client the env's real handshake offer, so a refusal never attributes one tier's value to another.
- The runtime now pins the env to the session edition: `ConfigureEnvRequest.selected_workflow_edition` is sent as the first Join message and acked before the first Reset (a served-model session pins both legs to the three-way floor); a served env records the pin and reports conformance warnings under that edition's reserved key, falling back to its current edition for runtimes that send none.
- The editions a build can drive are its retained list, generated from `rlmesh.toml`'s `supported_editions` and offered and accepted from that one source, and the negotiated edition is a typed `Edition` in the runtime with a per-edition defaults table, so a sealed edition's behavior is read from its row rather than from scattered constants.
- `rlmesh.current_workflow_edition()` reports the bare `YYYY.MM` edition this build runs at (`"2026.06"`), the same on a release and on a prerelease or source build, and is the value to paste into a declaration; `rlmesh.build_info().workflow_edition` reports the build's exact spelling, which is also accepted as a declaration when you mean to pin to one moving build.
- `RemoteEnv.selected_workflow_edition`, `RemoteVectorEnv.selected_workflow_edition`, `SandboxEnv.selected_workflow_edition`, `SandboxVectorEnv.selected_workflow_edition`, and `Session.selected_workflow_edition` report the edition a connection or session settled on, in the spelling the peers agreed; `workflow_edition` everywhere means what this peer declares.
- A cross-version matrix, `mise run test:crossver`, drives this tree against the pinned published wheel on both legs in both directions and asserts the handshake, the negotiated edition, and the refusal of an unknown edition and a forged protocol generation on each build; cells that need a second sealed edition are listed as pending rather than dropped.
- Serve Gymnasium-style environments and drive them with `reset`, `step`, `render`, and `close` over local or remote gRPC transports: `EnvServer`, `RemoteEnv`, `RemoteVectorEnv`, and `python -m rlmesh.serve` as a universal container entrypoint.
- Lane serving: `EnvServer([env, ...])` (or `RLMESH_NUM_ENVS=N` on a prebuilt image) hosts N independent copies of a scalar env on one endpoint. Each lane runs on its own thread. The endpoint advertises `subset_step`, `StepRequest.env_indices` and partial-width `StepResponse`s are honored, and the runtime driver treats each lane as its own reset/predict/step loop over one multiplexed Join stream, so lanes reset and step at their own pace while every episode's seed and index come from a route-global slot counter; lanes waiting for a prediction share one grouped predict on a model with a batched corner (`PredictScheduler`, one fused forward) and otherwise each predict on their own, applied as it lands, so a slow prediction on one lane never holds another. A single env is the one-lane case of the same server.
- Evaluate models locally, against a remote server, or inside a sandbox: `Model`, `RemoteModel`, and `SandboxModel`, with `run()` for whole evals and `session()`/`Session` for manual `reset`/`predict`/`step` control.
- Tag-driven IO adapters that resolve environment tags against model specs at runtime. Environments tag what they emit (`ImageTag`, `StateTag`, `TextTag`, `Split`); models declare what they consume (`Image`, `State`, `Text`, `Concat`) and produce (`Action`, `Actuator`). Conversions cover rotation accept-sets, custom rotation encodings (`CustomEncoding`, wire-portable in published specs), image `fit` and `normalize` ranges, channel validation, optional cameras, frame stacking, per-actuator `clip`/`scale`/`invert`/`threshold`, and role-less actuators; `adapter.explain()` prints the chosen transforms and `adapter.advisories()` surfaces severity-tiered data-loss notes (`info` for benign hints, `caution` when the adapter substituted or fabricated model-visible data).
- Roles `ACTION_EEF_POS`, `ACTION_EEF_ROT`, `ACTION_JOINT_POS_2`, and `IMAGE_WRIST_2`, with their `_2` mirrors, so an end-effector pose action and a second wrist camera bind by role instead of by ad-hoc name. A model-side ad-hoc role the env does not answer is an `info` advisory, a fabricated fill on an optional roled action is a `caution`, and a `_2` camera role never rebinds to an env's only camera.
- Per-predict context for stochastic and stateful models: the trailing `context` a predict corner declares now carries `predict_index` (the re-plan ordinal within the episode), `predict_seed` (a reproducible mix of the episode seed and that ordinal, also computed by `rlmesh.predict_seed(episode_seed, predict_index)`), and a per-episode `state` dict that lives as long as the episode does. Batched corners receive one `PredictContext` per row (`BatchPredictContext`), `Model.on_episode_end(episode_id)` drops one episode's state, and the SDK refuses a new episode past 65,536 live ones (`RLMESH_EPISODE_CAPACITY`) rather than evicting live state.
- Trial ordinals for environments: `EnvFactory.reset_options = ("trial_index",)` opts an env into receiving the runtime's 0-based trial ordinal as `reset(options={"trial_index": k})`, read with `rlmesh.trial_index(options)`. An env that does not declare the key never sees it. The runtime mints the ordinal for every episode it starts, from `RuntimeSessionSpec.trial_index_base` (0 by default), and reports it on episode events, summaries, and `EpisodeResult.trial` whether or not the env asked for it; `run(trial_index_base=)` / `Session.run(trial_index_base=)` pick the first ordinal, so a local eval walks the same states as a platform shard. A reset that restarts several lanes of a lane-served env now delivers each lane its own ordinal rather than the whole list, so `rlmesh.trial_index(options)` reads an integer on every lane. The encoding is one Rust implementation shared by the driver and external probers, exported as `rlmesh_runtime::{reset_options_for, declares_reset_option, TRIAL_INDEX_OPTION}`, so a second caller cannot drift from what the driver sends.
- Declared chunk length: a model with a fixed chunk sets `native_chunk = K`. The runtime then refuses an `execution_horizon` above K when the adapter resolves and fails a predict whose chunk is not exactly K long, instead of quietly re-planning every K steps of an H-step plan. Undeclared, the contract stays elastic: a short chunk replays as far as it goes and warns once. The horizon is bounded at 1024.
- Image resample kernels `bicubic_aa`, `lanczos3_aa`, and `area` alongside `bilinear` and `bilinear_aa`, each anchored to Pillow and OpenCV within one 8-bit step, including the clamp Pillow applies between its two passes.
- Image spec fields `crop`, `crop_area`, `crop_mode`, `channel_order`, `jpeg_quality`, `render`, `offsets`, `stride`, and `stack_pad`, all keyword-only after `stack` and omitted from a published spec when default. `render` asserts the camera resolution the model was trained against rather than requesting one, and a bound camera that disagrees is a `RenderMismatch` at resolve. The jpeg round-trip is baseline 4:2:0 through `jpeg-encoder`, forced explicitly because that crate switches to 4:4:4 above quality 90; the IJG acknowledgment ships in the wheel notices.
- Frame windows in the core engine: `Adapter.observe`, `history_keys`, and `history_windows` keep a stacked model's window per episode, and chunk replay ticks it on every replayed step, so the model sees the same payloads at every execution horizon. On the native and served paths the runtime negotiates this at resolve (`delivers_history`) and carries each replayed step's observation to the model as `PredictRequest.history` rows with a step counter the model holds to consecutive values, so a stacked model works at any `execution_horizon` there too; a served model advertises `rlmesh.model.observation_history.v1`.
- State geometry: a `CustomEncoding` can sit at any offset of a concatenated state and every piece records its width, which apply asserts. `Constant(dim=, fill=)` parts and `State(fill=)` declare a filler that never reads as fabricated data; `post_rotate` (with an exact `Rotation.from_matrix`), `scale`, and `offset` transform a piece after decoding.
- Body parts: `part=` on `ImageTag`, `StateTag`, `Field`, `Actuator`, `Image`, and `State`/`Concat` parts names where a role repeats on a body, matched as an identity key. A model that names a part binds only that leaf; one that names none binds the env's only leaf of the role under any part with an `info`, and fails naming the parts when there are several. Duplicate detection in `Split`, `Action`, and `EnvTags` is keyed by `(role, part)`, so one `action/joint_pos` per arm is a valid layout. The registered parts are `LEFT_ARM`, `RIGHT_ARM`, `ARM_2`, `HEAD`, `TORSO`, `BASE`, `LEFT_LEG`, and `RIGHT_LEG` (`adapt.PARTS`), governed like roles: an ad-hoc part draws the authoring nudge, the strict publish tier rejects it, and `x/` escapes. The ten `_2` roles are now the legacy spelling of the base role under `part="arm_2"` and bind each other; the kind prefixes `image/`, `proprio/`, `text/`, `action/`, and `command/` are a closed set enforced at authoring and resolve. `explain()` shows a bound part as a `#part` suffix.
- Axis labels: `labels=` on `StateTag`, `Field`, `Actuator`, and `State`/`Concat` parts names the joints of a vector in that side's own order, and the resolver aligns the two sides by name, so a checkpoint trained in Isaac Lab joint order resolves against a Unitree SDK-order environment as a derived permutation (`explain()` prints `perm[3,4,5,0,1,2,9,10,11,6,7,8]`) and a model that names a subset selects it on the observation side and, against an `optional` env actuator, drives those axes while the rest take the actuator's `fill`. A labeled model against an unlabeled env, or a label the env lacks, is a `LabelMismatch`. `scale` and `offset` on a `State` part and an `Actuator` (which gains `offset`) accept a per-axis sequence, serialized as `axis_scale`/`axis_offset`, and `fill` on an optional labeled env actuator as `axis_fill`; `explain()` prints them as `label:value`. The joint tuples ship as data in `rlmesh.adapters.embodiments` (`GO2`, `G1_29DOF`, `FRANKA_PANDA`, `UR5E`, also exported from `rlmesh.adapters`); a tuple matching no profile on a joint role draws an `unknown_labels` nudge, and the `require_labels` publish tier (`--require-labels`) requires labels from a profile on every joint-role leaf; labels on any other role (a wrench's axes) are never held to a profile.
- Body roles and projected gravity: `BASE_ANG_VEL` (`proprio/base_ang_vel`), `BASE_ROT` (`proprio/base_rot`) and `COMMAND_BASE_VEL` (`command/base_vel`, the first role under the `command/` kind) register the floating base's gyro, orientation and velocity setpoint, all framed. A model reads the orientation as projected gravity with `encoding="gravity_xyz"` (`R_world_from_base^T · (0, 0, -1)`, 3 wide): any rotation encoding converts into it and nothing converts out of it, so an env publishing `gravity_xyz` binds only a model that reads it, and a `post_rotate` or an actuator naming it is a codec error. `provenance=` on `StateTag`, `Field` and `State`/`Concat` parts (`"sensed"`, `"estimated"`, `"privileged"`; a model may accept a sequence) says where a state leaf's numbers come from and follows the frame rules, with a disagreement a `ProvenanceMismatch`; it is part of the env leaf's identity, so a simulator may publish one role as its truth and as its estimate, and a model that pins none against both is `Ambiguous`. `State`/`Concat` gain a container `clip=(low, high)` applied to the assembled vector before `pad_to`. `explain()` prints `#sensed` and `clip[-100.0,100.0]`.
- End-effector wrench: `EEF_WRENCH` (`proprio/eef_wrench`) registers the six-axis force/torque a wrist sensor reads, force first, 6 wide and framed; the frame vocabulary gains `tool`, the frame attached to the end effector, so a wrist-mounted sensor (`frame="tool"`, `provenance="sensed"`) and a controller's estimate (`frame="robot_base"`, `provenance="estimated"`) are different leaves of one role and a model binds the one it was trained on. Its `labels` (`fx`..`tz`) name its own axes and are never held to an embodiment profile.
- A `model.reset_adapter` telemetry row: the runtime driver records `rpc.total` for every eviction RPC it awaits, so the time a model spends ending episodes shows up in the runner's windows next to `model.predict` instead of only in the gap between episodes.
- The frame-window budget (`RLMESH_FRAME_HISTORY_LIMIT_BYTES`, default 2 GiB) now bounds the whole model endpoint rather than one route at a time: a predict that would open windows for a new lane is refused while every route's live lanes, charged at their full window size, would exceed it. Routes with no stacked input are never charged. The served resolve, which names no lanes, still validates one lane per route.
- `RLMESH_EPISODE_CAPACITY` (default 65,536) caps the Python SDK's live episode store. A new episode past the cap is refused with an error naming the variable; the store no longer evicts a live episode's state, resets its prediction ordinal, or fires its end callback early to make room.
- Previous action: `adapt.Previous(role, part=None, fill=0.0)`, a `State`/`Concat` part with `source="action"`, reads the model's own output actuator of the same role and part back as the raw action executed at the previous step, in model order and before the actuator's affine, with `fill` before an episode's first action. It binds the spec's own actuator (none is a `MissingRole`), `labels` select from the actuator's labels, and an env observation tagged under `action/` is an `ActionRoleOnObservation` join error. Every executed action is recorded under its step at every replay site (the served engine per chunk frame and lane, `RemoteModel`'s replay through the history rows, the Python session and `Adapter.transform_action` with `Adapter.observe` counting a replayed step), an observation whose previous step recorded none fails loudly, and a route with the part negotiates observation history like a stacked one, so the runtime delivers replayed steps and a prefetched predict carries the rows buffered so far. `explain()` prints `previous action/joint_pos (fill 0.0)`.
- Coordinate frames: `frame=` on `StateTag`, `Field`, `State`, and `Actuator`, and `reference="current"` or `"target"` on delta actuators. A disagreement is one `FrameMismatch` code on either axis, a model that declares a frame the env leaves unstated is a `caution`, and the spec gate can require frames on both sides. Spec descriptions render them as `@robot_base` and `~target` suffixes.
- Env contract branches: `EnvFactory.tag_params` names the make parameters that change an env's tags, `tags_for(**params)` returns the tags for one binding, and `describe()` lists every branch under `env_contracts`. The make wrapper stamps the chosen branch and the declared reset options into the env's metadata, and `EnvServer` asserts the branch the platform expects when `RLMESH_EXPECTED_ENV_BRANCH` is set.
- Action chunking and batched prediction in the runtime. Implement the most general of four corners and the runtime derives the rest: `predict`, `predict_chunk`, `predict_batch`, `predict_chunk_batch`. The runtime owns chunk replay and the execution horizon, so one action still reaches the environment per step. Any unbatched corner may accept a trailing `context` argument carrying the episode's `episode_id` and `episode_seed`, locally and across the wire. Grouped predict requests spanning several environments fuse into one batched forward pass when the model's batched corner is the corner a direct predict would run, so grouping never changes model behavior; `Model.allow_fusion = False` opts out a batched forward that assumes fixed-size, single-environment batches.
- Seeded evals: `run(seeds=[...])` gives each episode its own seed (and sets the episode count), threading it to the environment's `reset(seed=)` and to the model as episode context; `EpisodeResult.seed` records what each episode ran with.
- Startup phase marks: `python -m rlmesh.serve` records when it reached `imports`, `model` or `env`, and `listen`, in milliseconds since the process started (plus `process`, the interpreter and `rlmesh` import time before the entrypoint ran, from `/proc` on Linux), prints them on the serving line, and stamps them on the handshake as `PeerInfo.extra` keys `rlmesh.startup.<phase>_ms` beside the build keys. `rlmesh.serve.startup_marks()` returns the marks reached so far and `register_python_peer_info(extra=...)` exposes the extra map the Rust side already merged.
- Run observability: pass `hooks=RunHooks(...)` to `run()` / `Model.run` / `Session.run` for per-step `StepEvent`s (action, reward, the step's own terminal flags, timing, lazy role-addressed reads) and episode/run boundaries, in the same order on the native loop and the session loop; `on_run_start` receives a `RunContext` (the `Session` itself, or the native run's context) for role reads and frame discovery. Cap episodes with `max_episode_steps`/`max_episode_seconds`, and read per-episode timing off `EpisodeResult`. `instruction=` works on `run()` too.
- Read-only observation inspection: `Session.reader()`/`Session.read()` extract any role from a raw observation through the model's adapter, and `Session.observation_roles()`/`EnvTags.observation_roles` list the roles an env declares.
- PyTorch and JAX end to end: environments served with framework tensors (`EnvServer(env, framework="torch", device="cuda:0")`), `rlmesh.torch` and `rlmesh.jax` factory, model, and sandbox classes, and DLPack-native `Tensor` transport with zero-copy NumPy, Torch, and JAX backends.
- Isolated sandboxes: rebuild an environment identically in a container (`SandboxEnv` with grouped `SandboxBuild`/`SandboxRuntime` config, including `SandboxRuntime.user` for writable bind mounts) or run a prebuilt image. A bare tagless image name resolves against local Docker images and never silently falls into a source build.
- An experimental C ABI: `crates/rlmesh-capi` is a C11 header plus a header-only C++17 wrapper that lets a C or C++ program implement `predict` and have the runtime drive it against an environment (`rlmesh_model_run_local`) or serve it as a gRPC model service. Observations reach C already decoded, one value handle per sub-env, with each episode row's `predict_index` and `predict_seed`, and actions return as owned handles Rust validates against the route's action space; run options take a `trial_index_base`. Built from source with `mise run test:cxx`; the crate is not published to crates.io yet.
- `RemoteModel` now offers `delivers_history` only to a served model that advertised `rlmesh.model.observation_history.v1` at handshake (new `ModelClient::server_ingests_history`); a model without the capability receives no history rows.
- `policy:check` now pins the additive-forever wire-v1 contract in `rlmesh.toml [wire]`: the 256 MiB gRPC message cap, every proto enum's value count, and the `MetaValue.kind` / `SpaceSpec.spec` oneof arm counts must be updated deliberately in the same change; the emitter-side house rule is documented under "Additive-forever rules" in the editions guide.
- Docs: the compatibility page now states the sticky edition guarantee, the WANT/CAN negotiation, the runtime-as-interpreter and dual-stack rules, the 256 MiB cap and retained-edition contract, the cross-version matrix, and a release-anchored roadmap.
- `rlmesh-proto` ships its retained workflow-edition list (`supported_editions.txt`, current edition first) so a crate built from crates.io offers every retained edition, not just its own; the build fails if the file drifts from `rlmesh.toml`, `bump_version.py --sync-editions` regenerates it, and `policy:check` enforces it.
- The runtime records each served peer's ceiling (the highest edition both implement, the wire-v1 dtypes, capabilities, and the message cap) on `RuntimeSessionSpec` as `env_ceiling` / `model_ceiling`, exposed by `RemoteModel::ceiling()`.
- A `RelayPolicy` seam (`RefusingRelayPolicy` by default, `RuntimeDriver::with_relay_policy`) checks the env contract, observations, and actions against the target leg's ceiling; a converting policy can rewrite leaves and attach an advisory, which reaches `RuntimeReport.advisories`, a `relay_advisory` hook, and `RunResult.advisories` in Python. `Advisory` moves to `rlmesh-spaces` and stays re-exported from `rlmesh-adapters`.
- The C ABI takes the same declaration as `RlmeshServeOptions.workflow_edition`, which grows that struct: **ABI version 4** (`RLMESH_ABI_VERSION`, `rlmesh_abi_check()`, and the versioned SONAME all move from 3 to 4).
- Declared construction parameters: `EnvFactory.params = ParamSpec(Param(...))` validates `make()` arguments, `enumerate_variants()` lists a factory's concrete sub-environments, and `describe()`/`describe_json()`/`python -m rlmesh._describe` emit a JSON metadata envelope without loading a model (an env's spaces are read off one representative instance); a model envelope reports the predict `corners` the class actually defines, and `python -m rlmesh._describe --check IMAGE` validates a built image's rlmesh labels locally, the way the platform probe will, before pushing.
- A live debug viewer: pass `view="terminal"`, `view="http:9000"`, or `view="both"` to `session()` (or to the module-level `run()` for a served handle), or configure `rlmesh.View(...)`. It is best-effort and never breaks an eval.
- Record eval runs to a portable bundle for upload: `rlmesh.Recorder` accumulates per-episode metrics with `add()` (from any `RunResult`) or `capture()` (live `RunHooks` on the session path) and writes an `rlmesh.result.v1` folder or zip with `export()`. On the session path it records the same sources the live viewer offers -- the env's `render()` frame plus every declared image role -- each to its own AV1 `.mp4`, encoded in process (pure Rust, no ffmpeg or extra dependency; `Recorder(fps=, quality=)` set playback rate and size/fidelity); env-produced video files are carried into the bundle by path. Capture is best-effort: a source that fails to read or encode is dropped with a warning and never aborts the eval.
- `rlmesh.sanitize_metadata()` coerces a third-party sim's rich `info` objects into wire-safe metadata, and connection failures name the address and the likely fix instead of a bare transport error.
- Client timeouts: `RemoteEnv`, `RemoteVectorEnv`, and `RemoteModel` accept `connect_timeout_seconds` and `request_timeout_seconds`, so a hung peer fails with a `TimeoutError` instead of blocking forever.
- Fail-loud argument handling: a parameter that cannot be honored (`instruction=` on a served model, an unknown `vectorization_mode`, a conflicting CLI flag) raises with a directive error instead of being silently ignored.
- Self-explanatory predict failures: when a model's `predict` raises, the error is annotated with the adapter-assembled input signature (key → dtype/shape), both in local `run()` loops and across the wire from a served model, so a shape mismatch names what the model was actually handed.
- Managed-platform sign-in from the CLI: `rlmesh login` (device flow), `rlmesh logout`, `rlmesh whoami`, and `rlmesh registry login` (registers the bundled `docker-credential-rlmesh` helper, so docker fetches a fresh short-lived token per pull/push), with named profiles (`rlmesh profile use`/`list`/`remove`, `--profile`, `RLMESH_PROFILE`) and credentials held in the OS keychain. `rlmesh org list` and `rlmesh org switch` show the organizations the account belongs to and change the profile's active one.
- Managed-platform evaluations from the signed-in session: `rlmesh eval submit` (with `--preview` and `--wait`), `rlmesh eval list`, `rlmesh eval get`, `rlmesh eval wait`, and `rlmesh eval cancel`; `rlmesh token` prints a fresh access token for scripts; and `rlmesh.platform.Client` wraps the same routes from Python with `scenario_tasks()` to expand a scenario group into tasks.
- Build identity: `rlmesh.build_info()` and `rlmesh version` report the workflow edition of the native core — the sealed `YYYY.MM` name on a release build, a cohort-suffixed name (`YYYY.MM-<prerelease>` / `YYYY.MM-dev.<git>`) on prerelease and source builds.
- Runtime hook events `ObservationEmittedEvent` and `ActionReceivedEvent` carry `raw_observation` / `raw_action` alongside the transformed payload, so hooks can record both the pre- and post-transform leaves per step.
- `StepCompletedEvent` and reset `ObservationEmittedEvent`s carry the env's per-step / reset `infos` map, so hooks see dense rewards, success flags, and task diagnostics as they happen rather than only `final_info` at episode end. Under `NEXT_STEP` autoreset the roll step's `infos` land on the new episode's first `ObservationEmittedEvent`, not on the old episode's `StepCompletedEvent`.
- `StepCompletedEvent` carries per-lane `terminated` / `truncated` (env-reported or a runtime cap, known at the step itself) and a per-lane `autoreset_roll` mask (lanes roll independently under `NEXT_STEP`), so a hook learns how a step ended without waiting for `episode_completed`. The `rlmesh` crate re-exports `RuntimeHooks` and the per-episode events, and `ModelWorker::run_local_hooked_async` drives a local session with a hook implementation.
- The recorder captures on `Model.run` as well as on the session loop: image roles always, and the env's `render()` frame for a local env object; a vector env is refused unless `cameras=[]`.
- `EpisodeStartedEvent` and `EpisodeCompletedEvent` carry the episode's `seed` (`None` when the runtime sent no per-episode seed, e.g. an env-owned `NEXT_STEP` autoreset), so hooks can record it from episode start.
- Gym vector envs served with `num_envs > 1` report each autoreset episode's seed as `info["seed"]`, derived from the lane's last explicit seed, on both the registry `make_vec` path and the factory fan-out path.
- Decomposable endpoint timing: every env and model response now carries the split of its `endpoint_total_ns` into wire decode, the implementation's own work, and wire encode, and a model response adds the wait before its predict handler ran plus the slots the endpoint had taken. An env response adds its env-lock wait the same way. The runtime records them as the `endpoint.decode`, `endpoint.user`, `endpoint.encode`, `endpoint.queue`, and `predict.in_flight` metrics, so a slow step can be attributed to serialization, user code, or queueing without attaching a profiler. A peer that does not stamp them is unchanged. The phase-summary log moved to `RLMESH_PROFILE_PHASES`; `RLMESH_PROFILE` still enables it when it reads as a boolean, but it primarily names the CLI's credential profile.
- `RunResult.telemetry` surfaces the run's aggregated timing/size telemetry on the `Model.run` native loop: one `TelemetryRow` per measured op/metric series (count, avg, p50/p95/p99, unit), with `result.format_telemetry()` rendering the table -- so where an eval's time went is a printed property of the result, not a log to capture.
- The adapter engine measures its own share of each predict -- observation assembly plus action apply -- reported as `adapter_ns` on the model response and recorded as the `predict.adapter` metric (a sub-span of `endpoint.user`, so the model's own forward is the difference), on both the served endpoint and the in-process `Model.run` path.
- The engine reports the per-episode adapter state it is holding -- episodes with live frame-stack windows and the bytes they occupy, summed across routes -- stamped per predict and recorded as the `held.episodes` and `held.bytes` metrics, so unbounded episode-state growth (or an eviction that stopped firing) is visible as a trend instead of an OOM.
- A `lane_skew_ns` scalar on the env response and a matching `lane.skew` metric, for a vector env that times its own lanes: its slowest lane minus its median lane, one series no matter how many lanes it runs, so one pathologically slow lane can show up in p95/p99 instead of merely blurring the `env.step` aggregate. No in-tree env stamps it yet (the built-in Gymnasium vectorization hands the lane loop to Gymnasium), so the series stays empty until a lane-timing env does; a Rust `VectorEnv` can compute it with `rlmesh::env::lane_skew_ns` over a scratch buffer of per-lane durations.
- Async inference in the Rust runtime driver: `RuntimeDriver::with_prefetch(model, lead)` predicts the next action chunk on a second model handle while the current chunk's replay frames execute, firing when `lead` frames remain. The prefetched chunk is conditioned on an observation up to `lead` steps stale, so runs reflect deployment-realistic async timing and are not comparable to the synchronous predict-then-step loop; a chunk prefetched across an episode boundary is discarded. On a route that negotiated observation history the prefetched request carries the rows buffered so far and predicts from an observation of its own, so every env step still reaches the model exactly once. Opt-in: `RuntimeDriver::with_prefetch(lead)` in Rust, `prefetch_lead=` on `Model.run()` and `rlmesh.run()` in Python (the session loop and a served handle refuse a non-zero lead rather than faking it).
- Negotiated workflow editions content-pinned to the sealed `2026.06` edition spec, exact-match `rlmesh-wire-v1` protocol generation, and a per-lane `NEXT_STEP` autoreset contract for vector environments.
- Image adapters run as typed kernels: the 180° rotation, the uint8 to float32 normalisation, the HWC to CHW transpose, and a pad to the frame's own size no longer pass through the dtype-generic scalar codec, and a camera plan that ends in a normalised float32 CHW tensor (the shape every vision policy asks for) runs as one fused pass from the raw bytes. Output is byte-identical to the previous path; a 256×256×3 frame costs about a sixth of what it did.
- A fused grouped predict assembles its groups' inputs and applies their returned action chunks in parallel, one route per thread, when every group names a distinct route and no plan runs a Python custom transform (otherwise it stays sequential); results keep request order and the per-route entry locks still guard each route's buffers. The `predict.adapter` share of a served model's handler time, which was serial for every lane of a batch, shrinks accordingly.
- `rlmesh whoami --json`, `rlmesh org list --json`, and `rlmesh profile list --json` for scripts, and `expiresAt` on `rlmesh token --json`, so nothing has to scrape the human output.
- `RLMESH_API_KEY` (with `RLMESH_PLATFORM_URL`) drives `rlmesh token`, `rlmesh eval`, and `rlmesh whoami` without a browser sign-in, matching `rlmesh.platform.Client`; `RLMESH_CONFIG_DIR`, `RLMESH_DATA_DIR`, and `RLMESH_KEYCHAIN=off` confine the CLI's files and keep the OS keychain out, for CI runners and containers.
- `rlmesh logout` asks the platform to end the session (`DELETE /v1/me/session`) before deleting the local credential, so the refresh token stops working server-side too; a platform without the route still signs out locally.
- A CLI reference page covering every command, exit code, environment variable, file, JSON output, and the contract a platform must serve to be driven by the CLI.

### Changed

- `episodes=` replaces `max_episodes=` on `run()`, `Model.run`, and `Session.run` and is exact: one episode by default, `len(seeds)` when only seeds are given, and the two must agree when both are (no unseeded tail); `episodes=0` runs nothing and a negative count is refused. On a vectorized env the budget bounds episode starts, so `result.num_episodes == episodes` on every path -- a lockstep lane the env rolls past the budget under `NEXT_STEP` autoreset runs unscored (never counted, reported, or seen by hooks) instead of padding the result. Seeds and per-episode caps on an autoresetting vector env are refused before any episode starts.
- `EpisodeResult.predict_ms` / `step_ms` are that episode's own per-step means on every path (`float | None`, `None` for an episode that ended before its first step), never the run-wide average the native loop used to substitute; the runtime now times every predict and env step it issues and reports them per episode, so the record `on_episode_end` receives equals the one in the result, and `Recorder.capture()` and `Recorder.add(result)` record the same metrics. `StepEvent.predict_ms` is the predict that landed since the previous step (zero for a chunk-replay step; under prefetch, the next chunk's), the same definition the per-episode mean is built from.
- A model instance passed to `run()` / `session()` is borrowed: neither the run nor closing the session calls its `close()` any more (a model built from a class you passed is closed with the call or session), and a caller's env is left open unless `close_env=True` -- an env built from an `EnvFactory` is closed when the run or session ends. `EnvServer(..., close_env_on_shutdown=False)` serves an env without closing it at shutdown, which the loopback server `Model.run` stands up now uses.
- **Prerelease compatibility:** v0.1.0 seals `2026.06` and drops the provisional rc.12 cohort. Upgrade both peers before connecting a former rc.12 participant to a stable runtime. Replace cohort declarations such as `2026.06-0.1.0-rc.12` with the bare `2026.06`; future releases retain this sealed edition.
- `RunResult.success_rate` counts only the env-reported task outcome (`info["is_success"]` / `info["success"]`) and is `float | None`: `None` when the run is empty or any episode lacks the signal, never a rate inferred from `terminated`. `EpisodeResult.succeeded` and the terminal-state fallback are removed; the recorder's exported `successRate` follows the same rule and may be null, and the viewer's HUD shows `done` rather than `success` for a terminal state with no reported outcome.
- The `Model` subclass hook that fires when an episode ends is `on_episode_end(self, episode_id="")`, the name the constructor callback and the runtime already used; `Model.reset` is gone, so the model hook no longer reads like an env `reset`. A wrapped policy object's `reset()` is still picked up as that hook.
- `rlmesh.run()` and `rlmesh.session()` take a `Model` (an instance or subclass class) or a served handle and refuse a bare predict callable or policy object with a `TypeError` naming the fix: the library never picks a framework, so wrap it in `rlmesh.numpy.Model(fn)` / `rlmesh.torch.Model(fn)` / `rlmesh.jax.Model(fn)`, or `rlmesh.Model(fn)` for raw values. `python -m rlmesh.serve module:Policy` keeps serving a policy object as a NumPy model. `Model.run` no longer lists `view`; the live viewer belongs to `Model.session`, and the module-level `run()` forwards it only for a served handle.
- `rlmesh.build_info()` reports the native core's build identity as a frozen `BuildInfo` (`version`, `protocol_generation`, `workflow_edition`, `workflow_edition_base`, `build_cohort`, `build_source`, `git`); `rlmesh.__build__` is now a deprecated alias for `build_info().workflow_edition` that emits a `DeprecationWarning` on read and is removed in 0.2.
- The CLI reuses its access token until a minute before the `exp` claim and refreshes only then, under a per-profile lock that re-reads the credential store after acquiring it, so `rlmesh token`, `rlmesh eval`, and every docker pull cost no identity-provider round trip and concurrent commands rotate the single-use refresh token once. A request the platform still rejects is retried once after a forced refresh.
- The CLI has no built-in identity provider: a platform whose `/v1/info` does not advertise `deviceAuthorizationEndpoint` and `tokenEndpoint` cannot be signed in to, the platform URL itself must be https (loopback excepted), and the token endpoint's host is pinned per profile at sign-in so a later `/v1/info` cannot redirect a stored refresh token. Identity (email, display name, organization) now comes from the platform's `/v1/me`, never from provider-specific fields on the token response; `rlmesh login` reports a platform that cannot confirm the identity instead of hiding it.

### Fixed

- Fatal environment errors close the Join stream. `EnvServer.wait()` responds to Ctrl-C, and interpreter shutdown no longer aborts after serving an environment.

## [0.1.0-rc.11] - 2026-09-17

### Added

- Startup phase marks on the serving line and the handshake: `python -m rlmesh.serve` stamps `rlmesh.startup.{process,imports,model|env,listen}_ms` on `PeerInfo.extra`, so a runtime or platform reads where a container's startup wait went from the handshake it already receives. `rlmesh.serve.startup_marks()` and `register_python_peer_info(extra=...)` expose the pieces.
- Async inference from Python: `prefetch_lead=` (keyword-only, default 0) on `Model.run()` and `rlmesh.run()` predicts the next action chunk while the current chunk's last `lead` frames execute, the same `RuntimeDriver::with_prefetch` the Rust runtime has had since rc.10. The prefetched chunk is conditioned on an observation up to `lead` steps stale, so such runs are not comparable to the synchronous loop; a chunk prefetched across an episode boundary is discarded; a negative lead is a `ValueError`, and `rlmesh.run()` on a served handle or the session loop refuses a non-zero one.
- Body parts: `part=` on every tag, field, actuator, and model part names where a role repeats on a body (`LEFT_ARM`, `RIGHT_ARM`, `ARM_2`, `HEAD`, `TORSO`, `BASE`, `LEFT_LEG`, `RIGHT_LEG`; `adapt.PARTS`), matched as an identity key: a model naming a part binds only that leaf, one naming none binds the env's only leaf of the role, and several is an error naming them. The ten `_2` roles are now the legacy spelling of the base role under `part="arm_2"` and bind each other. `explain()` shows a bound part as `#part`.
- Axis labels: `labels=` names a joint vector's axes in that side's own order, and the resolver aligns the two sides by name as a derived permutation or a subset select, so an Isaac Lab-order checkpoint resolves against a Unitree SDK-order env without a hand-written index map. `scale`, `offset`, and `fill` accept per-axis sequences (`axis_scale`, `axis_offset`, `axis_fill`). The joint tuples ship as data in `rlmesh.adapters.embodiments` (`GO2`, `G1_29DOF`, `FRANKA_PANDA`, `UR5E`); a tuple matching no profile on a joint role draws an `unknown_labels` nudge, and the `--require-labels` publish tier requires profile labels on every joint-role leaf.
- Body roles and provenance: `BASE_ANG_VEL`, `BASE_ROT`, and `COMMAND_BASE_VEL` (the first role under the `command/` kind) register a floating base's gyro, orientation, and velocity setpoint; a model reads the orientation as projected gravity with `encoding="gravity_xyz"`. `provenance=` (`sensed`, `estimated`, `privileged`) says where a state leaf's numbers come from, is part of the env leaf's identity so a simulator may publish one role as its truth and as its estimate, and a disagreement is a `ProvenanceMismatch`. `State`/`Concat` gain a container `clip=`.
- Previous action: `adapt.Previous(role)` reads the model's own output actuator back as the raw action executed at the previous step, recorded at every replay site and numbered so a re-plan at any execution horizon reads the frame the runtime actually executed, including under a prefetch lead. A route with the part negotiates observation history like a stacked one.
- End-effector wrench: `EEF_WRENCH` (`proprio/eef_wrench`) registers the six-axis force/torque a wrist sensor reads, force first, 6 wide and framed; the frame vocabulary gains `tool`, the frame attached to the end effector, so a wrist-mounted sensor and a controller's estimate are two leaves of one role and a model binds the one it was trained on.

### Changed

- Async prefetch on a route that negotiated observation history now prefetches: the prefetched request promotes its own observation off the backlog and carries the remaining rows, so every env step reaches the model exactly once and the rc.10 run-start override (prefetch reset to 0 with a warning) is gone.
- The kind prefixes `image/`, `proprio/`, `text/`, `action/`, and `command/` are a closed set enforced at authoring and at resolve; a role under any other prefix is refused rather than binding to nothing. A role with no `/` is still ad-hoc and `x/` still escapes.
- Duplicate detection in `Split`, `Action`, and `EnvTags` is keyed by `(role, part)`, so one `action/joint_pos` per arm is a valid layout.
- Under `NEXT_STEP` autoreset the `episode_completed` hook event is now the last event a hook receives under that episode id: it fires at the roll, after the ended lane's post-end observation and the autoreset step's event, mirroring the model side (the last predict under an id precedes its `on_episode_end`). Step counts, summaries, and `EpisodeResult` are unchanged; the last episode of a bounded run is reported when the budget idles the group. Driver-owned resets keep their order.
- A labeled model against an unlabeled env, or a label the env lacks, is a `LabelMismatch`; a `post_rotate` or an actuator naming `gravity_xyz` is a codec error; an env observation tagged under `action/` is an `ActionRoleOnObservation` join error.
- Lanes in one group no longer wait for the slowest prediction: each lane's predict is dispatched on its own and applied as it lands, and per-episode ordering is unchanged. A model with a batched corner keeps one fused forward per group (`RuntimeModel::fuses_predicts`); a served or managed model receives one predict per lane and batches on its own side.
- Eviction (`reset_adapter`) in the runtime driver is bounded by the predict timeout in the loop and by the close timeout at teardown, and is cancellation-aware; an unanswered eviction is logged and abandoned instead of holding the route. A route that ends mid-episode ends every episode it still holds on the model side before releasing, so a persistent endpoint no longer keeps a failed run's Python episode state; this is new `ResetAdapter` traffic at route exit on the healthy path too.
- The served model handler evicts route state and decodes requests off the lock it holds across a forward: `ModelRouteSetup::reset_adapter` (defaulted) does the route-local eviction, and `predict` telemetry's `queue_ns` now runs from arrival to handler entry without the decode. The held-state totals (`held.episodes`, `held.bytes`) are kept by route deltas instead of a per-predict scan of every route. Embedders that call `AdaptedModelHandler::reset_adapter` directly must also call the route setup's method.

## [0.1.0-rc.10] - 2026-09-14

### Added

- Observation history on the wire, so a frame-stacked model works with action chunking on the native and served paths. The runtime declares on `ResolveAdapter` that it delivers history (`delivers_history`), a stacked route answers the inputs that hold a window (`ResolveAdapterResponse.history`), and each later `Predict` carries the env steps the runtime executed from a replayed chunk as `history` rows, oldest first, stamped with a per-group `step` counter that the engine holds to consecutive values per episode (a gap or repeat fails the predict rather than stacking a wrong window). Four additive proto fields; a runtime that never offers history and a model that never answers it exchange the same bytes as before. `Model.run`, a served model under the Rust runtime driver, and `RemoteModel` all deliver it; the Python session keeps ticking its window locally. The served model advertises `rlmesh.model.observation_history.v1`, and the `history.rows` telemetry metric counts rows per predict.
- Trial ordinals by default: under runtime-owned resets every episode walks a trial ordinal from `trial_index_base` (0 unless set), reported on episode events, summaries, and `EpisodeResult.trial` whether or not the env declared the reset option; delivery to the env is still gated on `EnvFactory.reset_options`. `Model.run()`, `rlmesh.run()`, and `Session.run()` take `trial_index_base`, so a local eval walks the same states as a platform shard. Under `NEXT_STEP` autoreset no ordinal is minted and a non-zero base is rejected.
- C ABI (experimental, ABI version 3): `RlmeshEpisode` carries `predict_index` and `predict_seed` (the same mix as `rlmesh.predict_seed`; `seeded` says whether the seed is meaningful), tracked per episode id with the SDK's 4096-episode cap and an LRU eviction that fires `on_episode_end`; `RlmeshRunOptions` gains `trial_indexed` and `trial_index_base`. The C++ wrapper mirrors both.

### Changed

- A frame-stacked adapter at `execution_horizon > 1` is no longer refused outright on the native engine: it is refused only when the runtime did not offer observation history, and the error says so. A stacked route whose windows would hold more than `RLMESH_FRAME_HISTORY_LIMIT_BYTES` (default 2 GiB across its lanes) is refused when the adapter resolves.
- Async prefetch (`RuntimeDriver::with_prefetch`) is reset to 0 with a warning on a route that negotiated observation history: its refill would deliver a step twice and skip another.
- The configure-time probe that predicted under a synthetic episode id and rejected any output drift as "internal state" is gone. It could not tell legitimate per-episode `context["state"]` or a `predict_index`-dependent output from cross-episode leakage, so a model using the rc.9 context failed to serve against `num_envs > 1`.
- Lane endpoints (`EnvServer([env, ...])`) require every lane to carry the same env contract (spaces, metadata, tags) as lane 0; a lane that disagrees fails at construction instead of running under lane 0's adapter. In Rust, `LaneEnv::new` and `WireLaneAdapter::new` now return `Result`.
- `EpisodeResult.trial` on the session path is recorded for every episode rather than only for an env that declared the reset option, matching the native report.

### Fixed

- A prediction that was in flight when an episode ended, and returned after the next observation had already landed, left the route stalled with nothing in flight. The driver now re-plans from the saved observation.
- A declared `native_chunk` is now enforced on the spec-less native path and at `execution_horizon=1` (the derived single-action corner measures the whole chunk before taking its first frame), so a chunk corner that slices itself is caught the same way on every path.
- Under `NEXT_STEP` autoreset on a lockstep vector env, the model no longer receives a predict for an episode after that episode's `on_episode_end`: the ended id's eviction now waits for the autoreset roll, after the terminal observation's predict, so an ended episode's state is neither re-created nor leaked.
- The env server reaps finished lane-scoped reset/step tasks as new ones arrive, instead of holding every completed task until a whole-endpoint request or the end of the stream.

The endpoint advertises `subset_step`, `StepRequest.env_indices` and partial-width `StepResponse`s are honored, and the runtime driver treats each lane as its own reset/predict/step loop over one multiplexed Join stream, so lanes reset and step at their own pace while every episode's seed and index come from a route-global slot counter; lanes waiting for a prediction share one grouped predict (`PredictScheduler`, one fused forward for a model with a batched corner). The make wrapper stamps the chosen branch and the declared reset options into the env's metadata, and `EnvServer` asserts the branch the platform expects when `RLMESH_EXPECTED_ENV_BRANCH` is set.

Built from source with `mise run test:cxx`; the crate is not published to crates.io yet.

The phase-summary log moved to `RLMESH_PROFILE_PHASES`; `RLMESH_PROFILE` still enables it when it reads as a boolean, but it primarily names the CLI's credential profile.
- `RunResult.telemetry` surfaces the run's aggregated timing/size telemetry on the `Model.run` native loop: one `TelemetryRow` per measured op/metric series (count, avg, p50/p95/p99, unit), with `result.format_telemetry()` rendering the table -- so where an eval's time went is a printed property of the result, not a log to capture.
- The adapter engine measures its own share of each predict -- observation assembly plus action apply -- reported as `adapter_ns` on the model response and recorded as the `predict.adapter` metric (a sub-span of `endpoint.user`, so the model's own forward is the difference), on both the served endpoint and the in-process `Model.run` path.
- The engine reports the per-episode adapter state it is holding -- episodes with live frame-stack windows and the bytes they occupy, summed across routes -- stamped per predict and recorded as the `held.episodes` and `held.bytes` metrics, so unbounded episode-state growth (or an eviction that stopped firing) is visible as a trend instead of an OOM.
- A `lane_skew_ns` scalar on the env response and a matching `lane.skew` metric, for a vector env that times its own lanes: its slowest lane minus its median lane, one series no matter how many lanes it runs, so one pathologically slow lane can show up in p95/p99 instead of merely blurring the `env.step` aggregate. No in-tree env stamps it yet (the built-in Gymnasium vectorization hands the lane loop to Gymnasium), so the series stays empty until a lane-timing env does; a Rust `VectorEnv` can compute it with `rlmesh::env::lane_skew_ns` over a scratch buffer of per-lane durations.

### Fixed

- The `rlmesh_package='local'` sandbox error for a missing compatible Linux wheel now points at `mise run release:python:wheels:linux` on a Linux host. The old hint named the host-dispatch task, which on macOS builds only macOS wheels and clears any Linux wheels already in `dist/`.

## [0.1.0-rc.6] - 2026-08-26

### Added

- Runtime hook events `ObservationEmittedEvent` and `ActionReceivedEvent` carry `raw_observation` / `raw_action` alongside the transformed payload, so hooks can record both the pre- and post-transform leaves per step.
- `StepCompletedEvent` and reset `ObservationEmittedEvent`s carry the env's per-step / reset `infos` map, so hooks see dense rewards, success flags, and task diagnostics as they happen rather than only `final_info` at episode end. Under `NEXT_STEP` autoreset the roll step's `infos` land on the new episode's first `ObservationEmittedEvent`, not on the old episode's `StepCompletedEvent`.
- `EpisodeStartedEvent` and `EpisodeCompletedEvent` carry the episode's `seed` (`None` when the runtime sent no per-episode seed, e.g. an env-owned `NEXT_STEP` autoreset), so hooks can record it from episode start.
- Gym vector envs served with `num_envs > 1` report each autoreset episode's seed as `info["seed"]`, derived from the lane's last explicit seed, on both the registry `make_vec` path and the factory fan-out path.

## [0.1.0-rc.5] - 2026-08-20

### Added

- `python -m rlmesh._describe --check IMAGE` validates a built image's rlmesh labels locally, the way the platform probe will, before pushing: the describe envelope must parse cleanly with no `error` badges, and packaged checkpoint declarations must be well-formed (DNS-label names, a `uri` per entry, a single default). Failures exit nonzero, so it can gate a push in CI.
- `RLMESH_ALLOW_REMOTE_SHUTDOWN=1` opts a served environment into honoring the remote `shutdown` RPC, so an orchestrator that queues env workloads can tell a finished worker to exit and free its slot. The variable can only enable remote shutdown, never disable a programmatic `allow_remote_shutdown=True`.
- Driver telemetry records each loop iteration's wall clock (`runner.round`), bracketing the full predict -> step -> transform body, so subtracting the per-op rows yields the driver's own residual overhead.

### Changed

- Batched leaf-slab encode and decode on the wire parallelizes past 64KB, speeding up large batched observation and action payloads.

## [0.1.0-rc.4] - 2026-08-19

### Added

- Seeded evals. `run(seeds=[...])` gives each episode its own seed and sets the episode count unless `max_episodes` is given; the seed reaches the environment's `reset(seed=)` and rides to the model as episode context, locally and across the wire. Any unbatched predict corner (`predict`, `predict_chunk`) may accept a trailing `context` argument carrying `episode_id` and `episode_seed`; batched corners never receive episode context. `EpisodeResult.seed` records what each episode ran with.
- Record eval runs to a portable bundle for upload: `rlmesh.Recorder` accumulates per-episode metrics with `add()` (from any `RunResult`) or `capture()` (live `RunHooks` on the session path) and writes an `rlmesh.result.v1` folder or zip with `export()`. On the session path it records the env's `render()` frame plus every declared image role, each to its own AV1 `.mp4` encoded in process (pure Rust, no ffmpeg or extra dependency; `Recorder(fps=, quality=)` set playback rate and size/fidelity). Capture is best-effort: a source that fails to read or encode is dropped with a warning and never aborts the eval.
- Managed-platform sign-in from the CLI: `rlmesh login` (RFC 8628 device flow), `rlmesh logout`, `rlmesh whoami` (with server-side identity verification), and `rlmesh registry login`, which registers the bundled `docker-credential-rlmesh` helper for the platform registry so docker requests a fresh short-lived token on every pull and push instead of storing a static password. AWS-style named profiles (`rlmesh profile use`/`list`/`remove`, `--profile`, `RLMESH_PROFILE`) select platform and identity; credentials live in the OS keychain with a 0600 file fallback, keyed by profile so two profiles can hit one platform as different users.
- Custom rotation encodings survive spec publication: a `CustomEncoding` arm serializes to the wire as a `module:callable` reference, or as a `<local>` marker for an in-process callable -- the published spec stays showable and validatable, while execution stays host-side.
- Model describe envelopes report `corners`: the predict corners the class actually defines, introspected from the code that ships rather than declared, so a packaging claim like batching support can be checked against it.
- Step telemetry records hook transform round-trips, so time spent in `RunHooks` transforms is visible per step.

### Changed

- `RunResult.success_rate` warns once when no episode in the run reported a task-outcome signal (Gymnasium `info["is_success"]`/`info["success"]`): the rate is then the `terminated` fallback, which counts any terminal state as a success.

## [0.1.0-rc.3] - 2026-07-06

### Added

- Grouped predicts fuse across environments. When the control plane groups predict requests, a model with a batched corner (`predict_batch` or `predict_chunk_batch`) serves the whole group in one forward pass. Fusion engages only when that batched corner is exactly the corner a direct predict would run, so grouping never changes which of a model's predict methods executes or how it chunks; a fused failure keeps the model error's recoverable flag and annotates each group with its own input signature.
- `Model.allow_fusion` (default `True`). Set it to `False` when a batched forward assumes fixed-size, single-environment batches, such as a shape-pinned `jit` trace or per-batch statistics; grouped predicts then run one route at a time.
- Adapter advisories carry a severity tier: `Advisory.severity` is `"info"` for benign hints and `"caution"` when the adapter substituted or fabricated model-visible data, the tier an eval harness may want to hard-fail on.

### Fixed

- Batched and chunked prediction now works in local `run()` evals. `run()` drives the same native runtime loop as a served model, so `predict_batch`, `predict_chunk`, and `predict_chunk_batch` activate locally instead of only on the served wire path.
