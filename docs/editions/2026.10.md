# Edition 2026.10

- **Status:** provisional (`2026.10-0.2.0-<prerelease>` cohorts); the bare `2026.10` seals at v0.2.0
- **Protocol generation:** `rlmesh-wire-v1`, and the rlmesh 0.2 session
- **Replaces:** [2026.06](2026.06.md), which 0.2 no longer offers (see [Support Window](index.md#support-window))

This document is the behavioral contract identified by the workflow edition base `2026.10`, the edition of rlmesh 0.2. Everything [2026.06](2026.06.md) specifies holds at `2026.10` unless a section below changes it; this document lists only those changes. Each one alters what an interaction 2026.06 already defines means for a session, so it takes a new edition rather than an amendment to the sealed one. Until v0.2.0 seals the bare name, this document may still change with the prerelease cohorts.

## Adapter Resolution

The resolver no longer makes a lossy fit between a model's spec and an env's tags silently. Each fit below fails `ResolveAdapter` (and a session's bind) with an adapter-resolution error unless the model spec allows it by name in `allow`:

| Fit                                                                                                             | Allowed by      |
| --------------------------------------------------------------------------------------------------------------- | --------------- |
| Both sides declare a gripper `polarity`, and they differ: the value is reversed into the declared range.        | `flip_gripper`  |
| Both sides declare a delta `unit`, and they differ: the command is rescaled.                                    | `convert_units` |
| A model state input reads the leading `dim` elements of a wider env state field.                                | `select_state`  |
| A model camera input is fed from the env's only camera under another role (a wrist input, a third-person view). | `rebind_camera` |
| A model output no env actuator consumes is discarded.                                                           | `drop_action`   |

Under 2026.06 the state truncation and the dropped output bound silently and the rebound camera bound with a caution; polarity and units were not declared at all. A side that declares no polarity or unit is not checked, and the resolve reports that as an info advisory.

What a resolve tolerated or applied (an allowed fit, a zero-filled optional input) is returned to the caller in `RunResult.advisories` whether the model runs in process or is served, instead of only being logged. On a session the driver asks for them on resolve (`ModelResolve.reads_advisories`) and the model answers them on `ModelResolved.advisories`.

## Rotation Encodings

A rotation conversion between encodings computes in 64-bit floating point; 2026.06 rounded through 32-bit. Reordering a quaternion between `quat_wxyz` and `quat_xyzw` is a permutation of its components that keeps the input's sign and norm, with no canonicalisation to `w ≥ 0`; 2026.06 sent the reorder through a rotation matrix, which could flip the sign. A quaternion produced from any other encoding has the sign the largest-diagonal method gives, as in 2026.06. Both changes can shift trajectories bit-for-bit against 2026.06. A model that needs a canonical quaternion sign declares it in its spec.

## Execution Horizon

The execution horizon `h` (2026.06, Predict) is no longer only the runtime's decision. A model may state it in its spec (`Timing(execution=K)`) or set it in `load()` from its checkpoint, read once after loading, and a served model publishes the loaded value in its describe envelope. The horizon a session runs at is the first of:

1. the `run`/`bind` caller's explicit value;
2. the value the model set in `load()`;
3. the spec's timing;
4. `1`.

The bounds are unchanged: `1 ≤ h ≤ 1024`, and `h` never exceeds a declared native chunk.

## Gymnasium Results

A `RemoteEnv` or `RemoteVectorEnv` connected to a served Gymnasium env is a Gymnasium env with the served env's own spaces, and `reset`, `step` and `render` return what the env itself returns on the same seeds and actions: types, dtypes, shapes and values. Arrays stay arrays (NumPy, or the torch and JAX clients' tensors), including in `info` and reset `options`. The accepted differences are that a reward is a Python `float` (`float64` per lane for a vector env), a `Discrete` observation is the space's NumPy integer, tuples in `info` arrive as lists, and an env's exception arrives as an `EnvironmentException` that is also its builtin class. Values the wire cannot carry are refused by name, naming their key path, instead of being converted. `python/rlmesh/tests/conformance/test_gym_conformance.py` is the reference for this section.

## Model Errors

A served model may type its resolve failures: one that advertises `rlmesh.model.adapter_resolution_code.v1` answers a `ResolveAdapter` it cannot pair with `MODEL_ERROR_CODE_ADAPTER_RESOLUTION` when the runtime set `reads_adapter_resolution_code`, and the runtime raises the adapter-resolution error class. Without both, the failure is `INTERNAL`, as under 2026.06. On a session, the same failure carries the `ADAPTER_RESOLUTION` fault code.

## Episodes

A run's runtime still mints every episode id, but it no longer hands them to the env to adopt and echo (2026.06, Reset and Step); it attributes each completion to its own ids. The Python remote env clients still add the reserved `episode_ids` info key.

Under `AUTORESET_MODE_NEXT_STEP` the env owns its episodes, so the runtime cannot truncate one. A counted episode that reaches the default step bound without ending now fails the run, naming the env slot; under 2026.06 it ran without bound. Where the runtime owns resets, the bound truncates the episode as before.

`AUTORESET_MODE_SAME_STEP` is served on the Gym door (a lockstep `EnvServer` read by a `RemoteVectorEnv`) with Gymnasium's own semantics. A run (`Model.run`, `rlmesh.run`) still refuses it, by name.

In a multi-lane batch, a fatal lane error wins over a recoverable one, and a batch where some lanes failed recoverably while others advanced ends the session, since replaying it would step the advanced lanes twice.

## Seeds

A local run derives its reset seeds from a `base_seed` with the session id `local` in every process, so the same `base_seed` reproduces the same seeds; under 2026.06 the id carried the process id. The derivation itself is unchanged.

`RANDOM_SAMPLE` seeds its action sampler with each episode's reset seed, so a seeded run reproduces its actions. An episode without a seed keeps the running stream; under 2026.06 the sampler always drew from OS entropy.

## Conformance Warnings

A lane endpoint reports each conformance warning once per lane, whichever language serves it; a vector env still reports once for all its lanes.
