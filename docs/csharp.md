# C# maintenance

C# tools are scoped in `csharp/mise.toml` with a separate lock. Root `check`
does not install dotnet or execute C# tasks. `test:affected` selects C#
when its files or the C ABI header change, or reverse dependencies reach
`rlmesh-capi`. That path runs interop staleness, assembly surface and tests.
The existing Linux CI job uses this same planner to select conditional C# tool
installation and tests. Neither `test` nor `test:ci` runs C#.

Every C# task enters through `csharp/tools/run.py`. The root tasks own the
heavy-job lock; affected tests already hold it and invoke that runner directly.
The C#-scoped zig 0.13.0 is also used for generated interop and C layout tests.
`mise -C csharp install --locked dotnet zig` verifies the tool lock. The core
dotnet backend resolves its SDK installer itself and writes no platform URLs;
locked installation has been checked on the development host.

Python integration uses the root `uv.lock` csharp dependency group (including
pinned grpcio), a non-editable package, and `uv run --no-sync` in the isolated
environment. It leaves the developer's editable extension intact. Both native
artifacts use the release protocol cohort. Scratch goes under `~/.cache`.

To regenerate both public snapshots after an approved surface change:

```sh
mise run dev:heavy -- python csharp/tools/run.py check --update
```

The Dict constructor accepts `Space` pairs because v0.2 has no public
`SpaceSpec`. Its keys follow the native constructor's sorted declaration order;
native metadata/value maps preserve insertion order independently. Top-level
wire info is an unordered protobuf map (COR-26) and can include runtime
`episode_ids`; its order is not the observation Dict order. Only the read-only
mapping contract ships, without positional accessors or a `Spaces` alias.

`Env.For` detects same-thread space-getter reentry. Cross-thread cycles through
a user getter cannot be detected without tracking arbitrary user locks; getters
must not wait on another thread resolving the same environment. The README
states this restriction. A generation that reaches uint.MaxValue retires rather
than wrapping, so an old owner token can never become current again.

## Maintainer checks

`test:csharp` also compiles the Unity integration's engine-free core as C# 9 /
netstandard2.1 and runs its dispatcher/preflight tests and Python-driven fake
main loop. `integrations/unity/**` changes select this suite in `test:affected`
and the conditional C# CI path. Actual Editor/IL2CPP verification is the separate
[Unity release gate](unity-release-checklist.md), requiring a Unity licence.

```sh
mise run csharp:interop:generate
mise run check:csharp
CXX="mise exec zig@0.13.0 -- zig c++" mise run dev:heavy -- mise run check
mise run test:affected
mise run test:csharp
```

Interop is generated by the pinned local ClangSharp tool from `rlmesh.h`;
never edit `Interop/Native.g.cs`. The generator discovers zig's builtin headers
with `mise where zig`. Known visibility-attribute warnings are accepted; other
generation diagnostics fail the task. The owned/borrowed string distinction
and `_INIT` factories live in the hand-written layer.

The metadata-only tool in `tools/rlmesh_csharp_surface` compares both assemblies
with [the serving inventory](../csharp/surface/v0.2.json). That inventory is R-28's v0.2
surface, including `ShutdownAsync`, `Ext.CancelledError` and `Ext.Lifetime`. The human-readable [public API dump](../csharp/surface/public-api.txt) lists its
types and declared members. `Space` and the `Box`/`Discrete` constructors live
in `RLMesh.Spaces`; `DType`, `Tensor`, values and authoring live in `RLMesh`.

Tests use xUnit because this repository has no existing .NET test framework;
its analyzers and normal `dotnet` test discovery suit the two-target fixtures.
`test:csharp` takes the shared heavy-job lock, builds the C library and a
non-editable Python package in `target/csharp-python` with
`RLMESH_RELEASE_BUILD=1` and `CARGO_TARGET_DIR=target/csharp-native`, compiles C layout assertions for Linux
x64, Windows x64 and both macOS architectures, checks `_INIT` fields, runs
isolated native-gate and C# 9 compile fixtures, then runs the same behavioral
suite against both assemblies. Python end-to-end clients run through `uv run`.
All .NET builds disable persistent build servers so they cannot retain the
inherited shared-lock descriptor. Test scratch lives under `~/.cache`.

## Specification integration notes

- The optional .NET-only loader resolver is omitted; ordinary platform loader
  resolution works for this source foundation.
- `host_runtime_json` changes the served describe envelope in the real ABI 5.
  It does **not** change handshake `PeerInfo`, contrary to E-3's fixture wording.
  Tests check the envelope's C# language and `framework_versions`, and the wire
  handshake's compatibility. This wave does not introduce a native handshake
  configuration API.
- `free_user_data` records root release by registry-entry identity. The retiring
  entry remains until native free returns, when it is removed by that same
  identity. Removing it inside the callback would let another `Env.For` create a
  second handle before the first free returned; retaining the tombstone enforces
  ENV-37's stronger retirement requirement.
- Only the eight `_INIT` factories the foundation uses are implemented. The
  extension initializer accepts a pinned host-runtime pointer instead of C's
  compiler-specific default string, as required by ENV-38. Field-wise tests
  compare pointer presence and explicit reserved bytes; implicit padding is
  ignored. ABI and package constants are checked against the header.
- `Bound` declares exactly SPC-35's eleven conversions. C# can still widen a
  `char` or native integer before selecting a permitted numeric conversion.
  Preventing that would require extra rejected operators absent from R-28's
  exhaustive inventory; wave A keeps the declared inventory. `Value` has the
  specified obsolete, error-producing `char` and `ulong` operators.
- The end-to-end error fixtures found a native bug: an attached host exception
  bypassed environment classification in `authored_failure`, losing
  recoverability and duplicating `[INTERNAL]`. The formatter now examines the
  underlying error while retaining authored text for other classes. A Rust
  regression test covers attached recoverable, ordinary environment and value
  failures, and both C# target suites verify the result through Python.

## Cancellation and shutdown

`ShutdownAsync` enters admission and takes its counted server reference before
scheduling. A growing library pool performs the blocking drain, including when
the caller cancels its wait. It releases the reference and admission only after
native return and output adoption. Ordinary .NET pool threads are callers;
R-28/E-3's refused pool context means RLMesh's own worker pool.

The internal cancellation bridge allocates one ABI 5 token for each operation.
It registers the caller token, passes the pointer explicitly, then disposes the
registration after native return and frees the reference last. Shutdown also
fires these live tokens, including those published by an already-admitted
operation after shutdown began. Tests use `rlmesh_run`'s cancel field because
this branch's ABI does not yet have X-12's per-call remote-step entry point.
There is no public run, remote environment or native cancel-token wrapper.

The terminal gate counts constructors through record publication and workers
through output adoption and reference release. The shutdown coordinator and
its tracked teardown threads stop servers independently. A constructor publishes its
new strong records only after adopting its outputs and dependency references;
the admitted count covers this interval. This protects an EnvServer constructor
between resolving its new env and borrowing it, while teardown still closes
every published owner immediately. Servers stop to release admitted blocking
Wait calls. Native frees
retain dependencies until return. Managed GCHandle roots and active trampoline
frames are counted separately; an empty ownership table alone is insufficient.
A free callback retires its root until the surrounding native call returns or
the server free that covers its thread has joined. A return with no known join
remains diagnostic and prevents completion, even after its GCHandle was freed.
The coordinator joins all frees, cleanup and operation workers before its own
join permits Completed. GC/finalizer rounds use a separate tracked thread, so an
unrelated blocked finalizer cannot stop independent teardown or late record
publication. A collection round gates completion only while strong ownership
records remain; it remains visible in Pending while running. A failed coordinator
can be restarted by the next Shutdown call. That retry also reschedules records
whose teardown thread threw; successful and still-running attempts stay claimed.
Only timed joins run on the caller, under one absolute deadline. Incomplete retains all roots and continues draining for a later retry.

Every terminal-barrier fixture uses a fresh collectible context, then checks
that the context is collected. This also catches AppDomain diagnostic handlers
that accidentally keep the context alive: successful teardown removes them.
The net10 context hook uses only RLMesh's own assembly, so the static assembly
checker allows Type.Assembly only for the net10.0 target's infrastructure lookup; no authored types
are reflected over. Unload notifications diagnose unsafe unload and attempt a
bounded drain, but cannot make an unload already in progress safe.

Native drain observers share a single join notification without taking the live
serve_async future's result. Repeated shutdown during a live serve_async only
signals, while wait joins without taking that future's result. Async wait uses
completion notifications, including for never-started close drains; it creates
no recurring polling threads. A suspended shutdown_async future retains no drain
lock, so a synchronous shutdown can join it without needing that future polled.
Close callbacks and env destruction carry the same reentrancy marker: shutdown
from that server's callback only signals, and wait answers from state without
waiting for its own drain.

Shutdown's close timeout still bounds its close attempt. Rust facade Drop also
stays bounded: it detaches close/actor threads beyond their timeout or lane grace.
The C wrapper alone calls a binding-only join hook after its finish() calls, so
rlmesh_env_server_free remains the unbounded native join point; no C ABI export
is added. The managed record has an explicit native-return token completed only after this call returns; Freed on an Env record
is never evidence that a foreign thread joined. A blocked native free is reported
by Pending and remains on a tracked teardown worker, so the barrier caller still
returns by its deadline. Unknown foreign returns remain diagnostic indefinitely.

A callback must not hand a blocking shutdown to a helper thread and then join that
helper: the helper cannot inherit the callback's thread-local reentrancy marker,
and shutdown must join the callback. Signal shutdown directly inside the callback
instead. Detecting this arbitrary cross-thread dependency would require changing
the blocking contract for unrelated observers; it remains unsupported.

ShutdownAsync uses ConfigureAwait(false) for all internal waits. Completion and
cancellation do not depend on the caller pumping a SynchronizationContext.

## Packaging, NativeAOT and allocation gates

`mise run csharp:pack` builds both Release assemblies, the nupkg and portable
symbol snupkg into `target/csharp-pkg`; `mise run csharp:upm` also assembles the
Unity package from that nupkg's netstandard2.1 DLL. Native inputs come from C
release tarballs in `target/capi-pkg`, with a local Linux build fallback for
iteration. Local partial packages are supported; `--require-all` refuses a
missing RID for final release assembly. Version comes from Cargo's workspace.

`mise run test:csharp:package` checks importer settings, the complete four-RID
input contract with synthetic libraries, actual NuGet/UPM file sets and symbols,
then restores the nupkg into a new net10 console app with a fresh local-only feed
and package cache. Python drives the served env with no inherited native loader
path. There is no Unity requirement. `mise run test:csharp:aot` publishes the
same serving harness with NativeAOT and exercises it from Python; the existing
path-gated Linux CI job runs both after `test:csharp` prepares native/Python inputs.

`test:csharp` also runs E-3's Release allocation gate: 1,000 warm-up steps,
10,000 measured steps between GC/finalizer checkpoints, at most two cumulative
finalizable SafeHandle constructions and 512 process-wide allocated bytes per
step, then a 100,000-step live-handle equality check. The local env caches its
Box(4,) float32 observation Value and empty Metadata; the test uses raw session
calls and adopts observations into public Value wrappers without expanding the
public foundation API. Handle counters are internal and cumulative/live counts
are distinct. The manual `mise run bench:csharp` adds five 10,000-step batches
per language, interleaved in long-lived C# JIT and C++ processes under one heavy
lock. It prints median timings and their ratio against 1.25x, never fails on time.

The native gate's package version is generated into `obj/` from the Cargo workspace
by `csharp/tools/version.py` before compilation, including direct dotnet builds.
It is never copied from an independent hand-written version constant. The package
suite bumps a copied workspace to a prerelease, builds a new nupkg, restores it in
a fresh consumer and accepts its matching native ABI fixture. The ordinary serving
smoke exercises the actual native library as well.
