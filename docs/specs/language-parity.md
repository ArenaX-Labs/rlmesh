# Language parity

Status: Reviewed (Opus rounds 2–6); user decisions settled 2026-10-15; implemented in Python, Rust, C (ABI 5) and C++17 (tested also at C++20; D-5 amended 2026-10-16). Draft: C# column pending review (D-17, 2026-10-20; not implemented, G-29).

RLMesh is one library in five languages: Python (the reference), Rust (the
`rlmesh` facade crate), C (`crates/rlmesh-capi/include/rlmesh.h`), C++
(`rlmesh.hpp`, wrapping C one to one) and C# (the `RLMesh` package in
`csharp/`, also wrapping C one to one; D-17). C# targets game engines and
simulators; engine integrations such as `integrations/unity/` sit on top of
it and are outside this spec, though their constraints shape it (R-28). If you know the Python API you know
what to expect in every other language, adjusted only by the fixed
translation rules. A difference that no rule explains is a bug.

Python's Stable surface
(`python/rlmesh/tests/api_surface/snapshots/api_surface.json`, labels in
[compatibility](../compatibility.md)) defines the nouns, verbs, defaults and
field names. The wire contract (`crates/rlmesh-proto/proto/`) is frozen and
this spec does not change it.

## How to read

1. Start with [rules](language-parity/rules.md): the translation table, the
   options-struct and async rules, C struct sizing, the one error matrix,
   warnings, fencing, decisions, Python changes, shapes, known gaps and the
   enforcement. C# rules are clauses inside each rule, plus R-28 (C# runtime
   constraints) and X-11 (C# trampolines).
2. Then read the area you work on. Each area maps every Stable Python symbol
   it owns to Rust, C, C++ and C#, and lists its own Python changes and current
   differences. A symbol shared by several areas has one owner (rules R-27);
   the others link to it.
3. IDs are stable: `R-n` rules, `D-n` decisions, `P-n` Python changes, `X-n`
   cross-cutting changes, `G-n` gaps, `E-n` enforcement. Area files use
   `<AREA>-n` for decisions and `<AREA>-P<n>` for Python changes (`COR`, `SPC`,
   `ENV`, `MDL`, `RUN`, `RMT`, `ADP`). Cite them in code review and commit
   messages.
4. "User (accepted default)" marks a default the user accepted on
   2026-10-15. Every one is listed under
   [Decisions accepted by the user](#decisions-accepted-by-the-user).
   "Pending (C#)" marks a C# default awaiting review; every one is listed
   under [C# decisions pending user review](#c-decisions-pending-user-review).

## C ABI and C#

C# needs no C ABI change for parity with Python. The spike bound ABI 5 from
C# on the tested path (spaces, env vtable, env server, Python driving a
C#-served env end to end), and every area mapped its rows onto existing ABI 5
calls. Three additive C changes would make C#'s language-only extras exact;
none is required, and C++ would gain the same:

| Gap                                                                                                                                                 | Candidate addition                                                                                                                         | Without it                                                                                                                                                                                                     |
| --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Single-call `Async` twins (`StepAsync`, `ResetAsync`, `PredictAsync`, remote client calls) can only cancel through the handle's shared token (R-18) | A per-call token for single calls (a `cancel` parameter on the `_ext` variants), or `rlmesh_ext_cancel_token_disarm`                       | A `CancellationToken` firing in the instant after the C call returns can fail the handle's next call at its start                                                                                              |
| `EnvFactory.ServeAsync` and `Model.ServeAsync` cannot match Rust's `serve_async` (R-16, ENV-39, MDL-24)                                             | A background factory serve returning `RLMeshEnvServer*`, and a background model serve (or an options field that skips signal installation) | These twins install process-wide SIGINT / SIGTERM handlers while serving; engine hosts serve a factory's envs with `EnvServer.Start()`, and serving a model from the Unity Editor replaces its signal handling |
| Unity Editor domain reload (Mono only): library threads that called managed code stay attached to the old domain (R-28)                             | A way to stop the library's shared callback threads (`rlmesh_ext_quiesce(timeout)`), if Mono's reload proves to wait on them               | Unverified; `Ext.Lifetime.DisposeAll()` stops every callback first, which may suffice. Players (IL2CPP) never reload                                                                                           |

The generator does not translate `_INIT` macros, `RLMESH_RANDOM_SAMPLE`'s
compound literal or `static inline` helpers; the hand layer supplies managed
equivalents and E-3 checks them byte for byte against C (R-19). That needs
no ABI change either.
