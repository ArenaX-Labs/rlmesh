# Adapters

Part of the [language parity spec](../language-parity.md). Status: Draft —
reviewed round 4. Rules: [rules.md](rules.md). Paths use the prefixes defined
there, plus `pyad/` = `python/rlmesh/src/rlmesh/adapters/` and `core/` =
`crates/rlmesh-adapters/src/`.

`rlmesh.adapters` is Stable. Its counterpart is `rlmesh::adapters` in Rust and
C++, and the `RLMesh*` / `rlmesh_*` / `RLMESH_ADAPTERS_*` names of D-6 in C.
This area owns `EnvTags`, `ModelSpec`, `ObservationRoles`, `tag`, `resolve`,
`Adapter`, `Advisory`, the `adapters.*` metadata keys and the
`AdapterResolutionError` detail (R-27).
`NO_ADAPTER`, `SpecArg`, `Model(spec=)` and `trust_entrypoints` on `Model`
belong to [Model](model.md); `Session.observation_roles` to
[Running](running.md).

## Shape

Build a spec, attach it to a model, tag an env, and drive an adapter by hand.

```python
import rlmesh.adapters as adapt

spec = adapt.ModelSpec(
    {"image": adapt.Image(adapt.IMAGE_PRIMARY, height=224, width=224),
     "state": adapt.Concat(adapt.EEF_POS, adapt.GRIPPER_POS)},
    adapt.Action(adapt.Actuator(adapt.ACTION_EEF_POS, dim=3),
                 adapt.Actuator(adapt.ACTION_GRIPPER, dim=1, binary=True)))
model = rlmesh.Model(policy, spec=spec)

env = adapt.tag(env, tags)

adapter = adapt.resolve_from_contract(remote.env_contract, spec)
predict = adapter.wrap_predict(predict_fn)
action = predict(obs)
adapter.reset()
```

```rust
use rlmesh::adapters::{self as adapt, AdapterBase, Action, Actuator, Concat, Image, InputNode, ModelSpec};

let spec = ModelSpec::new(
    InputNode::dict([
        ("image", Image { height: Some(224), width: Some(224), ..Image::new(adapt::IMAGE_PRIMARY) }.into()),
        ("state", Concat::new([adapt::EEF_POS, adapt::GRIPPER_POS]).into()),
    ]),
    Action::new([
        Actuator { role: Some(adapt::ACTION_EEF_POS.into()), dim: 3, ..Default::default() },
        Actuator { role: Some(adapt::ACTION_GRIPPER.into()), dim: 1, binary: true, ..Default::default() },
    ]),
)?;
let model = Model::new(policy, ModelOptions { spec: Some(spec.clone().into()), ..Default::default() })?;

let env = adapt::tag(env, &tags, adapt::TagOptions::default())?;

let mut adapter = adapt::resolve_from_contract(remote.env_contract(), &spec, Default::default())?;
let mut predict = adapter.clone().wrap_predict(predict_fn); // the clone shares state
let action = predict.call(obs)?;
adapter.reset()?;
```

## Parity table

Defaults equal Python's everywhere (R-6). Rust leaves are value structs with
`pub` fields, `X::new(required…)` (or `Default`), `Clone`, `Debug`,
`PartialEq` and `Display` (R-11; repr text ADP-28). The float-free leaves, whose frozen dataclasses hash
(`Text`, `Custom`, `CustomEncoding`, `ImageTag`, `TextTag`,
`ObservationRoles`), also derive `Eq` and `Hash` and get a C++ `std::hash`
specialization (R-10; callables hash by identity, ADP-6). Every other leaf
has a `float` field and no `Hash`. C leaves are sized structs with
`RLMESH_<X>_INIT` and `RLMESH_<X>_MIN_SIZE` (R-19). C++ leaves are aggregates
with designated initializers and `operator<<` (ADP-28); C leaves have no
`_repr`, as they have no `_equals` (ADP-6). `ModelSpec::new` /
`EnvTags::new` (C `_new`, C++ constructors) run exactly Python's constructor
checks, no more (R-11, ADP-2): each leaf's `__post_init__` / `__init__` rules
and the `EnvTags` duplicate `(role, part, provenance)` check, plus the
native-only duplicate Dict key (ADP-5) and C-only conflicts (ADP-2). Codec
bounds (the `stack` 1..=64 ceiling, `Rotation` orthonormality and width, the
`offsets` window law) run where Python runs them: `to_dict` / `to_json` /
`to_metadata` refuse with the ValueError class, and `resolve` /
`resolve_from_contract` / `tag` with `AdapterResolutionError`
(`pyad/specs/model_inputs.py:186-188,303-307`, `pyad/resolver.py:558-566`).

Member order (ADP-24): Rust fields, C++ members and C members follow the
leaf's `__init__` signature in the API snapshot, which puts kw-only fields
after the positional ones (`State`: `role` … `container`, then `fill` …
`clip`). InitVars are left out (`Image.size`, `Image.stride`). C++ designated
initializers follow this order. C adds its own members in place:

- `struct_size` comes first.
- `has_<name>` goes right before its field, and `<name>_len` right after its
  pointer.
- `<name>_other` follows the scalar enum, or `<name>_len` for an accept set.
- `normalize_range` follows `normalize`.
- `axis_<name>` + `axis_<name>_len` follow `<name>` (`scale`, `offset`).
- `custom_encoding` follows `encoding` and its `_len` / `_other`.
- `has_stride` + `stride` come last in `RLMeshImage` (ADP-25).
- No sized struct (options, leaf, out-struct, lent) has implicit padding,
  inside or at the tail, with a 4- or 8-byte `size_t`, as in Spaces
  (`RLMeshBoxOptions`, `RLMeshToDlpackOptions`): C adds `uint8_t` /
  `uint16_t` / `uint32_t` `_reserved` members wherever natural alignment
  would otherwise pad (after an enum or `uint32_t` that precedes a pointer,
  after trailing `bool`s), zeroed by `_INIT` and refused when nonzero
  (R-19's zero rule). This holds for the ABI-5 layout as well as appended
  fields, so the minimum's bytes are as well defined as the tail's; the
  header test asserts `sizeof` equals the sum of the members' sizes for every
  sized struct. By-value frozen structs (`RLMeshInputNode`, `RLMeshObsNode`,
  `RLMeshConcatPart`, `RLMeshEncodingArm`) are not sized and keep their
  natural layout.

`to_dict` / `to_metadata` refuse a custom input with ValueError
(`pyad/specs/model.py:60-62`). `from_metadata` returns None when the key is
absent or holds None; a present value that is not a Dict is
`AdapterResolutionError` in every language
(`pyad/specs/model.py:131-139`, `pyad/specs/env_tags.py:560-568`). Every
other `from_*` failure is the plain ValueError class. A `Concat` whose only
part is a parameterized `State` serializes exactly like that `State` and reads
back as it, as in Python (`pyad/specs/model.py:103-108`); a single `Constant`
part stays a `Concat`.

Repr text (ADP-28). For the dataclasses, whose `str` is their `repr`, Rust
`Display`, C++ `operator<<` / `to_string()` and the C `_repr` functions
(`rlmesh_model_spec_repr`, `rlmesh_env_tags_repr`,
`rlmesh_observation_roles_repr`) print Python's `repr` text, and Rust `Debug`
is derived and language-native.

- `Advisory` is the exception, because its `str` is not its `repr`
  (`pyrs/adapters.rs:483-492`). Rust `Display` and C++ `operator<<` /
  `to_string()` print `str()`, the message (R-10). Python's `repr`,
  `Advisory(severity="info", message="…")` with the message escaped as Rust
  `{:?}` escapes it, is printed by a hand-written Rust `Debug`, C++
  `std::string repr() const` and C `rlmesh_advisory_repr`.
- `ModelSpec`, `EnvTags`, `ObservationRoles` and every leaf print the
  dataclass repr `Name(field=value, …)`, fields joined by `, ` in Python's
  declaration order (`dataclasses.fields`; it differs from ADP-24 member
  order only for `State`'s early kw-only fields), InitVars omitted
  (`Image.size`, `Image.stride`).
- Each value prints as Python's `repr` of the stored canonical value: text
  as `repr(str)` (single quotes unless the text holds `'` and no `"`), `None`,
  `True` / `False`, integers in decimal, floats as `repr(float)` (`0.5`,
  `1.0`, `1e-05`), pairs and lists as tuples (`(224, 224)`, `('a',)`, `()`),
  an accept set of one entry as the bare value (`pyad/specs/_codec.py:36-53`),
  a vocabulary or `Tolerant` value as its quoted spelling, a Dict node as
  `{'k': v, …}` in authored order, a Tuple node as a tuple, a nested leaf by
  the same rule.
- Python-only facts are not reproduced. A callable prints as
  `<ObsTransform 0x…>` / `<RotationTransform 0x…>` with an identity token
  (Python prints the function's own repr), and a float field that Python
  stores as an authored `int` (`Constant(fill=0)`) prints as a float. E-3
  compares repr text only for values with neither.

enum returns `RLMeshStatus` and writes its result to `out`, so it can refuse

`rlmesh_observation_roles_equals`. A NULL argument or `out`, or a NULL
`components[i]` in an `RLMeshAction`, is `RLMESH_ERR_INVALID_ARGUMENT`; a

`AdapterBase.explain` default text is `"<Name> (custom adapter)"`. In Rust
`<Name>` is the bare type name, as Python's `type(self).__name__`: from
`std::any::type_name::<Self>()`, drop everything from the first `<`, then
take the last `::` segment (`Wrap` for `my_crate::Wrap<other::Inner>`). It is
`AdapterBase` in C and C++. An override may fail,
as Python's may raise (`pyad/adapter.py:208-210`), so the Rust method returns
`Result` and the default returns `Ok`. Adapter-only calls on a
custom adapter are ADP-10.

A NULL `transform_obs` or `transform_action` slot is `RLMESH_ERR_TYPE`, as
Python refuses to instantiate an `AdapterBase` missing an abstract method.

Custom-encoding arms behave as Python's shims do in every language:

- `from_base` receives the base slice of the state as a 1-D `Tensor` of width
  `CustomEncoding.width()` in the model input's dtype. It must return a flat
  1-D numeric value of that width, which is cast back to that dtype
  (`pyad/adapter.py:338-365`).
- `to_base` receives the action slice as a 1-D float64 `Tensor` of width
  `Actuator.dim`. It must return a flat 1-D numeric value of that width
  (`pyad/adapter.py:423-452`).
- A return of another rank or width is the ValueError class.

`check_inverse` (default true) round-trips each distinct `CustomEncoding`
whose two arms are both callables, in the order of first appearance in the
spec. Distinct means unequal by ADP-6 (base, name and arms, callables by
identity), because a native `CustomEncoding` is a value struct whose copies
have no identity of their own; copies of one encoding are checked once in
every language, Python included (ADP-P10).

- The check computes `to_base(from_base(probe))` on the float64 probe for the
  encoding's base (`pyad/resolver.py:61-68`):

  | Base                      | Probe                |
  | ------------------------- | -------------------- |
  | `quat_xyzw`               | `[0, 0, 0, 1]`       |
  | `quat_wxyz`               | `[1, 0, 0, 0]`       |
  | `axis_angle`, `euler_xyz` | `[0.1, -0.2, 0.3]`   |
  | `rot6d`                   | `[1, 0, 0, 0, 1, 0]` |
  | `rot6d_rowmajor`          | `[1, 0, 0, 1, 0, 0]` |

  A base with no probe is skipped.

- It passes when the result has the probe's shape and every element `r`
  satisfies `|r - p| <= 1e-5 + 1e-5·|p|` against probe element `p` (NumPy
  `allclose(atol=1e-5)` with its default `rtol`, `pyad/resolver.py:395-409`).
  Otherwise it fails with `AdapterResolutionError`.
- An arm that fails during the check becomes `AdapterResolutionError` naming
  the encoding, with the arm's error text in the message. This is a
  deliberate exception to R-12's unchanged propagation, because the check is
  part of resolve (ADP-27).

handle that lends it. As an input (Running's `rlmesh_run_result_new`) the

message is `RLMESH_ERR_TYPE` (ADP-2).

Every failure inside `resolve`, `resolve_from_contract` and `tag`, including
the strict normalize of the authored tags and `check_inverse`, is an
`AdapterResolutionError` (`pyad/resolver.py:523-526,560-566`,
`pyad/tag.py:54-59`). Python differs in these places:

- `tag(validate=False)` runs the normalize through `to_metadata` outside the
  guarded block and raises a plain `ValueError` (`pyad/tag.py:39`). ADP-P6
  aligns it.
- A trusted custom-input entrypoint (`trust_entrypoints=True`) is imported
  unguarded (`pyad/resolver.py:465-468`). A string not in `module:callable`
  form raises `ValueError`, and a target that is not callable raises
  `TypeError` (`py/_entrypoint.py:20,45-48`). An import or attribute failure
  becomes `AdapterResolutionError` (rules P-10). Natively an entrypoint is
  looked up by its exact text in Model's registry, whose values are callables
  (MDL-11). Every miss, malformed text included, is therefore
  `AdapterResolutionError` (ADP-11). This is a deliberate difference (R-21);
  `except ValueError` catches both forms.
- Python's `TypeError` for a non-node input tree (`pyad/resolver.py:108`) has
  no native counterpart, because native trees are typed.

Advisories from `tag` are `UserWarning`s (R-23).

### Per-step behaviour

Shared native engine in every language:

- The adapter resolves per route at `ResolveAdapter` when served, or at
  connect for `run` / `session`.
- A spec'd `predict` receives the model input tree as a `Value`; its output
  maps back through `Action`.
- An `ObsTransform` (a `Custom` input) receives the full raw observation, not
  only the keys the plan reads, as a `Value` Dict: the observation itself for
  a Dict observation, and the envelope `{"<obs>": leaf}` for any other
  observation. Its returned `Value` is placed at the `Custom` leaf's position
  in the model input tree. This holds in every language, in process and
  served (`pyad/adapter.py:287-291,315-321`,
  `pyad/specs/model_inputs.py:700-702`, `core/plans.rs:20`,
  `core/stateful.rs:751-752`).
- Frame windows and `Previous` history are kept per episode and cleared at
  episode end.
- A tagged env with no spec is an `AdapterResolutionError`; `NO_ADAPTER`
  passes raw observations (`py/_models/_resolve.py:51-62`).
- Per-step failures in `transform_obs`, `transform_action` and `observe` are
  never `AdapterResolutionError`:
  - A malformed raw observation or action, a non-1-D action under an action
    `CustomEncoding`, or an encoding arm's unusable return is the ValueError
    class: `Error::InvalidArgument`, `RLMESH_ERR_INVALID_ARGUMENT`,
    `rlmesh::ValueError`. Python raises `ValueError` from the plan
    (`pyrs/adapters.rs:690-696`) and from the shims
    (`pyad/adapter.py:343-359,435-450`).
  - A Dict action under an action `CustomEncoding` is the TypeError class
    (`pyad/adapter.py:428-432`).
  - An `ObsTransform`'s or `RotationTransform`'s own error propagates
    unchanged (R-12).
